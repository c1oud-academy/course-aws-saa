Қайырлы күн, құрметті студенттер. Келесі зертханалық жұмысты талқылау сессиясында сіздерді көргеніме қуаныштымын. Бүгінгі зертханалық жұмыстың тақырыбы – AWS бұлтында AWS Lambda сервисін пайдаланып, серверсіз архитектура құру. Ал, бастайық. Бірінші тапсырманы бастаймыз. Бірінші тапсырмада Lambda-функция жасаймыз. Бұл Lambda-функция S3 бакеттен деректерді жүктеп алып, оларды DynamoDB-ге енгізу үшін қолданылады. AWS Management Console басты парақшасынан бастаймыз. Мұнда сервис іздеу жолын қолданып, Lambda деп жаза бастаймыз. Іздеу нәтижесіндегі бірінші сілтеме – бізге қажет сілтеме. Сілтемеге өткен соң, бізді Lambda-функциялар тізімі парақшасына бағыттайды. Мұнда экранның жоғарғы оң жақ бөлігіндегі Create Function батырмасын басамыз. Содан кейін бізді Lambda-функция құру парақшасына жібереді. Мұнда біз Lambda-функцияны нөлден бастап жасайтынымызды көрсетуіміз керек. Lambda-функция атауы ретінде Load-Inventory деп жазамыз, Runtime ретінде Python 3.7 таңдаймыз және парақшаны соңына дейін жылжытамыз. Мұнда біз бар рөлді қолданатынымызды көрсетіп, IAM рөлдер тізімінен Lambda-Load-Inventory-Role рөлін таңдаймыз. Содан кейін экранның төменгі оң жағындағы Create Function батырмасын басамыз. Осыдан кейін бізді Lambda-функцияның басты парақшасына жібереді. Экранның жоғарғы бөлігінде жасыл фонда Lambda-функция сәтті жасалғаны туралы хабарлама көреміз. Енді парақшаның ортасында қойындылар тізімі бар жерге барып, бірінші қойынды – Code бөлігін ашамыз. Онлайн редактор толық экранда көрінуі үшін парақшаны төмен жылжытамыз. Мұнда дайын кодты қойып, өзгерістерді сақтап, Lambda-ның жаңа нұсқасын батырма арқылы орнатамыз. Егер бәрін дұрыс жасасақ, экранның жоғарғы бөлігінде Load-Inventory функциясы жаңартылғаны туралы жасыл фонда хабарлама көресіз. Сондай-ақ онлайн редактордың жоғарғы жағында Deploy батырмасы белсенді еместігін байқаймыз. Екінші тапсырманы бастаймыз. Бұл тапсырмада S3 бакет жасаймыз және осы S3 бакетте біздің Lambda-ны триггерлейтін Event құрамыз. S3 сервисіне өтіп, егер онда бұрын S3 бакет жасалмаған болса, осындай парақшаны көреміз. Мұнда экранның жоғарғы оң жағындағы Create Bucket батырмасын басамыз. Содан кейін бізді жаңа ресурс жасау парақшасына бағыттайды. Bucket Name ретінде Inventory- және кез келген кездейсоқ сан жазамыз, менде 777 нұсқасы жарады. Қалған өрістерді әдепкі күйінде қалдырып, парақшаны соңына дейін жылжытып, Create Bucket батырмасын басамыз. Бізді S3 бакеттер тізімі парақшасына қайтарады және жоғарғы бөлікте S3 бакет сәтті жасалғаны туралы жасыл фонда хабарлама көреміз. Енді S3 бакет атауын басып, оның басты парақшасын ашамыз. Мұнда бірнеше қойынды бар, бізді Properties қойындысы қызықтырады, оны ашып, парақшаның ортасына жылжимыз. Онда Event Notifications бөлігін табасыз және қазір 0 Event Notification орнатылғанын көресіз. Енді осы бөліктің жоғарғы оң жағындағы Create Event Notification батырмасын басамыз. Бізді осы ресурсты жасау парақшасына жібереді. Event Name ретінде Load-Inventory деп жазып, Event Types бөлімінде All Object Create Events опциясын таңдаймыз. S3 бакетке объектіні бірнеше тәсілмен жүктеуге болады. Бұл зертханалық жұмыста біз үшін оның қалай жүктелгені маңызды емес. Ең бастысы – егер ол бакетте пайда болса, Event біздің лямбданы триггерлеуі керек. Парақшаны соңына дейін жылжытып, Destination бөлімінде лямбда-функцияны таңдап, тізімнен Load-Inventory функциясын көрсетеміз. Содан кейін экранның төменгі оң жағындағы Save Changes батырмасын басамыз. Осылайша біз лямбда-функцияны және оны триггерлейтін S3 бакетті баптадық. Үшінші тапсырмада осы архитектура логикасының бөлігін тестілеуді бастаймыз. Ол үшін 21-қадамда көрсетілген дайын .csv файлдарын жүктеуіміз керек. Мұнда 6 .csv файл бар, оларды жергілікті компьютерге жүктейік. Оларда әр қала бойынша белгілі бір тауарлардың саны көрсетілген деректер бар. Файлдарды жүктеген соң, S3 бакет басты парақшасына өтіп, Objects қойындысын ашамыз, онда Upload батырмасын табамыз. Бізді жүктеу парақшасына жібереді, Add Files батырмасын басып, барлық файлдарды таңдаймыз. Содан кейін экранның төменгі жағындағы Upload батырмасын басамыз. Сосын бізді осы файлдардың жүктелу статусы парақшасына жібереді. Барлық жүктеу аяқталса, жоғарғы бөлікте барлық файлдар сәтті жүктелгені туралы хабарлама көреміз. Жекелеген файл немесе папка статустарын экранның төменгі жағынан көруге болады. Енді веб-қосымша жағынан бұл деректер DynamoDB-ге түскенін тексереміз. Ол үшін зертханалық жұмыстың басты парақшасына оралып, жоғарғы оң жақтағы Details батырмасын басамыз. Ашылған тізімнен Show батырмасын басамыз. Ашылған терезеден Dashboard URL мекенжайын көшіріп, браузердің жаңа қойындысында ашамыз, инкогнито режимін қолданған дұрыс. Сіз осындай парақшаны көресіз және аймақтар мен файлдар бойынша тауар саны көрсетілгенін байқайсыз. Бұл ақпаратты графиктер түрінде де көреміз. Енді осы деректерді DynamoDB-де көрейік. AWS Management Console қойындысына ораламыз. Сервис іздеу жолын қолданып, DynamoDB сервисіне өтеміз. Сол жақтағы навигация мәзірінен Explore items тармағын таңдаймыз. Кестелер тізімі парақшасында Inventory кестесін таңдаймыз. DynamoDB-дегі items-ті сканерлейтінімізді көрсетіп, Run батырмасын басамыз. Нәтижесінде экранның төменгі бөлігінде барлығы 36 жазба көрсетіліп, олар кесте түрінде шығады. Бірінші жол – бұл филиал туралы ақпарат, одан кейін item, яғни зат немесе тауар және осы филиалда бар саны көрсетіледі. Енді төртінші тапсырмаға көшеміз. Бұл тапсырмада SNS сервисі арқылы хабарландыру жіберуді баптаймыз. Ол үшін осы сервиске өтуіміз керек. Сервиске өткен соң, басты парақшасын көреміз. Егер бұл AWS аккаунтында әлі SNS topic жасалмаса, онда экранның жоғарғы оң жағында topic атауын жазамыз — NoStock, содан кейін Next Step батырмасын басамыз. Бізді жаңа SNS topic жасау парақшасына бағыттайды. Type ретінде Standard таңдаймыз, Name өрісі автоматты түрде толтырылады, парақшаны соңына дейін жылжытып, Create Topic батырмасын басамыз. Осыны жасағаннан кейін бізді осы ресурс басты парақшасына қайтарады. Экранның жоғарғы бөлігінде жасыл фонда SNS topic сәтті жасалғаны туралы хабарлама көреміз. Енді осы SNS topic-ке жазылушыларды жасауымыз керек. Ол үшін парақшаның төменгі жағындағы Subscriptions қойындысын ашып, осы бөлімде Create Subscription батырмасын басамыз. Жаңа жазылу жасау парақшасы ашылады. Protocol ретінде Email таңдаймыз, Endpoint ретінде кез келген email көрсетеміз, өзіңіздің жеке email-іңізді көрсетуге болады. Содан кейін экранның төменгі оң жағындағы Create Subscription батырмасын басамыз. Осыны жасаған соң, бізді жазылу басты парақшасына жібереді, онда жасыл фонда жазылу сәтті жасалғаны туралы хабарлама көреміз. Назар аударыңыз, бұл парақшада статус Pending Confirmation деп көрсетілген, яғни жазылуды растау қажет. Ол үшін поштамызды ашамыз, менің жағдайда бұл Cloud Academy-дің негізгі email-і. Мұнда AWS Notification-нан келген соңғы хатты көреміз, онда белгілі бір topic-тің ARN-і көрсетілген және жазылуды растау үшін сілтеме беріледі. Бір рет басып, осы сілтеме арқылы өтуіміз керек. Осыдан кейін жазылу сәтті расталғаны туралы хабарлама көреміз және енді SNS topic-ке жіберілген барлық хабарламалар сіздің email-іңізге де жіберіледі. Растаудан кейін SNS topic басты парақшасына өтіп, Subscriptions қойындысын ашсақ, бір ғана жазылу тұрғанын, онда сіздің email көрсетілгенін және статус Confirmed екенін көреміз. Енді қосымшамыздың қалған логикасын жасауға көшеміз, бесінші тапсырмада тағы бір лямбда-функция құрамыз. Бұл лямбда-функция DynamoDB кестесіндегі барлық өзгерістерді қабылдайды. Егер тауар саны нөлге тең болса, яғни таусылса, онда лямбда-функция төртінші тапсырмада жасаған SNS topic-ке хабарлама жібереді. Содан кейін SNS topic бұл хабарламаны барлық жазылушыларына таратады. Оны жасау үшін AWS Lambda сервисіне өтеміз, қазір бір ғана лямбдамыз барын көреміз. Енді екінші функцияны жасауымыз керек, ол үшін экранның жоғарғы оң жағындағы Create Function батырмасын басамыз. Бізді дәл сол сияқты парақшаға жібереді, мұнда біз лямбда-функцияны нөлден жасайтынымызды таңдаймыз. Function Name ретінде Check-Stock деп жазамыз, Runtime ретінде тағы да Python 3.7 таңдаймыз және парақшаны соңына дейін жылжытамыз. Бұл функция үшін де алдын ала рөл жасалған, сондықтан Use an Existing Role опциясын таңдап, тізімнен Lambda-Check-Stock-Role рөлін табамыз. Содан кейін экранның төменгі оң жағындағы Create Function батырмасын басамыз. Осыдан кейін бізді лямбда-функцияның басты парақшасына жібереді және жасыл фонда функция сәтті жасалғаны туралы хабарлама көреміз. Енді онлайн редакторға дейін парақшаны жылжытып, Code қойындысын ашамыз. Мұнда бізде дайын бағдарлама коды бар, оны зертханалық жұмыс тапсырмасынан көшіріп, осында қоямыз. Содан кейін өзгерістерді сақтаймыз — мұны онлайн редактордағы Menu File арқылы немесе Ctrl+S пернелер тіркесімін қолданып жасауға болады. Содан соң онлайн редактордың жоғарғы жағындағы Deploy батырмасын басамыз. Осыны жасағаннан кейін бірнеше секунд ішінде жасыл фонда функция сәтті жаңартылғаны туралы хабарлама аламыз. Сондай-ақ Deploy батырмасы белсенді еместігін байқайсыз. Енді DynamoDB кестесінен біздің лямбдаға триггер жасауымыз керек. Ол үшін парақшаның басына дейін жылжытып, Add Trigger батырмасын басу қажет. Бізді жаңа триггер жасау парақшасына жібереді. Мұнда сервис ретінде DynamoDB таңдап, DynamoDB Table өрісінде өз кестемізді көрсетеміз. Содан кейін парақшаның төменгі жағындағы Add батырмасын басу керек. Осыдан кейін бізді лямбда-функция басты парақшасына қайтарады. Жасыл фонда триггер сәтті жасалғаны және қосылғаны туралы хабарлама көреміз, сондай-ақ триггерлер тізімінде DynamoDB пайда болады. Біз соңғы, алтыншы тапсырмаға жеттік. Бұл тапсырмада қосымшамыздың жұмыс логикасын тексереміз. Ол үшін S3 сервисіне өтуіміз керек. Содан кейін өзіміздің S3 bucket-ті таңдап, оған бір немесе бірнеше файлды қайта жүктейміз. Бірнеше минут ішінде сіздің пошта жәшігіңізге AWS Notifications-тен осындай хаттар келеді. Егер солай болса, демек, сіз зертханалық жұмыстың барлық тапсырмаларын сәтті орындадыңыз. Енді автобағалау скриптін іске қосып, барлық жүйелерден дұрыс шығуымыз керек. Автобағалау скриптін іске қосу үшін зертханалық жұмыс басты парақшасына оралып, экранның жоғарғы оң жағындағы Submit батырмасын басамыз. Содан кейін бұл әрекетті растау керек. Біршама уақыттан кейін экранның оң жағында өз бағамызды көреміз. Егер сіз максималды балл жинамасаңыз және оны жақсартқыңыз келсе, қай тапсырмада балл жетіспейтінін қарап шығыңыз. Сол тапсырмаға оралып, кеткен қателерді түзетіңіз. Одан кейін ешқандай айыппұлсыз автобағалау скриптін қайта іске қосып, жаңартылған бағаны көре аласыз. Егер баға көрінбесе, экранның жоғарғы оң жағындағы Grades батырмасын басу арқылы оң жақ мәзірді ашуға болады. Жақсы, енді барлық жүйелерден шығуға болады. AWS Management Console ашық бір ғана қойындыны қалдырамыз. Содан кейін экранның жоғарғы оң жағындағы пайдаланушы атын басып, ашылған тізімнен Sign out батырмасын таңдаймыз. Содан кейін зертханалық жұмыс басты парақшасына қайта ораламыз. Мұнда экранның жоғарғы оң жағындағы End lab батырмасын басып, бұл әрекетті растау қажет. Біршама уақыттан кейін зертханалық жұмысты аяқтау басталғаны және осы қойындыны жабуға болатыны туралы хабарлама аласыз. Зертханалық жұмысты аяқтағандарыңызбен құттықтаймын. Біз сіздермен бірнеше AWS сервисін қолданып, қосымшамыздың логикасын баптай алдық. Қолданған сервис тізімі: файлдарды сақтау үшін S3. Қосымша логикасын орындау үшін екі лямбда-функция. Lambda функциясының басқа AWS сервистеріне қол жеткізуі үшін IAM рөлі. Деректерімізді сақтау үшін DynamoDB және хабарландыру жіберу үшін SNS topic. Осылайша біз зертханалық жұмысты аяқтаймыз. Назарларыңызға рахмет, келесі белсенділіктерде кездескенше.
