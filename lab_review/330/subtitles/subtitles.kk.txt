Қайырлы күн, құрметті студенттер. Зертханалық жұмысты талқылау сессиясында сіздерді көргеніме қуаныштымын. Бұл зертханалық жұмыста біз AWS Storage Gateway сервисімен тығыз жұмыс істейміз. Ал енді, бастайық. Бірінші тапсырманы бастаймыз. Бірінші тапсырма аясында біз осы зертханалық жұмыста құрамыз деп жоспарлаған архитектураны талдаймыз. Біз үш AWS аймағын қолданамыз. Бірінші аймақ — us-east-1, онда EC2 инстансы орналасқан, ол жергілікті дата-центрдегі серверді эмуляциялайды. Оған біз NFS File Share қосамыз, ол өз кезегінде S3 Bucket-ке байланысады. Осы серверден NFS File Share-ге түскен барлық нәрсе автоматты түрде S3 Bucket-ке беріледі. S3 Bucket жағында us-east-2 аймағында біз Cross-Region Replication баптаймыз. Яғни, оған түскен барлық файлдар us-west-2 аймағында орналасқан Destination Bucket-ке көшіріледі. Екінші тапсырмаға көшеміз. Бұл тапсырмада екі S3 Bucket құрамыз. AWS Management Console басты парақшасынан бастаймыз. Сервис іздеу жолағын пайдаланып, S3 енгізу керек. Бірінші сілтеме — бізге керегі. Егер бұл сервиске әлі bucket құрылмаса, осындай парақша шығады, онда Create Bucket батырмасын басу керек. Біз жаңа ресурс құру парақшасына өтеміз. Bucket name ретінде кез келген мән бере аласыз, S3 Bucket арасында шатаспау үшін source сөзін қосу ұсынылады. Мен өзім c1oud-academy-source-bucket деп атадым. Аймақ ретінде Ohio таңдап, төмен қарай жылжимыз. Bucket Versioning бөлімінде Enable опциясын таңдау керек. Қалған баптаулар әдепкіде қалады. Парақшаның төменгі жағында Create Bucket батырмасын басамыз. Біз S3 Bucket тізіміне өтеміз. Жасыл фонда S3 Bucket сәтті құрылғаны туралы хабарлама көреміз. Енді Destination Bucket құру керек. Ол үшін осы парақшадан экранның жоғарғы оң жағындағы Create Bucket батырмасын басамыз. Біз қайтадан жаңа ресурс құру парақшасына өтеміз. S3 Bucket аты ретінде кез келген ат береміз, мен c1oud-academy-destination-bucket деп таңдадым, аймақ ретінде Oregon (us-west-2) көрсетеміз. Bucket Versioning бөлімінде Enable опциясын таңдап, парақшаның төменгі жағында Create Bucket батырмасын басамыз. Осыны жасаған соң, біз S3 Bucket тізіміне қайта ораламыз, енді екі S3 Bucket көрініп тұр. Жасыл фонда Destination Bucket сәтті құрылғаны туралы хабарлама бар. Үшінші тапсырманы бастаймыз, мұнда Source Bucket-тен Destination Bucket-ке Cross-Region Replication баптаймыз. Ол үшін Source Bucket басты парақшасын ашамыз. Содан кейін Management қойындысына өтеміз, онда Replication Rules бөлімі бар. Create Replication Rule батырмасын басамыз, біз жаңа ресурс құру парақшасына өтеміз. Replication Rule Name ретінде crr-full-bucket деп көрсетіп, Status ретінде Enabled таңдаймыз. Source Bucket бөлімінде Scope таңдау керек. Біз барлық объектілерді таңдаймыз — Apply to all objects in the bucket. Destination бөлімінде Choose a bucket in this account опциясын таңдап, осы AWS аккаунттағы S3 Bucket таңдаймыз. Bucket Name ретінде Browse S3 батырмасын басып, тізімнен Destination Bucket таңдаймыз. IAM Role бөлімінде бар рөлді таңдап, тізімнен S3-CRR-Role табамыз. Содан кейін парақшаның соңына дейін жылжып, Save батырмасын басамыз. Осыны жасаған соң, Source Bucket-тегі бар объектілерді репликациялау туралы қалқымалы терезе шығады. Source Bucket бос болғандықтан, кез келген нұсқаны таңдап, Submit батырмасын басамыз. Осыдан кейін біз Source Bucket-тегі Replication Rules парақшасына өтеміз. Жаңа құрылған Replication Rule Enabled күйінде көрінеді. Сондай-ақ, жасыл фонда Replication Rule сәтті құрылғаны туралы хабарлама бар. Енді Cross-Region replication қалай жұмыс істейтінін тексеру керек. Ол үшін Source Bucket ашып, Objects қойындысында Upload батырмасын басамыз. Біз жүктеу параметрлері парақшасына өтеміз. Add Files батырмасын басып, жергілікті компьютерден кез келген файл таңдаймыз. Менде бұл QR.jpg, одан кейін экранның төменгі жағындағы Upload батырмасын басамыз. Біз жүктеу күйі парақшасына өтеміз. Егер файл шағын болса, бірден жасыл фонда файлдар жүктелгені туралы хабарлама көресіз. Сондай-ақ төменгі жағында жеке файлдың жүктелу күйін көруге болады. Енді Source Bucket сілтемесін басып, файлдың тізімде бар екенін тексереміз. Иә, бар екен, енді Destination Bucket ашамыз. Ол үшін экранның жоғарғы жағындағы Buckets сілтемесін басып, тізімнен Destination Bucket таңдаймыз. Егер файлдар көрінбесе, парақшаны жаңарту немесе тиісті пернені басу керек, содан кейін QR.jpg көрінуі тиіс. Егер солай болса, бәрін дұрыс жасадық, келесі тапсырмаға көшеміз. Төртінші тапсырманы бастаймыз, мұнда File Gateway баптап, NFS File Share құрамыз. Мұнда баптаулар саны көп болатынын атап өткім келеді. Қосымша ретінде AWS құжаттамасынан толығырақ таныса аласыз. Мұнда негізгі назарды біз не істегенімізге және оны не үшін істегенімізге жалпы түсінікке аударыңыз. Ал ұсақтау сәттерін зертханалық жұмыста көрсетілгендей орындап, келесі тапсырмаларға өте беруге болады. Енді AWS Management Console экранының жоғарғы бөлігіндегі сервис іздеу жолағын пайдаланамыз. Storage деп жаза бастаймыз, нәтижеде бірінші сілтеме Storage Gateway шығады. Сол сілтемені басып, сервис басты парақшасына өтейік. Міндетті түрде дұрыс аймақта тұрғаныңызды тексеріңіз, бізге керек аймақ — North Virginia. Егер солай болса, Gateway құруды бастай аламыз, ол үшін Create Gateway батырмасын басамыз. Жаңа ресурс құру парақшасы ашылады, Gateway Name ретінде File Gateway көрсетеміз. Gateway Time Zone ретінде GMT-5 таңдап, төмен қарай жылжимыз. Gateway Type ретінде Amazon S3 File Gateway таңдап, тағы төмен жылжимыз. Келесі секция — Platform Options, Host Platform ретінде Amazon EC2 таңдаймыз, одан төмен қосымша өрістер шығады. Customize Your Settings опциясын таңдау керек. Төменірек Launch Instance батырмасы бар блок шығады, соны басайық. Біз жаңа браузер қойындысына өтеміз, онда EC2 инстанс құрамыз. Содан кейін осы қойындыға қайтып келіп, Gateway құруды аяқтаймыз. Жаңа EC2 инстанс құру қойындысында Name өрісіне File Gateway Appliance деп енгіземіз. AMI ретінде ұсынылған мәнді қалдырып, төмен жылжимыз. Instance Type бөлімінде t2.xlarge таңдаймыз, Key Pair ретінде Vockey таңдаймыз, Network Settings бөлімінде Edit батырмасын басамыз. VPC ретінде On-Prem-VPC таңдау керек. Subnet ретінде On-Prem-Subnet таңдаймыз, Auto-Assign Public IP үшін Enable таңдаймыз, төменірек Security Group баптаулары бар. Мұнда бар Security группаларды таңдаймыз және тізімнен екі Security группа табамыз. Біріншісінде FileGatewayAccess мәтіні бар, екіншісінде — OnPremSshAccess. Осы екі Security Группаны таңдағаннан кейін төмен қарай жылжимыз. Келесі секция — Configure Storage. Бірінші диск өзгеріссіз қалады, Add New Volume батырмасын басып, екінші жолға 150 мәнін енгіземіз. Volume type ретінде gp3 қалдырамыз. Енді экранның оң жағында инстанс санын 1 деп көрсетіп, төменгі оң жақ бұрыштағы Launch Instance батырмасын басып, EC2 инстанс құрамыз. EC2 инстанс құру күйі парақшасына өтеміз, View All Instances батырмасын басып, барлық EC2 инстанстар тізімін ашамыз. Сондай-ақ Status Check өрісі 2/2 Checks passed мәніне өзгергенін күту керек. Ол үшін парақшаны уақытылы жаңартып отыру керек, немесе тізімді жаңарту пернесін басуға болады. EC2 инстанс дайын болғанда, оны таңдап, жалпыға ортақ IP-мекенжайын көшіру керек. Бұл мекенжай кейін Storage Gateway баптау үшін қажет болады. Енді алдыңғы қойындыға оралып, EC2 инстанс құрылғанын растау үшін құсбелгі қойып, Next батырмасын басамыз. Келесі парақшада IP address опциясын таңдап, EC2 инстанс IP-мекенжайын енгіземіз. Төменірек Endpoint жалпыға ортақ деп таңдаймыз, экранның төменгі жағында Next батырмасын басу керек. Келесі парақша — Review парақшасы, мұнда барлық енгізілген мәндерді тексеріп, экранның төменгі жағында Activate Gateway батырмасын басамыз. Келесі парақшада жасыл фонда File Gateway құрылып жатқанын көрсететін хабарлама көреміз. Сондай-ақ Configure Cache Storage бөлімінде құрылу күйін көресіз. Ол құрылып жатқанда, келесі бөлімде Deactivate Logging опциясын таңдап, File Gateway дайын болғанын күтеміз. Дайын болғанда, Configure Cache Storage бөлімінде 150 ГБ көлеміндегі дискімізді көреміз. Енді парақшаның соңына дейін жылжып, CloudWatch Alarms бөлімінде No Alarm мәнін таңдау керек. Бұл баптаулар міндетті емес, қажет болған жағдайда кейін толығырақ танысып, жұмыс барысында орнатуға болады. Енді экранның төменгі оң жағындағы Configure батырмасын басу керек. Біз gateways тізімі бар парақшаға өтеміз, онда статус Running болғанын күту керек. Бұл орындалған соң, экранның сол жақтағы навигациялық мәзірінен File Shares тармағын таңдаймыз. Біз жаңа File Share құрамыз. Барлық File Share тізімі бар парақшада Create File Share батырмасын басамыз. Біз жаңа ресурс құру парақшасына өтеміз. Gateway ретінде File Gateway көрсетіп, Protocol ретінде NFS таңдаймыз, S3 Bucket ретінде Source Bucket таңдаймыз. Содан кейін Customize Configuration батырмасын басу керек. Қосымша баптаулар ашылады, File Share Name өрісіне Share деп енгізіп, экранның төменгі жағындағы Next батырмасын басамыз. Келесі баптау парақшасында бізге IAM ролінің ARN қажет болады, сондықтан алдын ала оны көшіруге тырысайық. Сервис іздеу жолағына IAM деп енгізіп, тиісті сервиске өтеміз. Одан кейін сол жақтағы навигациялық мәзірді пайдаланып Roles тармағын таңдаймыз, рөлдер тізімінде fgw кілт сөзі бойынша фильтр жасаймыз. Қажетті рөлді таптық, оны ашып көрейік. Біз арнайы құмсалғышта жұмыс істеп жатқандықтан, IAM-ге қол жеткізу шектеулі. Өз құмсалғышыңызда жұмыс істегенде мұндай шектеулер болмайды. Енді ARN алу үшін зертханалық жұмыстың басты парақшасына өтіп, экранның жоғарғы оң жағындағы Details батырмасын басу керек. Түсетін тізімнен Show батырмасын басу қажет. Ашылған қалқымалы терезеде AWS аккаунтымыз туралы көптеген қосымша ақпаратты көреміз. Бізді FgwIamPolicyARN өрісі қызықтырады. Осы мәнді көшірейік, ол келесі қадамда қажет болады. Келесі парақшада Storage Class ретінде S3 Standard көрсетеміз. Object Metadata секциясында құсбелгілерді мынадай етіп қоямыз. Төменірек бізде бар IAM роль бар екенін көрсетеміз, IAM role өрісіне бұрын көшірген ARN енгіземіз, содан кейін Next батырмасын басамыз. Келесі парақшада кез келген NFS client біздің File Share-ге қосыла алатыны туралы ескерту көреміз. Бұл осы зертханалық жұмыс аясында қалыпты жағдай. Біршама уақыттан кейін бұл уақытша AWS аккаунт өшіріледі, сондықтан бұл ескертуді өткізіп жібереміз. Парақшаның соңына дейін жылжып, Next батырмасын басамыз. Келесі парақша — соңғы парақша, Review. Мұнда еш өзгеріс енгізбейміз, соңына дейін жылжып, Create батырмасын басамыз. Біз барлық File Share тізімі бар парақшаға өтеміз. Status өрісі Updating-тен Available-ге өзгергенін күту керек, сондықтан парақшаны мезгіл-мезгіл жаңартып отырамыз. Статус Available болғанда, File Share ID-ін басып, ресурс басты парақшасына өтеміз. Бұл парақшада Linux операциялық жүйесі үшін осы File Share-ді тіркеу командасы қызықтырады. Оны көшірейік, келесі тапсырмада қажет болады. Бесінші тапсырмада біз File Share-ді Linux инстансымызға тіркеп, деректерімізді инстанстың жергілікті дискінен File Share-ге көшіреміз, осылайша олар S3 бакетінде көрсетіледі. Бастайық. Ең алдымен инстансымызға қосылу керек, ол үшін EC2 сервисінде EC2 инстанстар тізімін ашамыз. Бізді On-Prem Linux Server атты инстанс қызықтырады. Оны таңдап, экранның төменгі жағынан жалпыға ортақ IP-мекенжайын көшіреміз. Содан кейін PuTTY бағдарламасын пайдаланып осы инстансқа қосыламыз. PuTTY бағдарламасын қалай қосу және пайдалану туралы біз бірнеше рет өткенбіз және алдыңғы демо мен зертханалық жұмыстарда толық талдағанбыз, сондықтан қиындық болмайды деп ойлаймын. Қосылғаннан кейін бірнеше команданы іске қосу керек. Бірінші команда media папкасындағы data папкасының мазмұнын көрсетеді. Біз бірнеше суретті көреміз, бұл файлдар File Share-ге көшіріледі. Содан кейін тіркеу папкасын құру керек, бұл екінші команда. Үшінші командада біз File Share-ді жергілікті папкаға тіркеп, df -h командасын орындағанда тізімде File Share көрінеді. Соңғы командада media/data жолындағы барлық файлдарды File Share-ге көшіру керек. Соңғы тапсырмада бәрінің жұмыс істейтінін тексереміз. Біріншіден, деректер source бакетінде көрсетілгенін тексереміз, екіншіден cross-region replication жұмыс істегенін және сол файлдардың destination бакетінде пайда болғанын тексереміз. Ендеше бастайық. Алдымен AWS Management Console-де S3 сервисіне өтеміз. Бакеттер тізімінде source бакетті таңдап, объектілер тізімін жаңартамыз. Біз 21 объект көреміз, біріншісі бұрын жүктелген, ал қалған 20 сурет Linux инстанстан жүктелген. Енді бакеттер тізіміне өтіп, destination бакетті таңдаймыз. Мұнда да қажет болса парақшаны немесе файлдар тізімін жаңартуға болады, біз 21 объект көруіміз керек. Тағы да, бұл бастапқыда жүктелген бір объект және source бакеттен алынған 20 сурет. Осылайша біз зертханалық жұмыстың соңына жеттік. Енді зертханалық жұмысты орындауды тексеріп, барлық жүйелерден дұрыс шығуымыз керек. Басты парақшаға оралып, экранның жоғарғы оң жағындағы Submit батырмасын басамыз. Бұл әрекетті растау керек, біраз уақыттан кейін экранның оң жағында жиналған баллымыз көрінеді. Мен максималды балл жинадым. Егер сізде балл жетіспесе немесе жақсартқыңыз келсе, әрқашан қажетті тапсырмаға оралып, түзетулер енгізіп, автобағалау скриптін қайтадан іске қосуға болады. Жақсы, енді барлық жүйелерден шығамыз. Бірінші кезекте бұл AWS Management Console-ге қатысты. Бір ғана қойындыны қалдырып, экранның жоғарғы оң жағындағы пайдаланушы атын басамыз. Тізімнен Sign out батырмасын басамыз. Одан кейін басты парақшаға оралып, экранның жоғарғы оң жағындағы End lab батырмасын басамыз. Бұл әрекетті растау керек, содан кейін қалқымалы терезе шығады. Онда бұл қойындыны жабуға болатыны және уақытша AWS аккаунтты жою процесі басталғаны туралы ақпарат болады. Осылайша біз зертханалық жұмысты талдауды аяқтадық. Назар аударғандарыңызға рахмет, келесі белсенділіктерде кездескенше.
