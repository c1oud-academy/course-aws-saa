Қайырлы күн, құрметті студенттер. Зертханалық жұмысты талқылаудың келесі сессиясында барлығыңызды көргеніме қуаныштымын. Бүгінгі зертханалық жұмыстың тақырыбы – біздің Cafe бизнес-кейсі үшін серверсіз архитектура құру. Ендеше, бастайық. Бірінші тапсырманы орындаудан бастаймыз. Бұл тапсырма аясында біз екі лямбда- функциямыздың кодын жүктеп алуымыз қажет. Zip-архивтерді жүктеу сілтемелерін бесінші қадамнан таба аласыз. Жүктегеннен кейін, осы архивтерде не бар екенін қарайық. Мен бірінші zip-файлды аштым, оның ішінде Python скрипті және package папкасы бар. Егер package папкасын ашып ішін қарасақ, онда лямбда-функция ішінде қолданылатын модульдерге арналған екі папка бар. Келесі архивте тек бір Python скрипті бар. Енді зертханалық жұмыстың басты парақшасына өтіп, экранның жоғарғы оң жағындағы Details батырмасын басып, ашылған тізімнен Show батырмасын басамыз. Қалқып шығатын терезе ашылады және мұнда бізді Access the multiple choice questions сілтемесі қызықтырады. Жаңа қойынды ашылады және мұнда біз бес сұрақты көреміз. Бірінші тапсырма аясында біз бірінші сұраққа жауап беруіміз қажет. Бірінші сұрақ келесідей естіледі. Неліктен бірінші zip-архивте package папкасы бар? Сұрақтарды мұқият қарап, жауап беруге тырысыңыз. Бұл сұраққа дұрыс жауап – екінші нұсқа. Бұл папкада негізгі Python скрипті қолданатын Python модульдері бар. Осы нұсқаны белгілеп, Submit батырмасын басайық. Екінші тапсырманы бастаймыз. Бұл тапсырма аясында біз VPC ішінде DataExtractor лямбда-функциясын құрамыз. Мұны жасау үшін алдымен лямбда-функциямызға арналған security топ құруымыз қажет. Сервис іздеу жолағында security groups деп жаза бастаймыз, және бірінші екі сілтеме – бізге керектілері. Security топтар тізімін EC2 сервисінде немесе VPC ішінде ашуға болады, айырмашылық жоқ. Мен бірінші сілтемені аштым, біз оны EC2 сервисінде жасадық. Экранның жоғарғы сол жағындағы жазуға назар аударыңыз. Біз сол жақтағы навигациялық мәзірде Security groups бөлімінде тұрмыз. Security топтар тізімін ашқан соң, экранның жоғарғы оң жағындағы Create security group батырмасын басу қажет. Жаңа security топ құру парақшасы ашылады. Мұнда Security group name ретінде LambdaSG деп, VPC өрісінде Lab VPC таңдап, парақшаны соңына дейін айналдырамыз. Outbound rules бөлімінде әдепкі бойынша барлық шығыс трафикке рұқсат беретін ережені қалдырамыз. Содан кейін экранның төменгі оң жағындағы Create security group батырмасын басу қажет. Осыны жасағаннан кейін бізді security топтың басты парақшасына бағыттайды. Мұнда Security group ID-ны есте сақтап немесе көшіруіміз қажет. Сондай-ақ, экранның жоғарғы бөлігінде security топтың сәтті құрылғанын жасыл фонда көрсететін хабарламаны көреміз. Енді security топтар тізімін ашып, ондағы Database SG тобын таңдау қажет. Біз оны Lambda SG security тобынан дерекқорға қосылуға мүмкіндік беретіндей етіп өңдейміз. Тізімнен Database SG таңдап, Inbound rules қойындысын ашайық. Мұнда бір ғана inbound rule бар, екіншісін қосайық. Ол үшін осы бөлімнің жоғарғы оң жағындағы Edit inbound rules батырмасын басу қажет. Ережелерді өңдеу парақшасы ашылады, мұнда Add rule батырмасын басу керек. Жаңа жолда Type ретінде MYSQL/Aurora таңдап, Source өрісін Custom қылып қалдырып, қасындағы өріске sg- деп жаза бастаймыз. Барлық security топтардың тізімі шығады, содан Lambda SG тобын таңдау қажет. Содан соң экранның төменгі оң жағындағы Save rules батырмасын басу керек. Бізді сол парақшаға қайта бағыттайды және inbound rules тізімінде екеуін көреміз, соның ішінде жаңадан қосқанымыз да бар. Енді лямбда-функцияны құруға көшуге болады. Ол үшін сервис іздеу жолағын пайдаланып, AWS Lambda сервисіне өтеміз. Мұнда экранның жоғарғы оң жағындағы Create function батырмасын басу керек. Бізді жаңа ресурс құру парақшасына бағыттайды. Мұнда біз лямбда-функцияны нөлден бастап жасайтынымызды көрсетуіміз қажет. Одан кейін Function name ретінде salesAnalysisReportDataExtractor деп, Runtime ретінде Python 3.8 нұсқасын көрсетіп, парақшаны соңына дейін айналдырамыз. Төменгі бөлігінде рөлді таңдау секциясы болады, мұнда бізде бар рөлді таңдап, рөлдер тізімінен salesAnalysisReportDERole, яғни Data Extractor role таңдаймыз. Create function батырмасын басуға асықпаймыз, алдымен Advanced settings секциясын ашуымыз қажет. Одан кейін Enable VPC жанына белгі қойып, VPC өрісінде біздің Lab VPC таңдаймыз. Төменірек Subnets таңдау өрісі бар, мұнда мұқият болып, private subnet 1 және private subnet 2 таңдау керек, содан кейін парақшаны соңына дейін айналдырамыз. Security groups өрісі үшін біз бұрын құрған Lambda SG security тобын таңдау қажет. Енді біз лямбда-функцияға қажетті барлық деректерді енгіздік, және экранның төменгі оң жағындағы Create function батырмасын баса аламыз. Біздің лямбда-функция VPC ішінде құрылып жатқандықтан, бұл әдеттегіден көбірек уақыт алады. Сіз шамамен 5 минуттай уақыт бөліп, шағын үзіліс жасай аласыз. Лямбда-функция құрылған соң, экранның жоғарғы бөлігінде лямбда-функция сәтті жасалғаны туралы жасыл фонда хабарлама көресіз. Енді біз лямбдамыздың кодын жүктей аламыз, ол үшін Code қойындысын ашу қажет. Содан кейін осы секцияның оң жағындағы Upload from батырмасын басып, ашылған тізімнен zip-файлды таңдаймыз. Қалқып шығатын терезе ашылып, мұнда Upload батырмасын басып, жергілікті компьютеріңізден қажетті zip-файлды тауып, Save батырмасын басу қажет. Біршама уақыттан кейін лямбда-функция сәтті жаңартылғаны туралы тағы бір хабарлама көресіз. Лямбда-функция ішінде бірнеше өзгеріс қалды. Configuration қойындысын, оның ішінде General configuration бөлімін ашып, Edit батырмасын басайық. Мұнда біз лямбда-функцияның негізгі ақпаратын өңдей аламыз. Зертханалық жұмыста көрсетілгендей Description мәтінін енгізуіміз қажет. Одан кейін Memory ретінде 128 мегабайт қоямыз, бұл лямбда-функция үшін мүмкін болатын ең аз өлшем. Содан соң Timeout өрісіне әдепкі 3 секундтың орнына 30 секунд қоямыз және экранның төменгі бөлігіндегі Save батырмасын басамыз. Бізді лямбда-функцияның басты парақшасына қайтарады, мұнда оның сәтті жаңартылғаны туралы жасыл фонда хабарлама көреміз. Соңғы қадам қалды — парақшаны соңына дейін айналдырып, Runtime settings бөлімінде дұрыс Handler көрсетуіміз керек. Қазіргі уақытта lambda handler мәні lambda_function.lambda_handler, оны өзгерту қажет. Handler-ді біз кодтағы негізгі функцияға өзгерістер енгізген жағдайда ғана өзгертеміз. Егер сіз кодыңызды кіріс функциясы lambda handler деп аталатындай етіп жазсаңыз, ешқандай қосымша өзгеріс енгізудің қажеті жоқ. Біздің жағдайда Edit батырмасын басып, Handler өрісіне келесі мәнді енгізу қажет. Содан кейін экранның төменгі оң жағындағы Save батырмасын басамыз. Бізді тағы да лямбда-функцияның басты парақшасына қайтарады және өзгерістер сәтті сақталғаны туралы хабарлама көреміз. Енді браузердегі сұрақтар қойындысына оралып, екінші сұраққа жауап беру қажет. Екінші сұрақ келесідей. Неліктен біз құрған лямбда-функцияны VPC ішіне орналастырдық? Жауап айқын, барлық нұсқаларды асықпай қарап, өзіңіз жауап беруге тырысыңыз. Бұл сұрақтың дұрыс жауабы – екінші нұсқа, біз лямбда-функцияны VPC ішінде құрдық, себебі ол RDS инстансымен әрекеттеседі. Осы нұсқаны таңдап, Submit батырмасын басу қажет. Енді үшінші тапсырманы бастаймыз, бұл тапсырмада екінші лямбда-функцияны құрамыз. Барлық әрекеттер ұқсас болады, тек айырмашылығы — VPC-мен байланысты баптауларды жасау қажет емес. Ендеше, бастайық. Алдымен AWS Lambda сервисіне өтуіміз қажет. Содан кейін лямбда-функциялар тізімі бар парақшада Create function батырмасын басамыз. Одан кейін лямбда-функцияны нөлден жасау опциясын таңдап, Function name және Runtime өрістерін толтыру қажет. Парақшаның төменгі бөлігінде бар рөлді қолдану керек екенін көрсетіп, тізімнен salesAnalysisReportRole рөлін таңдаймыз. Содан кейін экранның төменгі оң жағындағы Create function батырмасын басамыз. Бізді лямбда-функцияның басты парақшасына бағыттайды. Функция әлдеқайда тез құрылады және экранның жоғарғы бөлігінде лямбда-функция сәтті құрылғаны туралы жасыл фонда хабарлама көреміз. Енді осы лямбда-функцияның кодын жүктеу қажет, ол үшін Code қойындысын ашамыз. Содан кейін осы секцияның жоғарғы оң жағындағы Upload from батырмасын басамыз. Одан кейін .zip file опциясын таңдаймыз, қалқып шығатын терезе ашылады. Мұнда Upload батырмасын басып, жергілікті компьютерден екінші zip архивті тауып, Save батырмасын басу қажет. Бұны жасаған соң, лямбда-функция сәтті жаңартылғаны туралы хабарлама көреміз. Енді лямбда-функцияның негізгі ақпаратын жаңарту қажет. Сондай-ақ Configuration қойындысын, одан кейін General configuration бөлімін ашып, Edit батырмасын басу керек. Лямбда-функцияны өңдеу парақшасы ашылады, зертханалық тапсырма парақшасынан осы лямбда-функцияға арналған Description мәтінін көшіру қажет. Одан кейін Memory ретінде 128 мегабайт және Timeout ретінде 30 секунд қоямыз. Парақшаның соңына дейін айналдырып, Save батырмасын басамыз. Соңғы қадам — лямбда-функцияның басты парақшасында парақшаны соңына дейін айналдырып, Runtime settings бөлімін табу. Мұнда Handler жаңарту қажет, ол үшін осы секцияның жоғарғы оң жағындағы Edit батырмасын басамыз. Келесі парақша ашылады, мұнда Handler өрісін толтырып, экранның төменгі оң жағындағы Save батырмасын басу керек. Бізді лямбда-функцияның басты парақшасына қайта бағыттайды және өзгерістер сәтті сақталғаны туралы жасыл фонда хабарлама көреміз. Осылайша үшінші тапсырманы аяқтап, келесіге өте аламыз. Енді төртінші тапсырманы бастаймыз, бұл тапсырмада біз SNS topic құрамыз және баптаймыз. Алдымен сервис іздеу жолағын пайдаланып, SNS енгіземіз. Бірінші сілтеме — бізге керегі. SNS сервисінің басты парақшасына өткен соң, Topic name ретінде SalesReportTopic енгізіп, Next step батырмасын басамыз. Бізді жаңа SNS topic құру парақшасына бағыттайды. Type ретінде Standard таңдап, Name өрісі автоматты түрде толтырылады, ал Display name ретінде Sales Report Topic енгіземіз. Содан кейін парақшаны соңына дейін айналдырып, Create topic батырмасын басамыз. Бізді SNS topic басты парақшасына бағыттайды және экранның жоғарғы бөлігінде SNS topic сәтті құрылғаны туралы жасыл фонда хабарлама көреміз. Мұнда екінші лямбда-функциямен интеграциялау үшін осы SNS topic-тің ARN көшіріп алу қажет. Интеграция дегеніміз — ARN мәнін сақтайтын жаңа environment variable жасау. Осы арқылы лямбда-функция белгілі бір environment variable арқылы мәнді алып, осы topic-ке хабар жібере алады. Енді, осыны орындайық. Сервис іздеу жолағын пайдаланып, AWS Lambda сервисіне өтеміз. Содан кейін екінші лямбданы ашамыз — salesAnalysisReport. Лямбда-функцияның басты парақшасында Configuration қойындысын, одан кейін Environment variables бөлімін ашамыз. Көріп тұрғанымыздай, environment variables бапталмаған, сондықтан Edit батырмасын басу қажет. Біздің орта айнымалыларды өңдеу парақшасы ашылады. Add environment variable батырмасын басып, жаңа жол қосамыз және онда Key ретінде topicARN, ал Value ретінде SNS topic-тің ARN енгіземіз. Содан кейін Save батырмасын басамыз. Бізді лямбда-функцияның басты парақшасына қайтарады. Енді бізде бір бапталған environment variable бар екенін көреміз. Енді лямбда-функция environment variable topic ARN мәнін алған кезде, ол біздің SNS topic-тің нақты ARN мәнін алады. Осылайша, environment variables өзгерту арқылы біз лямбда-функцияны басқа SNS topic-ке ауыстыра аламыз. Environment variables-ті көп қолдану өте жақсы тәжірибе болып саналады және осының арқасында лямбда-функцияның әмбебап кодын жазып, оның жұмысын environment variables арқылы өзгертуге болады. Мұндай кодты жазу ұзаққа созылуы мүмкін, бірақ ол өзінің әмбебаптығының арқасында болашақта сізге көп уақыт үнемдейді. Енді сұрақтар парақшасын ашып, үшінші сұраққа жауап берейік. Үшінші сұрақ келесідей. Егер лямбда-функция кодында тиісті түзетулер енгізілсе, біз topic ARN мәнін AWS Systems Manager сервисінің параметрінде сақтай аламыз ба? Дұрыс жауап — иә, біз осылай істей аламыз, сондықтан Yes нұсқасын белгілеп, Submit батырмасын басамыз. Біз бесінші тапсырмаға көшеміз, бұл салыстырмалы түрде жеңіл тапсырма, біз мұны бұрын жасағанбыз. Біз өзіміздің SNS topic-ке email жазылымын жасаймыз. Ол үшін SNS topic-тің басты парақшасына жетуіміз қажет. Содан кейін Subscriptions қойындысын ашып, осы секцияның жоғарғы оң жағындағы Create subscription батырмасын басамыз. Бізді жаңа жазылым жасау парақшасына бағыттайды, Protocol ретінде Email таңдаймыз және Endpoint ретінде сізде қазір қолжетімді кез келген email енгіземіз. Менің жағдайымда негізгі C1oud Academy email-ін енгіздім — бұл academy@c1oud.org. Содан кейін экранның төменгі оң жағындағы Create subscription батырмасын басу қажет. Бұны жасағаннан кейін бізді жазылым парақшасына бағыттайды, сондай-ақ экранның жоғарғы бөлігінде SNS topic жазылымы сәтті құрылғаны туралы хабарламаны көреміз, бірақ күйі Pending confirmation болып тұр. Егер SNS topic басты парақшасына қайта оралсаңыз, онда біздің жазылымымыз көрсетіледі және мұнда да мәртебесі Pending confirmation болады. Енді пошта жәшігін ашу керек, хат келеді. Егер ол келмесе, Спам папкасын тексеріңіз, кейде бұл хабарламалар сонда түседі. Хаттың мазмұнын көресіз, онда сілтеме болады, жазылымды растау үшін сол сілтемеге өту қажет. Егер біз жазылымды растамасақ, SNS topic-тен хабарламалар таратылмайды. Сілтемеге өткен соң, жазылым сәтті расталғаны туралы хабарламаны көресіз. SNS topic-тің ARN де көреміз. Енді SNS topic парақшасына қайта оралып, жазылымды қарасаңыз, мәртебесі өзгеріп, Confirmed болды. Осылайша біз бесінші тапсырманы аяқтаймыз және мұнда төртінші сұраққа жауап беруіміз қажет. Сұрақ келесідей. Егер жазылымды растамасақ, біз SNS topic-тен хабарламаларды аламыз ба? Дұрыс жауап — No, яғни жазылым құрылған болса да, біз хабарламаларды алмаймыз. Тек жазылымды растағаннан кейін ғана SNS topic-тен хабарламалар ала бастаймыз. Сондықтан No нұсқасын белгілеп, Submit батырмасын басамыз. Енді алтыншы тапсырманы бастаймыз. Бұл тапсырмада біз өз лямбда-функциямыздың жұмысын тексереміз. Біз salesAnalysisReport лямбда-функциясын тексереміз. Бұл есептерді генерациялайтын лямбда-функция. Осы функцияны ашып, содан кейін экранның төменгі бөлігіндегі Test қойындысын ашамыз. Кез келген event жасай аламыз, мысалы, мазмұны төмендегідей Hello world шаблоны болсын. Event name енгізу керек, кез келген мән болуы мүмкін және осы секцияның жоғарғы оң жағындағы Save батырмасын басу керек. Бұны жасаған соң, test-1 атты тест event сәтті құрылғаны туралы хабарламаны көреміз. Енді оны лямбда-функцияны іске қосу үшін пайдалана аламыз. Мұнда Test батырмасын басу қажет. Батырманы басқан соң, лямбда-функцияның орындалуына біраз уақыт кетеді және лямбда-функция сәтті орындалғаны туралы хабарламаны көреміз. Енді егер поштаңызға кірсеңіз, келесі мазмұндағы хабарламаны алуыңыз керек. Егер солай болса, сіз осы уақытқа дейін бәрін дұрыс жасадыңыз және жетінші тапсырмаға өте аламыз. Жетінші тапсырмада біз event rule құрамыз, ол күн сайын белгілі бір уақытта біздің лямбда-функцияны триггерлейді. Ал лямбда-функция өз кезегінде жұмыс нәтижесі бойынша есеп генерациялап, оны SNS topic арқылы жібереді. Мұны жасау үшін лямбда-функцияның басты парақшасында Add trigger батырмасын басу керек. Бізді жаңа триггер құру парақшасына бағыттайды, Service ретінде EventBridge таңдаймыз. Содан кейін жаңа rule құрамыз деп көрсетеміз, Rule name өрісіне кез келген мән енгізуге болады. Менің жағдайымда бұл daily-event-rule, сонымен қатар Description енгізу керек және Rule type ретінде Schedule expression таңдау керек, яғни белгілі бір кестеге негізделген rule. Rule expression ретінде cron өрнегін көрсетеміз, мен ең жақын уақытты көрсетемін. Назар аударыңыз, уақытты UTC бойынша көрсету керек, сондықтан қажетті сағаттарды қосу немесе алу қажет болады. Осыдан кейін экранның төменгі бөлігінде Add батырмасын басу қажет. Содан кейін бізді лямбда-функцияның басты парақшасына бағыттайды, жасыл фонда триггер сәтті құрылып, белсендірілгені туралы хабарламаны көреміз. Сондай-ақ триггерлер тізімінде біздің event rule бар екенін көреміз, мұны Configuration қойындысындағы Triggers бөлімінде де көруге болады. Бізде бір триггер бар екенін және оның атауы daily-event-rule екенін көреміз. Жақсы, енді біраз күтеміз, cron өрнегін бірнеше минуттық қор қалатындай етіп енгізуіңіз керек еді. Бірнеше минуттан кейін event rule орындалып, лямбда-функцияны іске қосады және сіз дәл сондай хат аласыз, бірақ оны сіз емес, event rule жіберген болады. Егер солай болса, бәрін дұрыс жасадыңыз, енді ең соңғы сұраққа жауап беруіміз керек. Сұрақ мынадай: Фрэнк Софияға бірнеше күн бойы есептер алмай жүргенін жазды, бұл не болуы мүмкін және troubleshooting неден бастау керек? Бірнеше нұсқа бар, видеоны тоқтатып, өзіңіз жауап беріп көріңіз. Дұрыс жауап — CloudWatch сервисінде лямбда-функция логтарын ашу. Сол жерде қате не себептен болғанын және есептердің неге келмей жатқанын толығырақ көруге болады. Үшінші нұсқаны таңдап, Submit батырмасын басамыз. Біз зертханалық жұмыстың соңына келдік. Енді автобағалау скриптін іске қосып, осы зертханалық жұмысты аяқтайық. Зертханалық жұмыстың басты парақшасын ашып, Submit батырмасын басу керек, содан кейін бұл әрекетті растау қажет. Біршама уақыттан кейін экранның оң жағында бағаларыңызды көресіз. Егер бұл қойынды шықпаса, экранның жоғарғы оң жағындағы Grades батырмасын басу қажет. Скрипт орындалса, ол осы қойындыны оң жақта көрсетеді. Менің жағдайымда мен 35 ұпайдың 35-ін жинадым, егер сіз аз жинасаңыз және жақсартқыңыз келсе, қай қадамда ұпай жетіспейтінін қарап шығуға болады. Содан кейін тапсырма мәтінін қайта оқып, қатені түзетіп, автобағалау скриптін тағы бір рет іске қосуға болады. Енді жұмысты аяқтаймыз, AWS Management Console қойындысын ғана қалдыру қажет. Экранның жоғарғы оң жағында пайдаланушы атын басамыз. Төменгі тізімнен Sign out батырмасын басамыз. Енді зертханалық жұмыстан дұрыс шығуымыз қажет. Ол үшін экранның жоғарғы оң жағындағы End lab батырмасын басып, бұл әрекетті растау керек. AWS уақытша аккаунтын жою процесін бастағанымыз туралы хабарламаны көреміз және бұл парақшаны жабуға болады. Бүгінгі сессияның соңына келдік. Назарларыңызға рахмет, келесі белсенділіктерде кездескенше.
