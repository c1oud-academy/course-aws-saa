Қайырлы күн, құрметті студенттер. Зертханалық жұмысты талдаудың кезекті сессиясында сіздерді көргеніме қуаныштымын. Бүгінгі зертханалық жұмыстың тақырыбы — AWS бұлтында инфрақұрылымды орнатуды автоматтандыру. Ендеше, бастайық. Бірінші тапсырманы орындауға кірісеміз. Мұнда біз AWS CloudFormation Template-ін нөлден бастап құрамыз. AWS Management Console басты парақшасынан бастаймыз. Осы жерден Cloud9 сервисіне өтуіміз керек. Бұл — бізге IDE ұсынатын сервис. Бізде бір environment бар, оны ашу қажет. Экранның сол жақ жоғарғы бұрышындағы File батырмасын пайдаланып, жаңа файл жасау қажет. Жаңа файлды сақтау керек болады. Оған S3.yaml деген ат беріп, келесі жолдарды толтырамыз. Бұл жолдарды зертханалық жұмыстағы тапсырмадан көшіруге болады. Енді template-імізге сипаттама қосуымыз қажет. Бұл сипаттама: cafe S3 template. Жақсы, енді экранның төменгі бөлігінен Bash терминалын ашып, алғашқы aws configure get region командасын енгіземіз. Нәтижесінде, бізде әдепкі аймақ us-east-1 екенін көреміз. Енді екінші команданы енгізуіміз қажет, бұл команда CloudFormation stack құрады, аты CreateBucket болады және ол S3.yaml файлын қолданады. Егер жауап ретінде StackId бар JSON көрсеңіз, бұл команданың сәтті орындалғанын және stack құру процесі басталғанын білдіреді. Енді AWS Management Console ішінен stack-імізге көз жүгіртейік. Ол үшін CloudFormation сервисіне өту қажет. Содан кейін stacks тізімінен CreateBucket таңдаңыз, және парақшаның орталық бөлігінде бірнеше қойынды шығады. Бірінші қойынды — Stack Info, мұнда stack туралы жалпы ақпарат көрсетіледі. Келесі қойынды — Events, мұнда stack-ті жаңарту, құру немесе жою кезіндегі оқиғалар кері хронологиялық ретпен көрсетіледі. Біз stack құрғандықтан, ең төменгі жолда оның құруы басталғаны көрсетілген, Logical ID ретінде stack атауын көреміз. Ортада тұрған үш жол S3 bucket атты жалғыз ресурсымыздың құрылуын көрсетеді, ол сәтті құрылды. Жоғарғы жағында орналасқан соңғы оқиға — бұл бірінші жол, онда CreateBucket stack-іміздің Create complete күйіне өткендігі айтылған, яғни ол сәтті құрылды. Resources қойындысын ашсақ, ресурсымыз — S3 bucket көрінеді, сілтеме де бар және күйі — Create complete деп тұр. Outputs қойындысын әзірге толтырмағанбыз, сондықтан ол бос, Parameters те солай. Template қойындысында біз template-імізді және оның мазмұнын көреміз. Осылайша CloudFormation stack-іміздің мәліметтерін қарап шықтық. Енді ресурсымызды қарайық, ол үшін S3 сервисіне өту қажет. Бакеттер тізімінен біздікі — createbucket-s3 bucket- және кездейсоқ символдар жиынтығымен аталғанын табамыз. Бірінші тапсырма аясында енді бірнеше сұраққа жауап беру қажет. Ол үшін зертханалық жұмыстың басты парақшасын ашамыз. Экранның оң жақ жоғарғы бөлігіндегі Details батырмасын басып, ашылған тізімнен Show батырмасын басамыз, шыққан терезеден Access the multiple choice questions сілтемесін табамыз. Осы сілтемені бассақ, бізді жаңа браузер қойындысына бағыттайды, мұнда 6 сұрақ бар, қазір алғашқы үшеуіне жауап беруіміз керек. Ендеше қарайық. Бірінші сұрақ: Біз S3 bucket-ке арнайы ат бермеген жағдайда ол сәтті құрылды ма және қандай ат берілді? Template ішіндегі ресурстар тізімін қайта қарап шығайық, сол жерде S3 bucket атауы көрсетілген — createbucket-s3bucket- және кездейсоқ символдар. CreateBucket — бұл біздің template атауы, S3 bucket — бұл біздің template-тегі ресурс атауы (Logical ID). Сұраққа оралсақ, дұрыс жауап — үшінші нұсқа: иә, ол сәтті құрылды, біз оған арнайы ат бермесек те. Әдепкіде, аты stack атауымен, кейін Logical ID арқылы, соңында кездейсоқ әріптер мен сандар арқылы құрылады. Жауап нұсқасын таңдағаннан кейін Submit батырмасын басу қажет. Бұл әрекетті әрбір сұрақ үшін қайталаймыз. Енді екінші сұраққа көшейік. Екінші сұрақ: S3 bucket қай аймақта құрылды және неге? Дұрыс жауап — екінші нұсқа: S3 bucket AWS CLI арқылы CloudFormation сервисінде команда іске қосылған аймақта құрылды. Егер есіңізде болса, біз create stack командасын іске қостық, бірақ арнайы аймақты көрсеткен жоқпыз, себебі Cloud9 Environment әдепкі аймақта құрылған еді, bash терминалында әдепкі аймақты сұратқанда біз us-east-1 нәтижесін алдық, яғни бұл North Virginia. Осылайша команда осы аймақта орындалды және ары қарай CloudFormation сервисі осы аймақта template-іміздегі барлық ресурстарды құрды. Екінші жауап нұсқасын таңдаймыз және Submit батырмасын басамыз. Енді үшінші сұрақты қарайық, сұрақ келесідей: S3 bucket құру үшін CloudFormation template-інде қанша жол код жазу керек болды? Ендеше, template-імізге қайта оралып, қарайық. Ең алдымен, біз осы ресурсты құратынымызды жариялап, Logical ID көрсетуіміз керек. Біздің жағдайда бұл — S3 bucket. Содан соң типін көрсетуіміз қажет, яғни бұл S3 bucket екенін жазамыз және қалған параметрлер міндетті емес болғандықтан, тек екі жол кодпен S3 bucket сәтті құрыла алады. Сондықтан дұрыс жауап бірінші нұсқа — two lines, оны таңдап, Submit батырмасын басу қажет. Біз екінші тапсырманы бастаймыз, бұл тапсырма аясында веб-сайтымыздың контентін S3 bucket-імізге жүктейміз және сол bucket-те static website hosting функциясын қосамыз. Ендеше бастайық. Зертханалық жұмыс тапсырмасында дайын командалар берілген, оларды біртіндеп көшіру және bash терминалына енгізу қажет. Алдымен контентті интернеттен Cloud9 ортасына көшіреміз. Содан кейін екі команда орындап, S3 bucket жағындағы қол жеткізу құқықтарын орнатамыз. Мұнда міндетті түрде кілттік сөзді S3 bucket-тің нақты атауына ауыстыру қажет болады. Соңғы қадамда, жүктелген веб-сайт контентін S3 bucket-ке жүктейміз. Осы команданы орындаған сәтте бірнеше жол шығуы тиіс, онда белгілі бір файлдың S3 bucket-ке сәтті жүктелгені туралы хабарлама болады. Енді template жағында кейбір өзгерістер енгізуіміз қажет және stack-ті жаңартамыз. Өзгерістер енгізу үшін AWS documentation бізге жақсы көмек болады. Сондықтан CloudFormation сервисінің құжаттамасына берілген сілтеме арқылы өтейік. Содан кейін сол жақтағы навигациялық мәзірді төмен сырғытып, Amazon S3 сервисін табамыз. Оны ашып, AWS S3 bucket ресурсын таңдаймыз. Сондай-ақ сізге бір кеңес бергім келеді, CloudFormation template-тегі ресурс сипаттамасының дұрыс парақшасына тез өтуге болады. Тек aws cf (CloudFormation) және одан кейін сервис атауы мен ресурс атауын енгізсеңіз жеткілікті. Біздің жағдайда бұл — aws cf s3 bucket, және алғашқы жарнамасыз сілтеме — бізге қажет парақша. Біз CloudFormation template-імізге өзгерістер енгізуді бастаймыз. Ең алдымен, Deletion policy қосуымыз қажет, яғни stack жойылғанда біздің S3 bucket сақталып қалуы үшін. Жақсы, парақшада алдымен YAML бойынша фильтр жасайық. Егер JSON-мен жұмыс істесеңіз, онда JSON таңдаңыз, содан кейін CTRL+F пернелер тіркесімін басып, deletion немесе deletion policy сөздерін іздеңіз. Төмен қарай сырғытып, Examples бөлімінде ең алғашқы мысалды табамыз — онда қажет deletion policy көрсетілген S3 bucket құрылып жатыр. Бұл жолды көшіріп алып, template-імізге үшінші жол ретінде қоямыз. Осы әрекеттен кейін static website hosting функциясын S3 bucket үшін қосуға кірісеміз. Ол үшін AWS құжаттама парақшасына қайта оралып, «static» сөзін іздейміз. Алғашқы табылған орын — бізге керегі. Мұнда WebsiteConfiguration деген қасиет бар және оның түрі WebsiteConfiguration ретінде көрсетілген, бұл жай жол емес, белгілі бір қасиеттер жинағы. Қазір оны қараймыз. Бірақ алдымен template жағында дайындық жасайық. Properties деген секцияны Type және Deletion policy тұрған деңгейге қосуымыз керек. Содан кейін Properties ішінде WebsiteConfiguration қасиетін көрсетеміз және website hosting параметрлерін енгізе бастаймыз. Қажетті ресурсқа арналған құжаттама парақшасына өтіп, әрі қарай жалғастырамыз. Мұқият болыңыз, тақырыпта AWS S3 Bucket WebsiteConfiguration деп жазылған. YAML бойынша фильтр жасап көрейік, сонда бірден осы ресурстың синтаксисін көреміз. Біз мұнда 4 қасиет бар екенін көреміз — бұл ErrorDocument, IndexDocument, RedirectAllRequestsTo және RoutingRules. Мысал ретінде ErrorDocument-ті қарастырайық, сәл төменде әр қасиет сипатталған, біз бұл қасиетке қысқаша сипаттама берілгенін көреміз. Содан кейін бұл міндетті емес екенін және Type ретінде жолдық мән беру керектігі көрсетілген. Егер қалған қасиеттерге, яғни IndexDocument, RedirectAllRequestsTo және RoutingRules қарасақ, олар да міндетті емес екенін көреміз. Тапсырма аясында бізге IndexDocument қасиетін қосу керек, қалғандарын толтыру міндетті емес. Мән ретінде index.html көрсетуіміз керек, егер құжаттама парақшасын төмен жылжытсақ, дайын мысалды көреміз. Онда IndexDocument қана емес, басқа қасиеттер де толтырылған, бізге тек IndexDocument қажет, оны көшіріп алып template-імізге қосамыз, ол келесі түрде болады. Жақсы, біз S3 bucket ресурсына қажетті барлық өзгерістерді енгіздік. Енді веб-сайтымыздың URL-ын Outputs ішіне қосуымыз қажет. Соңғы қадам ретінде біз template-імізге output параметрлерін қосуымыз керек. Дайын сілтеме бар, соған өту керек болады. Examples бөлімінде толық дайын код жолдары бар, оларды көшіріп алып template-ке қою қажет. Сырттан алынған код жолдарын қойғанда міндетті түрде әр жолды мұқият тексеріңіз. Әсіресе, бұл сіздің ресурстарыңыздың Logical ID-не қатысты. Егер сәйкес келмесе, қате аласыз. Біздің жағдайда bucket-тің Logical ID сәйкесті, сондықтан ешқандай өзгеріс енгізудің қажеті жоқ. Жақсы, енді template-ті валидациялауды бастай аламыз. Егер команда орындалғанда JSON нәтижесін көрсек, бұл валидация сәтті өткенін білдіреді. Енді update stack командасын орындаймыз, параметрлер сол күйінде қалады: Stack name ретінде CreateBucket көрсетеміз, Template body ретінде жаңартылған YAML файлды таңдаймыз және Enter басамыз. Нәтижесінде біз StackId көрсетілген JSON көреміз, бұл stack жаңарту командасы сәтті басталғанын білдіреді. Енді AWS Management Console арқылы өзгерістерімізді қарайық. Ең алдымен CloudFormation сервисі қажет, stacks тізімін ашамыз. Біздің CreateBucket stack-ін таңдаймыз, оны ашқан сәтте барлық жаңартулар аяқталған, stack статусы Update complete деп тұр, яғни бәрі сәтті өтті. Соған қарамастан, Events қойындысын ашып, қандай оқиғалар болғанын қарайық. Ең алдымен stack Update in progress күйіне өтті. Одан кейін S3 bucket те Update in progress күйіне өтті. Сәл уақыттан соң Update complete күйіне өтті. Содан кейін stack Update complete clean up in progress күйіне ауысты. Бұл дегеніміз, барлық қажетті өзгерістер енгізілгенін қосымша тексерді, егер бәрі дұрыс болса, келесі күйге өтеді және Update complete күйіне жетеді. Енді Outputs қойындысын ашып, веб-сайтқа өту үшін берілген сілтемені қолданамыз. Егер сіз ұқсас көріністі көрсеңіз, бұл веб-сайт сәтті ашылғанын және тапсырманы дұрыс орындағаныңызды білдіреді. Енді қосымша S3 bucket-ті ашып, Properties қойындысын ашып, парақшаның ең соңына дейін жылжытайық. Соңғы бөлім — static website hosting функциясына қатысты және біз оның қосылғанын көріп тұрмыз. Оны біз қолмен емес, AWS CloudFormation сервисі арқылы іске қостық. Үшінші тапсырмаға көшеміз, бұл тапсырмада бізге арнайы дайындалған CodeCommit репозиторийін Cloud9 ортасына көшіру қажет. Ол үшін AWS Management Console ішінен CodeCommit сервисін ашамыз. Бір ғана репозиторий көресіз — CFTemplatesRepo. Оны ашайық, навигациялық мәзірдің сол жағында Code бөлімі таңдалады, онда репозиторийдің мазмұны көрсетіледі, біз әдепкі main тармағында боламыз. Репозиторий ішінде бір templates атты папка бар, оны таңдап, ішіндегісін қарайық. Ішінде үш yaml файл бар, біріншісі — start-lab, мысал ретінде соны ашып, оның ішінде не бар екенін көрейік. Назар аударыңыз, бұл template екі ресурсты қамтиды: бірінші ресурс — Cloud9 ортасы, ал екіншісі — біз қазір қарап отырған дәл осы атаудағы репозиторий. Әрине, бұл біздің уақытша AWS аккаунтымызды инициализациялау үшін қолданылған template емес. Бірақ ол өте ұқсас, тек бірнеше қосымша ресурстар, қосымша тексерулер мен рұқсат беру қосылады, және осындай template зертхана жұмысы аясында уақытша AWS аккаунтын инициализациялау үшін іске қосуға болады. Жақсы, енді экранның жоғарғы бөлігіндегі батырма арқылы репозиторийлер тізіміне қайта ораламыз. Мұнда репозиторийлер тізімінде репозиторийді көшіру сілтемелері болады, бізге HTTPS арқылы көшіру сілтемесі керек. Осы сілтемеге басып, оны көшіреміз. Енді Cloud9 ортасына оралып, bash терминалында git clone командасы мен репозиторийдің мекенжайын енгіземіз. Көшіру аяқталған соң, git репозиторийдің түбіріне өтеміз де, git status командасын орындаймыз. Егер ұқсас хабарламалар шықса, бұл репозиторий сәтті көшіргенін білдіреді, келесі тапсырмаға көше аламыз. Төртінші тапсырманы бастаймыз, бұл тапсырмада біз CloudFormation, CodeCommit және CodePipeline сервистерін қолданып барлық қажетті желілік ресурстарды құрамыз. Алдымен Cloud9 ортасына кіруіміз керек. Сол жақтағы навигациялық мәзір арқылы template1.yaml файлын ашамыз. Бұл жерде желілік ресурстар жасалады. Енді сол жақ мәзірде осы template-ке оң жақ батырмамен басып, Duplicate тармағын таңдаймыз. Жаңа файл жасалады, оны cafe-network.yaml деп қайта атау керек. Содан кейін template-ке Description қосамыз: Network layer for the cafe, және бұл файлдағы өзгерістерді сақтаймыз. Енді AWS Management Console ішінен бізге дайындалған pipeline-дарды қарайық. Ол үшін CodePipeline сервисіне кіреміз. Бізге екі pipeline дайындалғанын көреміз: біреуі application layer үшін, екіншісі network layer үшін. Сондай-ақ олардың күйі Failed екенін байқаймыз, бұл қалыпты жағдай, өйткені pipeline template-тің бар-жоғын тексереді, ал бұл template-тер әлі жасалмағандықтан, pipeline қате шыққан. Енді, cafe-network pipeline-ын ашып, оның қандай қадамдары бар екенін қарайық. Бірінші қадам — бұл дереккөзі, мұнда AWS CodeCommit сервисі қатысады. Ақпарат белгішесін басып, мәліметтерді қарайық. Бұл қадамда CFTemplatesRepo репозиторийі және main тармағы қолданылады. Жарайды, Done батырмасын басайық та, екінші қадамға өтейік. Екінші қадам — бұл deployment, мұнда AWS CloudFormation сервисі қолданылады. Details ашсақ, біз update-cafe-network stack-пен жұмыс істейміз, ал template келесі жолмен көрсетіледі. Source қадамындағы файлдар ішінен templates папкасындағы cafe-network.yaml файлын табамыз. Егер ол бар болса, біз бұл template-ті stack құру немесе жаңарту үшін қолданамыз. Жақсы, Done батырмасын басайық және Cloud9 ортасына оралайық. Біз репозиторийге өзгеріс енгіздік, енді оны тіркеп, CodeCommit репозиторийіне жүктеуіміз қажет. Ол үшін алдымен git status командасын енгізіп, қандай өзгерістер бар екенін көреміз. Сосын git add арқылы өзгерген файлдарды белгілейміз. git commit арқылы өзгерістерді тіркеп, жаңа commit жасаймыз. Одан кейін git push командасы арқылы тіркелген commit-терді CodeCommit репозиторийіне жүктейміз. Егер сіз pipeline парақшасын ашып жаңартсаңыз, Source Status мәні Succeeded болып тұрғанын көресіз, яғни commit жіберу арқылы pipeline автоматты түрде триггерленді. Сондай-ақ commit-ті байқаңыз, бұл — біз енгізген commit. Source қадамы аяқталысымен, екінші қадам Deploy автоматты түрде басталды және ол қазір орындалуда. Келесіде CloudFormation сервисіне өтейік те, stack-тің қалай құрылып немесе жаңартылып жатқанын қарайық. Біз ашып үлгергенше, stack сәтті құрылып қойған екен — update-cafe-network, статус Create complete деп тұр. Events қойындысын ашсаңыз, соңғы оқиға — stack Create complete күйіне өтті. Жақсы, Resources қойындысын ашайық. Барлық желілік ресурстарды көреміз, Output әзірге бос. Енді шын мәнінде ресурстар AWS аккаунтында бар ма, соны тексерейік. Ол үшін VPC сервисіне өтеміз, біздің VPC атауы Cafe VPC, оны VPC тізімінен көреміз. Сол жақтағы навигациялық мәзірді пайдаланып, Internet Gateways тізімін ашайық. Екі Internet Gateway бар, олардың бірі Cafe VPC-ге байланған және атауы Cafe IGW, яғни Internet Gateway-дің қысқартылған түрі. Енді template-імізге оралып, Internet Gateway атауын қайта тексерейік. Шынында да, біз Internet Gateway ресурсына келесі тегтерді қосқанбыз: Key ретінде name, Value ретінде Cafe IGW көрсеткенбіз. Жақсы, бұл барлық ресурстарымыздың AWS CloudFormation template көмегімен сәтті құрылғанын білдіреді. Осылайша төртінші тапсырма аяқталды, келесіге өте аламыз. Бұрын біз stack-іміздің Output параметрлерінің тізімін арнайы қарап едік, ол бос болды. Енді басқа stacks осы мәндерді қолдана алатындай екі output параметрін қосуымыз қажет. Сонымен бесінші тапсырманы бастаймыз және network stack-ті жаңартатын боламыз. Зертханалық жұмыста дайын код жолдары берілген, оларды көшіріп, template-імізге қою қажет. Қандай код қосқанымызды көрейік. Outputs секциясын жарияладық, екі output параметрін қостық, Description мен Value-ден бөлек, Export қасиетін де көрсеттік. Бұл — осы output параметрлерінің мәнін басқа stack-тер сұрата алатынын білдіреді. Жақсы, енді CloudFormation template-іміздегі өзгерістерді сақтауымыз керек, сосын bash терминалын ашып, оларды git арқылы тіркеуіміз қажет. Алдымен git status командасымен өзгерістер бар-жоғын тексереміз. Содан кейін git add * және жұлдызша арқылы барлық өзгерістерді қосамыз. git commit арқылы тіркеп, жаңа commit құрамыз және git push арқылы оларды AWS CodeCommit репозиторийіне жүктейміз. Енді pipeline парақшасына қайта оралсақ, pipeline автоматты түрде іске қосылғанын көреміз. Репозиторий жағына өзгеріс енгізілгендіктен, бірінші қадам сәтті орындалған, оның күйі — Succeeded. Сонымен қатар commit өзгерген, бұл — біз құрған соңғы commit және қазір pipeline күйі — Deploy. Жақсы, енді CloudFormation ішіне кіріп, stack-імізді қарайық. Өзгеріс аса көп болмағандықтан, stack жаңартылып үлгерген — күйі Update complete. Events тізімін ашсақ, бар болғаны үш оқиға тіркелген. Бірінші оқиға — stack күйі Update in progress болған. Екінші оқиға — stack Update complete cleanup in progress күйіне өткен. Яғни stack барлық өзгерістер қолданылғаннан кейінгі тексеру күйінде болған. Ресурстарға өзгеріс енгізілмегендіктен, тек output қосылғандықтан, ешбір ресурс үшін оқиғалар тіркелмеген. Жақсы, соңғы оқиға — stack Update complete күйіне өткен. Outputs қойындысын ашсақ, template-ке енгізген өзгерістер stack ішінде пайда болғанын көреміз. Екі output параметрі көрініп тұр — public subnet ID және VPC ID, сондай-ақ Description берілген және ең маңыздысы — Export name бағаны толтырылған. Export name арқылы біз бұл output параметрлерге басқа stack-терден қол жеткізе аламыз. Бесінші тапсырма аяқталды, келесіге өтеміз. Алтыншы тапсырманы бастаймыз, бұл жерде AWS CloudFormation template-ке EC2 инстанс құру үшін код жолдарын қосамыз, содан кейін application stack құрамыз. template2.yaml файлын көшіру қажет болады, оның атын cafe-app.yaml деп өзгертеміз. Мұнда біз алдын ала дайындалған template-ті көреміз. Ең алдымен үшінші параметрді қосуымыз қажет. Бұл үшін қажетті код жолдары сілтемеде бар. Оларды тауып, көшіріп, template-ке қою жеткілікті. Одан кейін зертханалық тапсырма бойынша косметикалық өзгерістер енгізу керек. Содан кейін AWS EC2 instance ресурсы бойынша документацияны ашу ұсынылады. Біз оны қажетті код жолдарын қосу үшін пайдаланамыз. Осы слайдта EC2 инстансты құру үшін қажет барлық қосылатын бөлім көрсетілген. Енді template-іміздің валидациясын жасау қажет. Егер валидацияны орындау нәтижесінде қате шықпаса және JSON секілді жауап алсақ, бұл — валидация сәтті өткенін білдіреді. Енді өзгертулерді сақтап, commit жасап, оларды CodeCommit репозиторийіне push жасаймыз. Commit-терді push жасағаннан кейін, pipeline-дар триггерленіп, автоматты түрде іске қосылады. CafeAppPipeline ашайық, мен оны соншалықты тез аша алдым, себебі бірінші қадам әлі аяқталмапты. AWS CodeCommit күйі — In progress, сәл күтіп парақшаны жаңартсақ, бірінші қадам — Source сәтті орындалып, Succeeded күйіне өткенін көреміз. Сонымен қатар біз CodeCommit хабарламасымен commit-імізді көріп тұрмыз және CodePipeline екінші қадамға көшкенін де байқадық. Қазір біздің stack AWS CloudFormation сервисін қолдана отырып орнатылып жатыр. Енді AWS CloudFormation сервисіндегі stack-імізді тікелей ашайық, оның атауы update-cafe-app. Ол әлі аяқталмаған, қазіргі күйі — Create in progress. Events қойындысын ашсақ, кейбір ресурстар әлі де құрылу үстінде екенін көреміз. Күтіп, stack сәтті құрылып, Create complete күйіне өткенін күтеміз. Events қойындысында барлық оқиғаларды көреміз және соңғы оқиғада stack Create complete күйіне өткенін байқаймыз. Resources қойындысын ашсақ, екі ресурс құрылғанын көреміз — бұл security тобы мен EC2 инстансымыз. EC2 инстансымыздың Physical ID-ін басып, осы ресурстың парақшасын ашайық. Өтіп, инстансты таңдасақ, ол туралы мәліметтерді көреміз, Security қойындысында CafeRole рөлі байланысқанын көреміз. Сондай-ақ бұл рөл security топқа байланысқанын көреміз, оған сәйкес inbound ережелер бар — HTTP және SSH трафигіне интернеттен кіруге рұқсат берілген. Біраз күтейік, барлық жүйелік тексерулер сәтті өткен соң, қосымшамыздың жұмысын тексере аламыз. Жақсы, дайынбыз, енді инстансымызды таңдап, Details қойындысын ашып, жалпыға ортақ IP-адресін көшіруіміз қажет. Еске салайын, біз бұл IP-адресті output-қа да қосқанбыз, сондықтан оны сол жерден де көшіруге болады. IP-адресті браузердің жаңа қойындысында ашайық, келесі хабарламаны көреміз — бәрі дұрыс. Енді осы URL-адреске /cafe қосуымыз қажет және келесі қосымша ашылуы керек. Егер шынымен солай болса, барлық әрекеттерді дұрыс орындағанбыз. Сондай-ақ AWS Management Console-ге қолмен араласусыз, AWS CloudFormation сервисі арқылы біздің IT-инфрақұрылымымыздың application layer-ін бұлттағы AWS-те сәтті деплойдедік. Енді қалған үш сұраққа жауап беруіміз керек, төртіншісінен бастаймыз. Төртінші сұрақта бізден update-cafe-app stack үшін LatestAmiId параметрінің мәнін қарауды сұрайды. Оны орындау үшін тиісті қойындыны ашып, осы параметрдің мәнін қарастырамыз. Жақсы, көрдік, дұрыс жауап нұсқасын белгіледік те, Submit батырмасын басамыз. Егер тапсырманы орындаған болсақ, бұл оңай сұрақ. Бесінші сұраққа көшеміз, мұнда да оңай сұрақ, update-cafe-app stack қолданған IAM рөлді қарау қажет. Ол үшін Stack info қойындысын ашып, парақшаның оң жақ төменгі бөлігінен IAM рөлін көреміз. Жақсы, оны жауап нұсқаларынан тауып, белгілеп, Submit батырмасын басамыз. Соңғы сұрақ мынадай: егер AWS CodeCommit сервисінде репозиторий ашсақ, кейін commits тізімін ашып, кез келген commit-ті ашсақ, қандай парақша ашылады? Ендеше, соны істеп көрейік. Біз репозиторийдің басты парақшасында тұрмыз, сол жақтағы навигация арқылы Commits бөлімін таңдаймыз. Содан кейін commits тізімі ашылады, соңғы commit-ті таңдаймыз, және commit сілтемесін ашқанда мынадай көрініс ашылады. Commit туралы барлық мәліметті көреміз: кім және қашан жасағанын, сондай-ақ парақшаның төменгі жағында қандай файлдарда қандай өзгерістер болғанын көреміз. Жақсы, үшінші жауап нұсқасын таңдап, Submit батырмасын басамыз. Осылайша барлық тест сұрақтарына жауап беріп, алтыншы тапсырманы аяқтадық. Жетінші тапсырманы бастаймыз, бұл тапсырмада біз өз IT-инфрақұрылымымыздың көшірмесін көршілес AWS аймағында жасаймыз. Сонымен, IDE Cloud9 ішінде келесі команданы іске қосамыз, мұнда жаңа параметр — аймақ, мәні us-west-2, яғни Oregon аймағы. Команда орындалғаннан кейін JSON жауап аламыз, бұл — stack құру командасы сәтті басталғанын білдіреді. Мұны тексерейік. AWS Management Console-ды ашу керек, CloudFormation сервисіне кіріп, аймақты ауыстырамыз. Аймақты ауыстыру — экранның оң жақ жоғарғы бұрышында, бізге керек аймақ — Oregon. Оны таңдағаннан кейін stacks тізімін көреміз. update-cafe-network stack бар, ол бірнеше секунд бұрын құрылды және қазіргі күйі — Create Complete. Events қойындысында да осыны көреміз. Енді VPC сервисінен ресурстарымызды қарап көрейік. Бізге кез келген бір ресурсты қарау жеткілікті, мысалы, біздің VPC болсын. VPC тізімінің парақшасын ашсақ, дұрыс аймақта екенімізді міндетті түрде тексеріңіз. Егер сіз Cafe VPC көріп тұрсаңыз — онда бәрін дұрыс жасадық деген сөз. Енді Oregon аймағында жаңа Key Pair жасауымыз қажет. Key Pair-лер аймақ деңгейінде жасалады. Еске салайын, Key Pair бізге не үшін керек — оны EC2 инстансымызға байлаймыз. Кейін осы Key Pair көмегімен EC2 инстанстарға SSH арқылы қосыла аламыз. Ендеше, бастайық. EC2 сервисіне өтіп, сол жақтағы навигация мәзірінен Key Pairs тармағын таңдаңыз. Бұл аймақта бізде әлі Key Pair жасалмағанын көреміз. Мұны түзетейік — экранның оң жақ жоғарғы бұрышындағы Create Key Pair батырмасын басамыз. Мұнда атау ретінде `cafe-oregon` енгізу қажет. Ол CloudFormation template ішіндегі Mapping бөлімінде көрсетілген Key Pair атауымен сәйкес болуы тиіс. Атау енгізілген соң, қалған параметрлерді әдепкі күйінде қалдырып, төменгі оң жақтағы Create Key Pair батырмасын басамыз. Біз Key Pairs тізіміне қайта бағытталамыз және Key Pair сәтті жасалғаны туралы хабарламаны көреміз. Жақсы. Енді template-імізді ашайық. Mappings бөліміне қараңыз. Мұнда RegionMap бар, әр аймаққа Key Pair атауы көрсетілген және Oregon үшін `cafe-oregon` екені жазылған. Жақсы, енді біз Oregon аймағында Application Stack жасауға дайынбыз. Бұған дейін біз CloudFormation Stack жасаудың түрлі әдістерін қолдандық. Бірінші рет AWS Management Console арқылы жасадық. Содан соң AWS CLI арқылы команданы пайдаланып Stack құрдық. Одан кейін CloudFormation, CodeCommit және CodePipeline байланысын пайдаланып, репозиторийдегі өзгеріс кезінде pipeline автоматты түрде триггерленіп, Stack-ті жаңартатын тәсілді қолдандық. Осылайша CloudFormation сервисімен жұмыс істеудің үш тәсілін қолданып көрдік. Енді төртінші тәсілді қарастырайық. Ол үшін S3 сервисінен атауында `RepoBucket` сөзі бар бакетті табу керек. Оны ашайық. Енді `cafe-app.yaml` файлын осы S3 бакетке көшіру қажет. Қажетті команданы көріп тұрсыз. Оны орындаған соң бакеттің мазмұнын ашайық — yaml файлының онда бар екенін көреміз. Оны таңдап, жоғарыдағы Copy URL батырмасын басамыз. Жақсы, енді S3 бакеттегі yaml файлға сілтемеміз бар. Енді AWS Management Console-де CloudFormation сервисіне өтіп, міндетті түрде Oregon аймағында екенімізге көз жеткізіп, жоғарғы оң жақта Create Stack батырмасын басып, бірінші опцияны таңдаймыз. Бұл жерде бізде дайын template бар екенін көрсетеміз. Template көзі ретінде Amazon S3 URL таңдап, сілтемемізді енгіземіз. Содан соң Next батырмасын басамыз. Келесі қадамда Stack аты мен параметрлерді енгіземіз. Stack атауын еркін таңдай аласыз. Алайда тапсырма бойынша `Instance Type Parameter` мәні ретінде `t3.micro` таңдау қажет. Содан соң Next батырмасын басамыз. Үшінші парақшада барлық баптауларды әдепкі күйінде қалдырып, төменге дейін жылжып, Next батырмасын басамыз. Төртінші парақшада Review парақшасын көреміз. Мұнда біз енгізген барлық баптаулар көрсетіледі. Парақшаның соңына дейін жылжып, Submit батырмасын басу қажет. Біз Stack тізіміне бағытталамыз, Stack автоматты түрде таңдалады және Events қойындысында оның күйі Create in Progress екенін көреміз. Біраз уақыт күтейік, кейін парақшаны жаңартамыз. Көп ұзамай Stack сәтті құрылып, күйі Create Complete болып өзгереді. Енді қосымшамыздың дайын болуын күту қажет. Оны тексеру үшін EC2 сервисіне өтіп, инстанстар тізімін ашып, біздің EC2 инстансымыз барлық жүйелік тексеруден өткенін күтеміз. Сондай-ақ сіз қажетті аймақта екеніңізге көз жеткізіңіз, бізге керек аймақ — Oregon. Парақшаны жаңартайық, серверіміз толық дайын екенін көреміз, барлық жүйелік тексерулерден өтті. Енді stack парақшасына қайта ораламыз, Outputs қойындысын ашамыз, мұнда Output параметрі бар — бұл біздің EC2 инстансымыздың жалпыға ортақ IP-мекенжайы. Оны көшіруіміз керек, соңына /cafe қосып, қосымшамызды ашып көреміз. Егер тиісті парақша ашылса — құттықтаймын, біз барлық баптауларды дұрыс енгіздік, тапсырманы сәтті орындадық. Сондай-ақ сервер туралы метадеректер бар екенін ескеріңіз, IP-мекенжайды көреміз, аймақ — us-west-2, яғни Oregon аймағы, сондай-ақ Instance ID көрсетілген. Осылайша біз қолмен ештеңе істемей-ақ AWS CloudFormation templates көмегімен IT-инфрақұрылымымызды көршілес AWS аймағына толықтай көшіруді жүзеге асырдық. Осы жерден зертханалық жұмысымыз аяқталып, зертхананың қорытынды бөліміне көшеміз. Енді автобағалау скриптін іске қосып, барлық жүйелерден дұрыс шығып кетуіміз керек. Автобағалау скриптін іске қосу үшін зертханалық жұмыстың басты парақшасын ашыңыз. Мұнда бізге жоғарғы оң жақтағы Submit батырмасы қажет, оны басайық және бұл әрекетті растаңыз. Сәл күту қажет болады, скрипт жұмысын аяқтағаннан кейін оң жақ бөлікте бағаларыңызды көресіз. Егер бұл орындалмаса, 5 минуттан кейін жоғарғы оң жақтағы Grades батырмасын өзіңіз баса аласыз. Бұл жерде барлық бағаларыңыз көрсетіледі — қорытынды баға, тапсырмалар және тест сұрақтары бойынша баллдар бар. Егер қажетті балл жинай алмасаңыз және оны жақсартқыңыз келсе, кез келген тапсырмаға қайта оралып, түзетулер енгізіп, автобағалау скриптін қайтадан іске қоса аласыз — сол арқылы қалаған нәтижеге жетесіз. Мені бәрі қанағаттандырады, енді барлық жүйелерден шығуға болады, ең алдымен бұл AWS Management Console-ге қатысты — бір ғана қойындыны қалдырыңыз. Содан кейін жоғарғы оң жақта өз атыңызды басып, ашылған тізімнен Sign out батырмасын таңдаңыз. Зертханалық жұмыстың басты парақшасына қайта оралып, жоғарғы оң жақтағы End Lab батырмасын басыңыз және әрекетті растаңыз. Сізге зертханалық жұмыс қойындысын жабуға болатыны жайлы хабарламасы бар қалқымалы терезе пайда болады. Осылайша біз зертханалық жұмысты толық аяқтадық. Назарларыңызға рахмет, келесі белсенділіктерде кездескенше!
