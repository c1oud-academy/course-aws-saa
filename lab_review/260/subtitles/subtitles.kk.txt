Қайырлы күн, құрметті студенттер, зертханалық жұмысты талқылаудың кезекті сессиясына қош келдіңіздер. Бүгінгі зертханалық жұмыстың тақырыбы — AWS CloudFormation сервисін пайдалана отырып, инфрақұрылымды AWS бұлтында автоматты түрде орнату. Ендеше, бастайық. Біз бірінші тапсырмадан бастаймыз. Бұл тапсырма аясында Networking Layer-ді орнатамыз. Ол үшін алдымен бесінші қадамдағы сілтеме бойынша template-ті жергілікті компьютерге жүктеуіміз керек. Міне, сіз оның мазмұнын көріп отырсыз. Енді AWS Management Console ішіндегі AWS CloudFormation сервисіне өту қажет. Біз бірден stacks тізіміне бағытталамыз. Экранның жоғарғы оң жағынан Create Stack батырмасын басып, ашылған тізімнен бірінші опцияны таңдаймыз. Бізді жаңа stack құру парақшасына бағыттайды. Бізде template толығымен дайын екенін көрсетеміз. Оны жергілікті түрде жүктейміз де, Choose File батырмасын басамыз. Оны жасаған соң файлдар тізімі көрінеді. Біздің жағдайда бұл — lab-network.yaml. Сонымен қатар біз S3 URL жолын көреміз — бұл CloudFormation біздің template-ті жүктеген жол, ол оны жұмыс үшін қолданады. Енді Next батырмасын басу қажет. Екінші қадамда жаңа stack атауын енгіземіз, мысалы, lab-network. Бұл stack ішінде параметрлер жоқ, сондықтан ештеңе енгізу қажет емес, әрі қарай Next батырмасын басамыз. Үшінші парақшада тегті енгізу ұсынылады — Key ретінде application, Value ретінде inventory деп енгіземіз, парақша соңына дейін айналдырып, Next батырмасын басамыз. Төртінші парақша — Review парақшасы. Мұнда енгізілген барлық параметрлер көрсетіледі. Барлығы дұрыс болса, парақшаны соңына дейін айналдырып, Submit батырмасын басамыз. Біз stacks тізімі бар парақшаға қайта бағытталамыз. Біздің stack автоматты түрде таңдалады және экранның ортасында stack-ке байланысты бірнеше қойындылар көрінеді. Events қойындысын ашайық. Бірінші жазбаны көреміз — онда Logical ID ретінде lab-network көрсетілген және статус Create in Progress — stack құрылымы басталды деген сөз. Экранның жоғарғы оң жағында орналасқан Refresh батырмасын бассақ, оқиғалар саны көбейеді. Оқиғалар бір-бірімен байланысты. Әрбір ресурсқа кемінде екі жазба сәйкес келеді. Бірінші — Create in Progress, ал біраз уақыттан кейін сол ресурсқа арналған Create Complete статусымен жазба пайда болады. Мысалды қарасақ, PublicRoute атты ресурс құрылу үстінде, себебі оның статусы Create in Progress. Енді Resources қойындысына өтіп, тексеріп көрейік. Бізде барлығы 8 ресурс бар, олардың 7-і сәтті құрылды — оларда Create Complete статусы тұр, ал PublicRoute әлі құрылуда — Create in Progress. Біз осы қойындылар арасында еркін ауыса аламыз — бұл процессқа еш әсер етпейді. Outputs қойындысын ашайық. Қазіргі уақытта екі Output мәні көрсетілген — егер мән әлі дайын болмаса, ол көрінбейді; ал егер дайын болса, Output ішінде көрсетіледі. Біздің жағдайда бұл VPC ID және Public Subnet ID. Үшінші бағанға назар аударыңыз — Description, бұл Output параметрінің template ішінде жазылған мәтіндік сипаттамасы. Төртінші баған — Export Name. Бұл Output параметрінің бірегей атауы, басқа templates арқылы Subnet ID және VPC ID мәндерін алу үшін қолданылады. Келесі қойынды — Template. Мұнда біз бастапқы template мәтінін көреміз — бұл өте ыңғайлы. Оны көшіріп алуға болады, басқа template-пен салыстыру үшін, сәйкестік немесе айырмашылықтарды көру үшін қолдануға болады. Stack Info қойындысын ашайық — мұнда stack туралы негізгі ақпарат көрсетіледі. Overview секциясы жалпы мәліметтерді, Tags секциясы біздің stack-тің тегтерін көрсетеді. Бұл тегтер stack ішіндегі барлық ресурстарға да қолданылады. Events қойындысына оралып, сол жақтағы stacks тізімінде lab-network stack үшін күйі Create Complete екенін көреміз — яғни ол сәтті құрылды. Сол оқиғаны Events тізімінде де көреміз — соңғы оқиға: Logical ID — lab-network және статус — Create Complete. Біз екінші тапсырмаға жеттік — бұл тапсырмада Application Layer орнатамыз. Процесс дәл сондай, тек template басқаша болады. Template-ке сілтеме 15-қадамда көрсетілген — бұл lab-application.yaml. Бұл template-тің ерекшелігі — біз бұрынғы stack-тің Output параметрлерін осы template ішінде қолданамыз, бұл мәндер жаңа ресурстарды құруда пайдаланылады. Сілтемені бассақ, template мәтіні ашылады, оны жергілікті компьютерге сақтау керек, содан кейін AWS Management Console парақшасына оралу қажет. Мұнда CloudFormation сервисін ашып, экранның жоғарғы оң жағындағы Create Stack батырмасын басып, бірінші опцияны таңдаймыз. Stack құру парақшасына өтеміз — бұл бірінші тапсырмадағыдай. Template дайын екенін көрсетеміз. Содан кейін Upload Template File опциясын таңдап, Choose File батырмасын басу қажет. Екінші template-ті таңдаймыз да, Next батырмасын басамыз. Мұнда Stack name ретінде lab-application деп көрсету қажет. Назар аударыңыз, бізде екі параметр бар. Бірінші параметрде әдепкі мән бар, оны өзгертудің қажеті жоқ, ал екінші параметрге бірінші stack атауын енгізуіміз керек, сонда біз оның output параметрлеріне сілтеме жасай аламыз. Содан кейін Next батырмасын басамыз. Үшінші парақшада тегтерді енгізу қажет: Key ретінде Application, Value ретінде Inventory көрсетеміз де, экранның төменгі жағындағы Next батырмасын басамыз. Соңғы парақшада — Review парақшасы, біз енгізген барлық мәндер көрсетіледі. Парақшаның соңына дейін айналдырып, Submit батырмасын басу қажет. Біз stacks тізімі парақшасына бағытталамыз, lab-application автоматты түрде таңдалады, сондықтан экранның ортасында тиісті қойындылар көрсетіледі. Events қойындысын ашсақ, оқиғалар көрсетіледі. Кейін Resources қойындысын ашсақ, барлық ресурстар және олардың ағымдағы күйлері көрінеді. CloudFormation ресурстарды құра бастаған сайын, олар да осы қойындыда пайда болады, ал әзірше басталмаған ресурстар көрінбейді. Кішкене күтейік, lab-application сәтті құрылып болған соң, Outputs қойындысына өтеміз. Мұнда бір output параметрі пайда болады, бізді оның мәні қызықтырады, сол URL-адресті көшіріп, браузердің жаңа қойындысында ашайық. Егер сіз қажетті хабарламасы бар қолданбаны көрсеңіз, бұл — дайын templates арқылы ешқандай қолмен араласусыз IT-инфрақұрылымды және қосымшаны сәтті орнатқанымызды білдіреді. Құттықтаймын! Енді екінші template-ке назар аударғым келеді, атап айтқанда Resources бөліміне, ішінде Web Server Instance ресурсы — бұл біздің EC2 инстансымыз. Егер осы ресурсқа қарасақ, онда Properties секциясы бар, онда біз оның сипаттамаларын сипаттаймыз. Төменірек қарасақ, үш жол бөлінген — оларда біздің EC2 инстанс қай Subnet ішінде құрылатыны көрсетілген. Біз VPC мен Subnet сияқты желілік ресурстарды басқа stack ішінде құрғандықтан, қажетті мәнді осы жерге тартуға тырысамыз. Есіңізде болса, бірінші stack құрған кезде біз VPC ID және Subnet ID мәндерін output ретінде шығардық. Сонымен қатар, бұл мәндер үшін Export Name бағанында атау көрсетілген болатын. Енді біз осы Export Name мәнімен сәйкес келетін жол құрастырып жатырмыз, сонда бұл мән автоматты түрде осы template-ке тартылады. Import Value командасы қолданылады, үшінші жолда біз Network Stack Name параметрінің мәнін қолданамыз. Есіңізде болса, біз оған lab-network деп мән бердік, содан кейін оған -SubnetID деген мәтін қосылады және осы жолға сәйкес Export параметрі бар-жоғы тексеріледі. Бұл мән табылады, өйткені ол бізде бар және ол Subnet ID өрісінің мәні ретінде пайдаланылады. Енді алдыңғы stack ішіндегі output параметрлер тізімін ашайық және шынымен де Export Name мәні lab-network-SubnetID екенін және сәйкес Subnet ID мәнін көреміз. Біз үшінші тапсырмаға жеттік — бұл тапсырмада біз stack-ті жаңартамыз. Бұны бастамас бұрын, қазіргі ресурстардың күйін тексеруіміз қажет. Бізді Security Group қызықтырады, оған жету үшін EC2 сервисіне өту қажет. Бұны жасаған соң, инстанстар тізіміне өтіп, жалғыз EC2 инстансымызды таңдаймыз. Экранның төменгі бөлігінде ашылған қойындылардан Security қойындысын ашамыз, онда біз өзіміздің Security Group сілтемесін көреміз. Осы сілтемені басып, Security Group-тың басты парақшасын ашайық. Егер біз Inbound Rules қойындысын ашсақ, бір ғана ереже бар екенін көреміз — бұл 80-порт арқылы интернеттен трафикке рұқсат беретін ереже. Енді бізге 26-қадамнан жаңартылған template-ті ашып, жергілікті компьютерге сақтау қажет. Бұл парақшада біз бірінші template ішіндегі Security Group мәтінін және жаңартылған нұсқасын көреміз. Егер назар аударсаңыз, шағын төртбұрышпен бөлінген — бұл қосылған 4 жаңа жол. Жоғарырақ қарасақ, Security group ingress секциясы бар, онда осы Security Group-тың Inbound параметрлері сипатталған. Алғашқы 4 жол 80-порттағы трафикті сипаттайды, келесі 4 жол 22-порттағы трафикті сипаттайды және дәл осы 4 жол жаңадан қосылды. Енді stack-ті жаңартайық, ол үшін AWS CloudFormation сервисіне өтіп, stack тізімінен lab-application таңдаңыз. Одан кейін экранның жоғарғы оң жағындағы Update батырмасын басу керек, біз stack жаңарту парақшасына өтеміз. Мұнда бізде template жаңартылғанын көрсетуіміз керек, сондықтан Replace Current Template опциясын таңдаймыз. Сәл төменде Upload a Template File опциясын таңдап, Choose File батырмасы арқылы жергілікті компьютерден lab-application2.yaml файлын таңдап, экранның төменгі жағындағы Next батырмасын басамыз. Сол сәтте біз параметрлерді жаңарта алатын екінші парақшаға өтеміз. Мұнда ештеңені өзгертудің қажеті жоқ, сондықтан Next батырмасын басамыз. Үшінші парақшада да ештеңе өзгертпейміз, сондықтан соңына дейін айналдырып, Next батырмасын басып, соңғы парақшаға өтеміз. Бұл — Review парақшасы, соңына дейін айналдырсақ, жаңа секция пайда болғанын көреміз — Change Set Preview, себебі stack бұған дейін бар еді, ал біз оны жаңартып жатырмыз. Change Set құрамында барлық өзгерістер бар және егер көрсетілген өзгерістермен келіссек, Submit батырмасын басу керек. Біз бір ғана өзгерісті көріп тұрмыз — ол Security Group-қа қатысты және ол кішігірім өзгеріс, яғни тек осы ресурс қана жаңарады. Сонымен, Submit батырмасын басайық, біз stacks тізімі парақшасына өтеміз. lab-application автоматты түрде таңдалады және Events қойындысын ашсақ, тек 5 жаңа оқиғаны көреміз. Қарапайым түрде, төменнен жоғары қарай оқиғаларды қарап шығайық. Бірінші оқиға lab-application stack-інің Update in Progress күйіне өткенін көрсетеді — яғни жаңарту басталды. Келесі екі жол Web Server Security Group ресурсына қатысты: алдымен ол Update in Progress күйіне өтті, содан кейін Update Complete болды. Одан кейін бүкіл stack Update Complete Cleanup in Progress күйіне өтеді — бұл CloudFormation-ның барлық өзгерістерді тексеріп, қажетсіз нәрселерді тазалауын білдіреді. Тексеру аяқталған соң, stack Update Complete күйіне өтеді. Жақсы, енді Security Group парақшасына қайта оралайық, егер ол ашық болса — парақшаны жаңартыңыз. Inbound Rules қойындысын ашыңыз, екі ереже көрінуі тиіс. Біріншісі — жаңадан қосқан, алфавит бойынша сұрыпталған және ол SSH трафигін бұзатын. Екіншісі - Inbound Rule, бұрын болған ереже. Көріп отырғанымыздай, біз ешқандай қолмен өзгеріс енгізбедік, тек template-ті өзгерттік және бұл өзгерістерді stack арқылы енгіздік. Осылайша, жаңа өзгерістер template-те бар, олар template-те құжатталған, сонымен қатар біз осы template-пен барлық қажетті stack-терді жаңарта аламыз және қолмен әрекеттерді орындаудың қажеті жоқ. Біз төртінші тапсырмаға жеттік. Бұл тапсырма бағаланбайды, бірақ біз функционалды танып білеміз. Бізді қызықтыратыны — AWS CloudFormation Designer, ол бізге templates-ті графикалық түрде көруге, өзгертуге және құруға мүмкіндік береді. Designer-ге өту үшін алдымен AWS CloudFormation сервисіне кіріп, сол жақтағы навигация мәзірінен Designer пунктін таңдау керек. Жаңа парақша ашылады, Designer интерфейсі мынадай көрініске ие болады. Жоғарғы бөлікте диаграмма, сол жағында ресурстар тізімі, ал төменгі бөлігінде біздің template көрсетіледі. Енді template-імізді қосып көрейік. Ол үшін сол жақ жоғарғы бұрыштағы файл белгішесін басып, ашылған мәзірден Open-ді таңдаңыз. Ашылған терезеде Local file таңдап, жергілікті компьютерден файлды таңдау қажет болады. Бізді қызықтыратын файл — lab-application2.yaml. Оны таңдап, Open батырмасын басыңыз. Сол сәтте біз экранның төменгі бөлігінде template-імізді көреміз, сонымен қатар оның графикалық көрінісі де көрсетіледі. Бізде үш ресурс бар: security group, EC2 инстанс және оған байланған EBS Volume. Назар аударыңыз, Designer арқылы template форматын YAML мен JSON арасында ауыстыруға болады. Енді екінші template-ті ашайық, ол — lab-network.yaml және оның қалай көрінетінін көрейік. Онда VPC, subnet, Internet Gateway және басқа желілік ресурстар бар. Designer ішіндегі template-ті тереңірек зерттеуді сіздің еркіңізге қалдырамын, ал біз келесі тапсырмаға өтеміз. Біз бесінші және соңғы тапсырмаға жеттік, мұнда stack-тердің бірін жоямыз. Бұған дейін AWS CloudFormation Designer-ден шығу қажет, бұл әрдайым айқын емес. Экранның жоғарғы сол жағындағы Close батырмасын басыңыз. Оны басқан соң, stacks тізімі парақшасына өтеміз. Мұнда lab-application таңдап, жоғарғы оң жақтағы Delete батырмасын басып, бұл әрекетті растау қажет. Біз бірден Events қойындысына өтеміз, мұнда lab-application stack-інің Delete in Progress күйіне өткені туралы алғашқы оқиға көрсетіледі. Сол жақ жоғарғы бөлігінде көк фонда stack жою басталғаны туралы хабарлама көрінеді. Енді Resources қойындысына ауысайық та, ресурстардың қандай күйде екенін көрейік. Соңғы екі ресурсқа назар аударыңыз — Security Group және Instance. Instance өзгертілмегендіктен, күйі Create Complete. Security Group жаңартылғандықтан, оның күйі Update Complete. Егер біз ең бірінші DiskMountPoint-ты қарасақ, ол жойылып қойылған, сондықтан күйі Delete Complete. Ал DiskVolume жою процесінде. Біраз уақыт күтейік және парақшаны жаңартайық, барлық ресурстар жойылғанын және олардың күйі Delete Complete екенін көреміз. Енді Events қойындысына ауысайық және қандай оқиғалар тіркелгенін көрейік. Біз төменнен жоғары қарай оқимыз, яғни оқиғалардың пайда болу ретін сақтай отырып. Ең төменгі жол — бұл stack Delete in Progress күйіне өткені. Сонымен қатар Status Reason ретінде User Initiated көрсетілген, яғни жоюды бастағанымыз көрсетіледі. Одан кейін CloudFormation барлық ресурстарды жоя бастайды. DiskMountPoint үшін екі оқиға тіркелген: алдымен ол Delete in Progress күйіне өтті, содан кейін Delete Complete, яғни жойылды. DiskVolume үшін үш оқиға бар: алдымен Delete in Progress, екіншісі - түсініктемемен. Кейін сәтті түрде Snapshot жасалды және ID көрсетілді. Содан кейін бұл ресурс Delete Complete күйіне өтіп, жойылды. Қалған екі ресурс — WebServer Security Group және WebServer Instance. Екеуі де жойылды, әрқайсысы үшін екі оқиға тіркелген. Жоғарғы жол — соңғы оқиға. lab-application stack толықтай Delete Complete күйіне өткенін көрсетеді, яғни толықтай жойылды. Енді template-імізді толығырақ қарайық, бізді қызықтыратын ресурс — EC2 Volume. Мәтінінен Type секциясын көреміз — бұл ресурс типі. Келесі — Properties секциясы, онда қасиеттер сипатталған. Үшінші — Deletion Policy, оның мәні — Snapshot. Бұл барлық ресурстарға жарамайды, бірақ EC2 Volume үшін қолданылады. Сондықтан CloudFormation бұл ресурсты жоймас бұрын, алдымен Snapshot жасап, оны S3-ке сақтап, кейін EBS Volume-ді жойған. Мұны тексеріп көрейік, EC2 сервисіне өтуіміз керек. Сол жақ мәзірдегі Snapshots бөліміне өтіп, біз бір ғана Snapshot-ты көреміз. Оны таңдайық, тегтер тізімінен бұл Snapshot lab-application stack-іне тиесілі екенін, тегтер ішінде Application=Inventory барын көреміз және басқа да мәліметтер көрсетіледі. Енді Instances тізімін ашайық, бір ғана инстансты көреміз, бірақ оның күйі — Terminated, яғни жақында жойылған, сондықтан ол көрсетіліп тұр, бірақ сервер ретінде ол енді жоқ. Жақсы, осылайша біз stack-ті жойдық және ресурстарға Deletion Policy қолданылғанда не болатынын көрдік. Енді біз барлық тапсырмаларды орындадық. Автобағалау скриптін іске қосу қажет. Ол үшін зертханалық жұмыстың басты парақшасына қайтамыз. Submit батырмасын басып, әрекетті растаймыз және біраз күтеміз. Біраз уақыттан соң, оң жақта біз жинаған ұпайлар көрінеді. Бағаланатын 4 тапсырмадан біз әрқайсысы үшін 5 ұпай алдық, яғни барлығы 20 ұпай және бұл тапсырмалардың дұрыс орындалғанын білдіреді. Енді барлық жүйелерден дұрыс шығу қажет, бірінші кезекте AWS Management Console. Тек соңғы қойындыны қалдырып, жоғарғы оң жақтан пайдаланушы атын басып, ашылған мәзірден Sign out батырмасын басыңыз. Енді зертханалық жұмыстың басты парақшасына қайтып, End Lab батырмасын басып, әрекетті растау керек. Қалқымалы терезеде зертханалық жұмыстың қойындысын жабуға болатыны туралы хабарлама көрсетіледі. Осымен зертханалық жұмысты талдау сессиясын аяқтаймыз. Назар аударғандарыңызға рахмет, келесі белсенділіктерде көріскенше!
