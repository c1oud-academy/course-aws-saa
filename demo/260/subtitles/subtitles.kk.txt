Қайырлы күн, құрметті студенттер, сіздерді демо-сессияда көргеніме қуаныштымын. Бүгінгі демо тақырыбы — AWS CloudFormation template құрылымын талдау. Ендеше, бастайық. Бірінші қадам — CloudFormation template табуымыз керек. Мұны істеу үшін AWS Quick Starts сервисін пайдалануға кеңес беремін. Оны Google арқылы оңай табуға болады, жай ғана AWS Quick Starts деп терсеңіз жеткілікті, бірінші сілтеме — бізге қажет сілтеме. Міне, AWS Quick Starts басты парақшасы осындай. Бұл сервис толықтай тегін және онда AWS IT-архитекторлар командасы құрған бірнеше жүздеген ұсынылатын AWS CloudFormation templates бар. Олардың барлығы best practice бойынша жасалған және дәл осы templates негізінде үйрену керек, өз templates-іңізді AWS Quick Starts-тегі templates сияқты етуге ұмтылған дұрыс. Сәл төмен қарай жылжытсаңыз, барлық CloudFormation templates тізімін көресіз. Жазылып жатқан сәтте барлығы 499 templates бар. Бұл өте үлкен сан, сондықтан кілт сөздер арқылы іздеуді немесе экранның сол жағындағы фильтрді пайдаланған жөн. Ендеше, VPC бойынша фильтр жасап көрейік. 11 template шығады. Бізге AWS-тің өзі жасаған templates қажет. Олар — Amazon Virtual Private Cloud және Linux Bastion Hosts. Бұлар — осы тізімдегі ең қарапайым templates. Бастапқы жұмыс пен үйрену үшін өте жақсы мысал болып табылады. Мысал ретінде алғашқы template-ті таңдайық. Бұл — Amazon Virtual Private Cloud on AWS. Сізді осы парақшаға бағыттайды. Мұнда екі сілтеме болады. Біріншісі — View Deployment Guide. Сізді осы template-ке арналған жеке мини-сайтқа жібереді. Мұнда түрлі аспектілер қарастырылады: осы template арқылы жасалатын ресурстардың құны, архитектурасы, deployment және post-deployment мәселелері, troubleshooting және т.б. Екінші батырма — AWS Management Console ішіндегі жаңа stack жасау парақшасына апарады. Сонымен қатар бұл template автоматты түрде байланыстырылып тұрады. Бұл — егер сіз еш өзгеріссіз бұл template-ті deploy еткіңіз келсе арналған. Сәл төмен қарай жылжытсаңыз, бірнеше қойындыны көресіз. Бұл — не deploy жасайтынымыз туралы қысқаша мәлімет, әрі қарай — қалай deploy жасалатыны жайлы. Үшінші қойынды — осы template арқылы жасалатын ресурстардың бағасы жайлы ақпарат. Бұл және басқа да парақшаларды тереңірек зерттеу — өз еркіңізде. Енді демо-сессияның екінші бөліміне өттік және AWS CloudFormation template ішіндегі секцияларды қарап шығамыз, кейін қарапайым бір template алып, талдаймыз. Кез келген AWS CloudFormation template 10 түрлі секциядан тұруы мүмкін. Әрбір секция template-тің белгілі бір аспектісін сипаттайды. Ендеше, әрқайсысына қысқаша шолу жасап өтейік. Ең бірінші секция — бұл AWS Template Format Version. Онда жалғыз ғана мән болады — 2010 жылдың 9 қыркүйегі, бұл датаны есте сақтаудың қажеті жоқ. Бұл қазіргі уақытта AWS CloudFormation үшін тек бір ғана template нұсқасы бар екенін білдіреді. Бұл секция міндетті емес және қажет болмаған жағдайда өткізіп жіберуге болады. Келесі секция — Description, бұл да міндетті емес, бірақ толтырсаңыз, еркін форматта мәтін жаза аласыз. Көбіне бұл секция template не үшін жасалып жатқанын және оның мақсаттарын сипаттау үшін қолданылады. Келесі секция — Metadata, бұл да міндетті емес. Біз бұл секцияны тек шаблон параметрлері парақшасын кастомизациялау қажет болғанда толтырамыз, яғни stack жасау кезінде AWS Management Console арқылы. Есіңізде болса, AWS Management Console арқылы stack жасаған кезде бөлек парақша ашылады, онда stack атауын жазамыз және сәл төменде параметрлер тізімі бар. Егер Metadata секциясы көрсетілмесе, параметрлер әліпби тәртібімен көрсетіледі. Ал егер оларды топтастырғыңыз келсе немесе ретімен өзгеріс енгізгіңіз келсе, онда Metadata секциясын толтыруыңыз қажет. Келесі секция — Parameters. Бұл жерде біз кіріс параметрлерінің тізімін көрсетеміз. Бұл секция міндетті емес, егер сізде кіріс параметрлері болмаса, оны template-ке енгізбеуге болады. Келесі — Rules секциясы. Бұл параметрлердің дұрыстығын тексеруге арналған қосымша валидация ережелерін жазуға мүмкіндік береді. Бұл сирек қолданылады, бірақ жалпы түсінік үшін мұндай секция бар екенін және ол міндетті емес екенін білгеніңіз жөн. Келесі міндетті емес секция — Mappings, яғни анықтамалар. Бұл секцияда бір-біріне тәуелсіз анықтамалар жазылады. Әрқайсысында кілт-мағына (key-value) жұптары болады және template-тің басқа бөліктерінде mapping-ке жүгінгенде, анықтаманың атауын және кілтті көрсетеміз, жауап ретінде мәнін аламыз. Келесі міндетті емес секция — Conditions. Мұнда біз өз шарттарымызды көрсетеміз. Шарттар белгілі бір ресурстарды жасау үшін қолданылады, сондай-ақ осы шарттарға байланысты ресурстардың сипаттарын өзгертуге болады. Мысал ретінде: егер Environment параметрі Prod-қа тең немесе Prod деген сөзді қамтыса, онда EC2 инстанс үшін жасалатын дискінің өлшемі 30 ГБ болады. Егер шарт жалған болса, яғни бұл Prod емес, онда диск өлшемі 10 ГБ болады. Келесі міндетті емес секция — Transform. Бұл да сирек қолданылады, көбіне AWS SAM-ды қосу үшін қолданылады. SAM — CloudFormation көмегімен serverless қосымшаларды жасауға арналған арнайы шешім. Келесі секция — Resources. Бұл — бүкіл AWS CloudFormation template ішіндегі жалғыз міндетті секция және ол кем дегенде бір ресурсты қамтуы тиіс. Келесі және соңғы міндетті емес секция — Outputs. Outputs екі жағдайда толтырылады. Бірінші — кейбір деректерді алу ыңғайлылығы үшін, мысалы, VPC ID, subnet ID немесе EC2 инстанс-тың жалпыға ортақ IP-мекенжайын көрсетеміз, егер бізге бұл мәндер керек болса. Бұл мәндердің барлығы бір жерде жиналғандықтан, бізге AWS Management Console ішінде түрлі сервистерге барып, ресурстарды іздеп, қажетті қойындыны ашып отырудың қажеті жоқ. Сондықтан бұл ең алдымен ыңғайлы. Екінші қолданыс — бұл stack құру кезінде генерацияланған мәндерді экспорттау. Бұл экспортталған мәндерді басқа template-тер импорттай алады. Енді біз template мысалына келдік, ол өте қарапайым. Біз мұнда 6 секцияны көреміз: AWS Template Format Version, Description, Parameters, Mappings, Resources және Outputs. Енді осы секциялардың әрқайсысын толығырақ қарастырайық. Бірінші бізді қызықтыратын секция — Parameters. Барлығы 3 параметр бар, әрқайсысын егжей-тегжейлі қарастырайық. Бірінші параметр — KeyName, мұнда 3 қасиет сипатталған: Description, Type және Constraint Description. Description және Constraint Description мәндері stack жасау кезінде параметрлер парақшасында көрсетіледі. Type үшін көрсетілген мән — KeyPair, яғни AWS аккаунтында жасалған KeyPair атауын енгізуіміз керек. Егер жоқ KeyName енгізілсе — қате шығады. Екінші параметр — InstanceType, оның қасиеттеріне назар аударайық. Description және Constraint Description — алдыңғы параметр сияқты жұмыс істейді. Type — жолдық мән (string), ал Default ретінде t2.small көрсетілген — бұл EC2 инстанс-тың типі. Сондай-ақ, AllowedValues қасиетінде EC2 инстанс-тың 5 түрлі типі көрсетілген. Олардың барлығы валидті және бізде AllowedValues қасиеті болғандықтан, біз тек осы тізімнен бір мәнді таңдай аламыз, ал басқа мәнді енгізу мүмкін емес. Енді үшінші параметрге — SSHLocation назар аударайық. Мұнда да Description, Constraint Description, Type бар — бұл жолдық мән. Енді жаңа қасиеттерді қарастырайық. MinLength және MaxLength бар, бұл — жолдың ең аз және ең көп ұзындығы. Default ретінде интернет CIDR блогы көрсетілген, барлық мәндер — нөлдер. Сонымен қатар жаңа қасиет — AllowedPattern бар. Мұнда тұрақты мән берілген, егер енгізілген мән осы тұрақты мәнмен сәйкес келмесе, қате пайда болады. Бұл параметр үшін AllowedValues жоқ, сондықтан кез келген мәнді енгізуге болады, бастысы — ол шаблонға сәйкес болуы тиіс. Жақсы, енді келесі секцияны қарайық — бұл Mappings секциясы. Бұл template аясында бізде үш анықтама бар, біз оларды толық талдамаймыз, тек мысал келтірейік. Мысалы, біз бірінші анықтамаға t2.nano мәнімен жүгінеміз, сосын Arch өрісін сұраймыз — нәтижесінде HVM64 мәнін аламыз. Немесе басқа мысал: үшінші анықтамаға жүгінеміз — AWSRegionArch2AMI, яғни бізге AMI аймақ пен архитектураға байланысты керек. Кіріс ретінде us-east-1 мәнін береміз — бұл бірінші жол, содан кейін архитектураны — мысалы, HVMG2 — бұл екінші мән, осы екі мәннің комбинациясы нәтижесінде біз AMI ID аламыз. Енді қандай ресурстар бар екенін қарастырайық. Еске салайын — бұл жалғыз міндетті секция, кемінде бір ресурс болуы тиіс. Бұл template ішінде екі ресурс бар: біріншісі — EC2 Instance, екіншісі — SecurityGroup. Инстансқа толығырақ тоқталайық. Бірінші қасиет — Type, ол ресурстың түрін белгілі бір форматта сипаттайды: AWS, қос нүкте, сервис атауы — біздің жағдайда EC2, тағы қос нүкте және ресурс атауы — Instance. Содан кейін Properties кілтімен блок келеді — мұнда біз инстанс типін көрсетеміз, ол параметрден алынады. Параметр де Instance type деп аталады, содан кейін SecurityGroup, KeyName және ImageID көрсетіледі, ImageID Mapping арқылы алынады. AMI мәнін алу үшін алдымен Instance type параметрінен архитектураны AWSInstanceType2Arch анықтамасынан аламыз. Содан кейін алынған мән мен аймақты бірге үшінші анықтамаға — AWSRegionArch2AMI — береміз, нәтижесінде AMI ID мәнін ImageID үшін аламыз. Енді екінші ресурсқа — SecurityGroup-қа назар аударайық, Type кілті бойынша мән көрсетілген. Содан кейін Properties кілтімен SecurityGroup қасиеттері беріледі. Алдымен GroupDescription көрсетіледі — мұнда SSH арқылы 22-портқа қолжетімділік қосылғаны жазылған. Содан кейін SecurityGroupIngress кілті бар — бұл массив, әр элементі 4 кілт-мағына жұбынан тұрады: IpProtocol (tcp). Келесі FromPort көрсетеміз, ToPort - 22 және соңғысы — CidrIp, ол SSHLocation параметрінен алынады. Template ішіндегі ең соңғы секция — Outputs, бұл template ішінде 4 outputs бар. Біріншісі — InstanceId, екі қасиетпен сипатталған: Description және Value. Description — еркін мәтін, Outputs қойындысында көрсетіледі, ал Value ретінде EC2 instance ID беріледі. Қалған 3 output техникалық жағынан бірдей, екіншісін қарастырайық. Екіншісі — AZ деп аталады, Description еркін мәтін. Value мәніне назар аударайық. Value мәні — EC2 instance-тің AvailabilityZone қасиеті. Кез келген ресурс түрлі қасиеттерге ие. EC2 instance үшін кемінде үш қасиет бар: AvailabilityZone, PublicDnsName және PublicIp. Бұл мәндердің барлығы жеке-жеке алынып, outputs ретінде беріледі. Осылайша біз бүгінгі демоның соңына жеттік, AWS CloudFormation template ішінде қандай секциялар бар екенін қарадық және қарапайым template мысалын талдадық. Назарларыңызға рахмет, келесі белсенділіктерде көріскенше!
