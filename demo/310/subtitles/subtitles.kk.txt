Қайырлы күн, құрметті студенттер, кезекті демо сессияда сіздерді көргеніме қуаныштымын. Бүгінгі демоның тақырыбы — лямбда-функция құру. Онда, бастайық. Біз AWS Management Console негізгі парақшасынан бастаймыз. Мұнда сервис іздеу жолағын пайдаланып, lambda деп енгізу қажет. Бірінші сілтеме — бізге керек сілтеме. Lambda сервисіне өткен соң, барлық функциялар тізімі бар парақша ашылады. Мұнда бізді қызықтыратын — экранның жоғарғы оң жағындағы Create Function батырмасы. Сол батырманы басайық. Бізді жаңа функция құру парақшасына бағыттайды. Бірінші кезекте, функцияны нөлден бастап жасаймыз ба, әлде дайын blueprint пайдаланамыз ба — соны таңдау қажет. Зертханалық жұмыс аясында біз дайын blueprint пайдаланамыз, бірақ нақты мақсаттар үшін лямбда-функция жасағанда, сіз оны AWS Management Console арқылы нөлден бастайтын боласыз. Немесе дайын кодты қолдана отырып, CloudFormation немесе CodePipeline арқылы орнату жасайсыз. Сонымен, біз Use a Blueprint опциясын таңдаймыз. Келесі қадамда Blueprint name ретінде Hello World енгіземіз, және программалау тілі Python болғанына көз жеткізіңіз. Бұл аса маңызды емес, әдетте студенттердің көбі Python біледі, сондықтан осы демоны Python тілі арқылы қарастырамыз. Функция атауы ретінде кез келген атты енгізуге болады, мен my-hello-world-lambda деп атаймын, әрі қарай Runtime ретінде Python таңдаған жөн. Төменірек бізге жаңа рөлді автоматты түрде жасау немесе бар рөлді пайдалану ұсынылады. Осы зертханалық жұмыс аясында біз жаңа рөл жасаймыз. Болашақта нақты жобамен жұмыс істегенде, сіз арнайы рөл жасауыңыз мүмкін. Мүмкін бұл рөл бірнеше лямбдамен қолданылуы мүмкін және сол кезде сіз нақты Lambda рөлін көрсетесіз, құру әдісіне қарамастан. Біздің жағдайда біз базалық қолжетімділіктері бар жаңа рөл құрамыз. Парақшаны соңына дейін айналдырайық, мұнда біз лямбда-функция кодын көреміз, оны өзгерте алмаймыз, енді Create Function батырмасын басу қажет. Бізді лямбда-функция парақшасына бағыттайды, жасыл фонда лямбда-функция сәтті жасалғаны туралы хабарлама көреміз, енді осы парақшамен толығырақ танысайық. Жоғарғы сол жақта лямбда-функцияның атауы көрсетілген, бірінші секция - бұл Function Overview. Мұнда триггерлер тізімін көреміз (бар болса), қосылған layers (қабаттар), егер олар байланысты болса. Сонымен қатар Destination өрісін көреміз — егер лямбда-функция басқа сервиске немесе ресурсқа дерек жіберетін болса. Мен Last Modified өрісін ерекшелеп көрсеттім, бұл жиі қолданылады, себебі біз лямбдамен жұмыс істейміз, оны өзгертеміз және орнатамыз — осы өріс жаңарту сәтті болды ма, соны көрсетеді. Сәл төмен түсейік, келесі секцияда бірнеше қойынды бар, біз олардың негізгісіне тоқталамыз. Бірінші қойынды - бұл Code, мұнда лямбда-функция кодын көреміз. Енді, лямбдамыз не істейтінін қарастырайық: JSON импортталады, кейін мәтіндік хабарламалар шығарылады және Lambda handler функциясы басталады. Lambda handler — бұл лямбда-функциядағы кіріс нүкте, ол екі айнымалы қабылдайды: біріншісі - Event, екіншісі - Context. Event ішінде — кіріс хабарлама. Біз оны кейінірек тест ретінде өзіміз құрып, осы тест хабарламаны лямбда-функцияны іске қосу үшін қолданамыз. Лямбда коды бойынша біз event ішінен key1, key2 және key3 кілттерін алуға тырысамыз және оларды экранға шығарамыз. Содан кейін лямбда нәтижесі — key1 кілтінің мәні болады. Жоғарғы бөлігінде екі батырма бар: Test және Deploy. Біз AWS Management Console ішінде кодқа өзгерістер енгізіп, оларды сақтап, кейін Deploy жасай аламыз. Сіз лямбда-функция кодын жаңартқаннан кейін, келесі іске қосуларда осы жаңартылған код қолданылады. Біз лямбданы тестілеу немесе ақауларды табу мақсатында өзіміз іске қоса аламыз. Ол үшін арнайы Test батырмасы бар. Енді екінші қойындыны қарастырайық — бұл Test. Мұнда біз лямбда іске қосу үшін тесттік events жасай аламыз. Бірінші event жасайық: Action ретінде Create New Event таңдаймыз, Event name ретінде Event1 көрсетеміз және шаблон ретінде Hello World қолданамыз. JSON-ды өзгертудің қажеті жоқ, бірақ қажет болған жағдайда өзгертуге болады, ағымдағы JSON лямбданы тестілеуге жеткілікті, сондықтан экранның жоғарғы оң жағындағы Save батырмасын басайық. Осы жерден-ақ біз лямбда-функцияны іске қоса аламыз, бірақ оны бірінші қойынды — Code арқылы да іске қосуға болады. Code қойындысына өтейік, егер есіңізде болса, мұнда да Test батырмасы бар, жанында үшбұрыш белгісі бар. Оны бассаңыз, бар event-тердің тізімі көрсетіледі. Осы жерден қай event-ті іске қосуды ыңғайлы түрде таңдай аласыз. Event1 таңдайық, ол автоматты түрде таңдалады, содан кейін Test батырмасын басамыз. Оны басқан сәтте Execution Results атты жаңа қойынды ашылады. Мұнда біз қандай event іске қосылғанын, лямбда-функция нәтижесін көреміз, біз Key1 кілтінің мәнін қайтардық — ол Value1. Сондай-ақ біз Function Logs көреміз, бұл — экранға шығарылған барлық хабарламалар. Назар аударыңыз, біз Value1, Value2, Value3 мәндерін шығардық және осы сәтте лямбда-функция аяқталды. Лямбда-функцияның басталуы — START мәтінімен басталады, әрі қарай Request ID көрсетіледі. Лямбда-функцияның соңғы хабарламалары: End — соңғы, Log — алдындағы және Report — ең соңғы лог, онда да сол Request ID болады. Мұнда біз лямбданың қанша уақыт жұмыс істегенін, қанша уақыты үшін төлем жасалатынын, қанша жедел жады бөлінгенін және нақты қаншасы пайдаланылғанын көре аламыз. Егер бұл суық іске қосу болса, яғни лямбда бірінші рет контейнерде іске қосылса, онда Init Duration көрсетіледі, бұл жағдайда 100 миллисекундтан сәл артық. Егер лямбда-функцияны тағы іске қосатын болсақ, Init Duration мәні 0 миллисекунд немесе мүлде көрсетілмейді. Бұл — функция ыстық контейнерде іске қосылды деген сөз, және қосымша инициализация уақыты қажет емес. Енді Monitor қойындысын толығырақ қарастырайық, бұл үшінші қойынды. Экранның жоғарғы оң жағында View CloudWatch Logs батырмасы бар — бізге керегі сол. Осы батырма арқылы біз лямбда-функция логтарына оңай әрі тез өте аламыз. Осы қойындының төменгі бөлігінде біздің метрикаларымыз көрсетіледі. Біз кез келген уақыт аралығын таңдай аламыз — 1 сағаттан бастап әрі қарай. Метрикаларды жаңарту үшін арнайы батырма бар. Метрика бойынша ең жиі қолданылатын — уақыт бойынша лямбда-функцияның қанша рет іске қосылғаны. Сондай-ақ, лямбда-функцияның қаншалықты жылдам жұмыс істейтінін, және үшінші графикте — әрқашан сәтті орындалып жатыр ма, әлде кейде қате шығып жатыр ма — соны көрсететін метрика бар. Төменірек басқа да метрикалар бар, олар сирек пайдаланылады, бірақ олармен өзіңіз таныса аласыз. Енді Configuration — төртінші қойындыны ашайық. Бұл қойындыда көптеген ішкі қойындылар бар, біз негізгілеріне тоқталамыз. Бірінші маңызды ішкі қойынды — General Configuration. Мұнда біз лямбда-функция үшін қанша жедел жады бөлінгенін көреміз. Біздің жағдайда — 128 мегабайт, бұл минималды мән. Лямбда-функцияның ең ұзақ жұмыс істеу уақыты — 3 секунд, оны Timeout өрісінен көруге болады. Келесі ішкі қойынды — Triggers. Мұнда лямбда-функцияға тіркелген барлық триггерлер көрсетіледі, қосымша мәліметтерімен бірге. Содан кейін Permission қойындысы бар, мұнда IAM рөлі атауы мен сілтемесі көрсетілген, осы рөлге лямбда-функция байланысқан. Төменірек біз лямбда-функция не істей алады, не істей алмайды — соны IAM рөлге өтпей-ақ көре аламыз. Соңғы ішкі қойынды, бүгін қарастырғымыз келетін — Environment Variables. Environment Variables — бұл орта айнымалылары. Қарапайым тілмен айтқанда, бұл — кілт-мән жұптарының тізімі, олар лямбда-функцияның жұмысын басқаруға көмектеседі. Егер сіз код жазу кезінде орта айнымалыларын пайдалансаңыз — бұл жақсы практика саналады. Осылайша, бүгінгі демо соңына келіп жеттік. Назарларыңызға рахмет, келесі белсенділіктерде кездескенше!
