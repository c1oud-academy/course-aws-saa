Сонымен, бастайық. Біз Демоны AWS Management Console басты парақшасынан бастаймыз. Негізгі тапсырма - EC2 Instance арқылы басқа AWS сервистеріне қолжеткізуді баптау. Мұны орындау үшін біз кейбір дайындық жұмыстарын орындауымыз керек, атап айтқанда, S3 жағында кем дегенде бір бакет жасаймыз. Ол үшін S3 сервисіне барамыз. Менің жағдайымда 10 бакет бар. Біреуін еске түсірейік. Біріншісі - c1oud-academy-aws-test-temp-data-bucket. Енді EC2 сервисіне өтіп, жаңа инстанс жасауымыз керек. Параметрлердің көпшілігін әдепкідей қалдырамыз. Name ретінде c1oud-academy-demo-ec2-instance-profile көрсетеміз. Әрі қарай, SSH арқылы қосылу үшін қажетті кілтті таңдаймыз. Бұл - алдыңғы демода орнатқан кілт. Тағы бір маңызды мәселе, желі параметрлерінде Public Subnet бар VPC таңдау керек. Сондай-ақ, Auto-Assign Public IP үшін Enable опциясын орнату керек. Security group параметрлерінде сәл төменірек, кез келген IP мекенжайынан осы EC2 инстансына SSH арқылы қосылу үшін rule қосуымыз керек. Сақтау параметрлерін осылай қалдырамыз. Advanced details бізді қызықтырмайды. Онда бәрі әдепкі бойынша қалады. Экранның төменгі оң жақ бөлігіндегі Launch instance батырмасын басамыз. EC2 инстанстар тізіміне өтуге болатын парақшаға қайта бағытталамыз. Және ол біздің жаңа EC2 инстансының идентификаторымен бірден фильтрленеді. EC2 Instance жасалғанын көреміз және ол тексеру сессиясынан өтіп, Instance State Running болғаннан кейін жалпы IP мекенжайын көшіріп, оған қосылып көреміз. EC2 инстансына PuTTY қосымшасы арқылы қосыламыз. Менде бұрын пайдаланылған және жеке кілтпен бапталынған сақталған сессия бар. Маған тек осы сессияны жүктеп, жаңа EC2 инстансының IP мекенжайын енгізу керек. Open батырмасын басқаннан кейін Terminal терезесі ашылады. Мұнда алдымен менің пайдаланушы атымды енгізу сұралады. Бұл Amazon Linux үшін стандартты және бізге ec2-user енгізу керек. Enter пернесін басқаннан кейін сіз терминал терезесіне түсесіз, енді қажетті командаларды енгізуге болады. Демо аясында ең қарапайым және ең танымал команда - S3 бакеттерінің тізімін көрсету болып табылады. Сондықтан aws s3 ls пәрменін тереміз және бакеттердің ешқайсысы көрсетілмейтінін көреміз және олар табылмағандықтан credentials орнатуды сұрайды. Мұны істеу үшін сізден AWS Configure пәрменін пайдалану сұралады. AWS Configure-ні EC2 инстансында конфигурациялауға рұқсат етілмегенін есте сақтау үшін мен тыйым салынған белгішені арнайы қостым, себебі AWS Configure осы инстанстан AWS аккаунтына тұрақты қатынасты орнатады. Бұл пәрмен интерфейсі арқылы әзірлеушінің компьютерінде немесе AWS пайдаланушыларында ғана жасалады. Сондықтан, біздің жағдайда EC2 инстансын пайдаланушылар емес, қолданба пайдаланады, сондықтан бұл нұсқа жарамайды. Неліктен бұл нұсқа қолайлы емес екенін түсіндірейін. Шабуыл жасаушылар EC2 инстансына қосылып, AWS кілттерін алды деп елестетіп көрейік. Олар сонда тұрақты сақталады, ол стандартты орынды біледі, оны көшіреді және кетеді. Осыдан кейін ол осы credentials пайдаланып, өз компьютерінен, кез келген басқа компьютерден біздің AWS аккаунтымызға қосыла алады. Және ол жасай алатын барлық нәрсе осы credentials астында отырған рөлге байланысты. Егер біз осылайша root аккаунтының деректерін жоғалтсақ, бұл апат. Егер бұл тек оқуға арналған әрекеттерді жасайтын азды-көпті қарапайым рөл болса, бұл соншалықты қорқынышты емес, бірақ ақпарат сыртқа кетуі мүмкін, өйткені шабуылдаушы бізде қандай ресурстар бар екенін көру мүмкіндігіне ие болады. Бұл да құпия ақпарат, сондықтан оны кез келген жағдайда болдырмау керек. Шешім бар, ол бұрыннан бар, ол EC2 Instance Profile деп аталады. Идея мынада: EC2 инстансын жасаған кезде біз оған ерекше рөл тағайындаймыз. Ал EC2 инстансы осы рөлдегі барлық рұқсаттарды алады. Ол басқа AWS сервистерін пайдалана алады, бірақ EC2 инстансы жағында credentials жасалмайды. Бұл AWS жағында жергілікті түрде жасалады және өте қауіпсіз. Осылайша, рөл EC2 инстансымен тығыз байланысты және EC2 инстансының өзінде credentials жоқ және ешкім, тіпті олар біздің EC2 инстансымызға қосылса да, бұл credentials-тарды өзімен бірге ала алмайды. EC2 Instance Profile функциясын пайдалану үшін алдымен рөл жасау керек. Сондықтан IAM сервисіне өтіп, осы жерде жаңа рөл жасаймыз. Рөлді AWS сервисі, атап айтқанда EC2 сервисі пайдаланатынын көрсетеміз. Экранның төменгі оң жақ бөлігінде Next батырмасын басыңыз, сонда осы рөлге қандай policy байланыстыратынымызды баптаймыз. Бізге S3 кілт сөзі бойынша фильтрлеу керек және біз AWS Managed Policy AmazonS3ReadOnlyAccess таба аламыз. Бұл біздің демомыз үшін жеткілікті. Оны таңдап, мазмұнын қарастырайық. Біз барлық S3 ресурстарына қол жеткізе алатынымызды көреміз. Және List сөзінен басталатын барлық операцияларды осы ресурстарға орындай аламыз. Сонымен, List Buckets те қамтылған. Жақсы, біз парақшаның ең төменгі жағына жылжып, Next батырмасын басуымыз керек. Келесі парақшада осы рөлдің атын енгізуіміз керек, ол c1oud-academy-demo-ec2-instance-profile болсын. Сондай-ақ, Step 1 Select Trusted Entities көреміз және мұнда төмендегіні айтатын бұрыннан толтырылған JSON құжаты берілген. Тек EC2 сервисінде бұл рөлді assume мүмкіндігі бар, яғни бұл рөлді басқа пайдаланушылар қабылдай алмайды. Жарайды, аздап төмен айналдырайық, бұл рөлге қандай policy қосқанымызды көреміз, бұл AmazonS3ReadOnlyAccess. Біз барлығын дұрыс орнаттық, енді экранның төменгі оң жағындағы Create role батырмасын басу керек. Жақсы, барлық рөлдері бар парақшаға қайта бағытталдық. Экранның жоғарғы жағында IAM рөлін сәтті жасағанымызды көреміз, бұл жасыл өңі бар хабарламамен көрсетіледі. Енді бұл рөлді EC2 инстансына байланыстыру үшін EC2 сервисіне бара аламыз. Ол үшін EC2 сервисіне өтуіміз керек, инстанстар тізімінде біздің инстансты таңдауымыз керек. Жоғарғы оң жақ бөлікте Actions батырмасын басыңыз, ашылмалы тізімнен Security батырмасын басыңыз. Мұнда сондай-ақ ашылмалы тізім болады, Modify IAM Role пунктін басу керек. Бөлек парақшаға бағытталатын боламыз, мұнда EC2 сервисі үшін осы рөлдерді қабылдауға рұқсат берілген барлық рөлдермен ашылмалы тізім көрсетіледі. Біз көретін жалғыз рөл - біз жасаған рөл c1oud-academy-demo-ec2-instance-profile . Сіз оны таңдап, Update IAM Role батырмасын басуыңыз керек. Мұны жасағаннан кейін инстанстар тізіміне қайта ораламыз, өзгерту сәтті жасалғаны туралы хабарды көреміз. Енді PuTTY қосымшасын ашып, aws s3 ls пәрменін қайта іске қосып көруіміз керек. Жақсы, мұны істегеннен кейін 10 бакет көреміз. Бірінші бакет - біз бұрын еске сақтаған бакет, ол c1oud-academy-aws-test-temp-data-bucket. Жақсы. Енді сіз EC2 Instance Profile не екенін және оның EC2 инстанс жағында тіркелгі деректерімен тұрақты қатынас жасаумен салыстырғанда қосымша артықшылықтар беретінін білесіз. Мұны пайдаланыңыз, егер сіз бұлттық инженер ретінде жұмыс істесеңіз, бұл жиі кездесетін тапсырма. Енді AWS аккаунтымызды жасалған ресурстардан тазалауымыз керек. Инстанстар тізіміне өтіп, инстансымызды таңдаймыз, содан кейін Instance State батырмасы арқылы Terminate instance басыңыз. Бұл инстансты жойып жатқанымызды растаймыз, содан кейін IAM сервисіне барамыз, өзіміз жасаған рөлімізді табамыз, оны да таңдаймыз және жоғарғы оң жақ бөліктегі Delete батырмасын басыңыз. Мұнда оны жою үшін осы рөлдің атын енгізу керек, оны қалқымалы терезенің жоғарғы жағынан көшіріп, осы өріске қоюға болады. Осыдан кейін Delete батырмасы қолжетімді болады. Жақсы, біз жасаған барлық ресурстарды жойдық және осымен бүгінгі демомыздың соңына жеттік. Назарларыңызға рахмет, келесі белсенділіктерде кездескенше.
