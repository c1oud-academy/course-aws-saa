Добрый день уважаемые студенты, я рад вас всех видеть на очередной сессии демо. Тема сегодняшнего демо - это создание высокодоступного веб-приложения. Итак, давайте начнем. Мы с вами начинаем с главной страницы AWS Management Console. Первым делом нам необходимо создать Load Balancer. Для этого в строке поиска сервисов мы можем ввести EC2 и перейти на главную страницу сервиса EC2, либо ввести ALB или Load Balancers. И мы видим, что в выдачах есть отдельная секция Features и там отображается Load Balancers. Давайте на нее нажмем, чтобы нас сразу направило на нужную страницу в целом сервисе EC2. То есть фактически откроется пункт Load Balancers в левом навигационном меню сервиса EC2. Мы видим, что у нас нет созданных Load Balancers, поэтому нам необходимо нажать на кнопку Create Load Balancer в верхней правой части экрана. Здесь мы в рамках демо будем создавать Application Load Balancer или ALB. В нижней части будет кнопка Create. Как название Load Balancer укажем c1oud-academy-demo-elb. Далее мы укажем, что Load Balancer у нас Internet-facing, то есть он обслуживает интернет трафик, внешне входящий трафик. Указываем, что мы используем IPv4, IPv6 нам не нужен в рамках этого демо. Прокрутим чуть ниже, здесь необходимо будет выбрать VPC. Выбираем VPC. Далее в Mapping нам необходимо выбрать Availability зоны и для каждой Availability зоны необходимо выбрать Subnet в этом VPC. У нас уже есть созданные Public Subnets, поэтому мы для каждого из Availability зон их выберем. Прокрутим чуть ниже, здесь необходимо будет создать новую Security группу. Для этого будет готовая ссылка, что очень удобно. Давайте на нее нажмем, нас направит сразу на страницу создания новой Security группы. При этом мы откроем ее не в той же вкладке, а создастся новая вкладка браузера. И там мы сможем создать Security группу. Предыдущую вкладку закрывать не нужно, мы к ней еще вернемся. Теперь как название Security группы укажем c1oud-academy-demo-sg. sg это вкратце от Security group. Укажем некоторый Description. Чуть ниже есть Inbound rules, необходимо будет нажать на кнопку Add Rule, добавится строчка. Здесь мы как Type укажем HTTP Traffic, автоматически проставится протокол TCP и Port Range, то есть 80 порт. Как Source необходимо будет указать Anywhere IPv4 и мы увидим проставится CIDR блок со всеми нулями. После этого в самой нижней части экрана необходимо будет нажать на кнопку Create Security Group. Нас направит на главную страницу ресурса, мы увидим также зеленым фоном сообщение о том, что Security группа была успешно создана. Теперь мы можем вернуться на страницу создания Load Balancer и выбрать эту созданную Security группу. Для этого нам необходимо будет в первую очередь нажать на кнопку обновить, чтобы подтянуть свежий список Security Group. После этого, когда мы нажимаем на поле Security Groups, то в всплывающем списке мы увидим Security группу, созданную нами ранее. Давайте ее выберем. Далее необходимо будет прокрутить чуть ниже до следующей секции и здесь необходимо выбрать Target группу. Так как Target группу мы еще не создавали, воспользуемся готовой ссылкой Create Target Group. Нас также направят в отдельной вкладке браузера на страницу создания Target группы. Здесь нам необходимо будет указать, что таргетом являются инстансы, то есть EC2 инстансы. Далее как Target group name укажем c1oud-academy-demo-tg, то есть вот Target group. Прокрутим чуть ниже, необходимо будет выбрать ту же VPC. Далее как Protocol version укажем значение по умолчанию и прокрутим в самый низ страницы. Здесь нам необходимо будет нажать на кнопку Next, чтобы мы перешли на вторую страницу создания Target группы. Здесь предлагается зарегистрировать Target. Мы сейчас этого делать не будем, нам достаточно прокрутить в самый низ страницы и нажать на кнопку Create Target group. Как только мы это сделаем, нас направят на страницу со списком Target group. Мы также увидим сообщение с зеленым фоном о том, что Target группа была успешно создана. Теперь мы можем закрывать эту вкладку и возвращаться на предыдущую, там где мы создавали Load balancer. Здесь по той же логике необходимо будет сначала нажать на кнопку обновить список Target group, после чего нужная Target ссылка будет в выпадающем списке. Давайте ее выберем и прокрутим до конца страницы. В самом низу страницы необходимо будет нажать на кнопку Create Load balancer. Далее мы увидим сообщение о том, что Load balancer был успешно создан. Мы можем нажать на кнопку View Load balancer и нас направит на страницу со списком Load balancer. Мы увидим, что мы успешно создали наш Load balancer. Как состояние видим Provisioning, то есть он создается, нам нет необходимости ее ждать. Мы переходим к созданию Auto Scaling Group. Для этого в навигационном меню слева необходимо будет выбрать пункт Auto Scaling Groups. Так как на нашем AWS аккаунте еще нет ни одной Auto Scaling Group, мы видим соответствующую страницу. В верхней правой части будет кнопка Create Auto Scaling Group. Давайте на нее нажмем. Нас направят на первую страницу создания Auto Scaling Group. Здесь как name укажем c1oud-academy-demo-asg, то есть вкратце Auto Scaling Group. Далее необходимо будет выбрать Launch template. Мы ее еще не создавали, поэтому здесь также давайте воспользуемся ссылкой Create Launch template. В новой вкладке откроется страница создания нового Launch template. Как Launch template name укажем c1oud-academy-launch-template. Далее как template version description укажем v1, это первая версия. Там где Auto Scaling guidance нужно поставить галочку, так как мы создаем ее для сервиса EC2 для наших EC2 инстансов. Прокрутим ниже. Здесь необходимо будет выбрать операционную систему. Мы в рамках этого демо выберем Ubuntu, выберем последнюю версию. Далее как Instance type выберем t2.micro. Как keypair можем ее не включать, можем включить. В принципе в рамках этого демо она нам не нужна. Прокрутим чуть ниже. Здесь будут настройки сети. Мы здесь будем выбирать security группу, которую уже создавали ранее. Необходимо ее найти в списке, называется с1oud-academy-demo-sg. Давайте ее выберем. Прокрутим в самый низ страницы. Необходимо будет развернуть секцию Advanced details, прокрутить в самый низ страницы и ввести следующие команды. Эти команды создают Apache веб-сервер с одной единственной страницей, где будет написано Hello world. Этого нам достаточно в рамках нашего демо. Как только ввели эти команды, давайте нажмем на кнопку Create launch template. Мы увидим сообщение о том, что launch template был успешно создан. Если нажмем на кнопку View launch template в нижней правой части экрана, нас направит на страницу со всеми launch templates. Эта вкладка нам уже не нужна, мы можем ее закрывать и возвращаться на предыдущую вкладку. Здесь нам необходимо будет также нажать на кнопку обновить и мы получим свежий список launch templates и выберем ту, которую мы сейчас только создали. После чего нажмем на кнопку Next в нижней части экрана. На следующей странице нам необходимо будет ввести настройки сети, а именно мы выбираем наш VPC. Далее указываем необходимые public subnets в двух availability зонах. В нашем случае это us-east-1a и us-east-1b и соответствующий public subnets в этих availability зонах. Прокрутим вниз страницы и нажмем на кнопку Next. На следующей странице здесь мы будем привязывать нашу Auto Scaling Group к Load Balancer. Привязка происходит не напрямую, а через нашу target группу. Если мы помним, мы привязывали target группу к Load balancer и теперь мы Auto Scaling Group привязываем к target группе. После чего все три ресурса между собой будут связаны и готовы к работе. Здесь необходимо будет выбрать опцию Attach to an existing load balancer. Далее необходимо будет указать, что мы ищем среди существующих target групп и из списка находим тот, который мы создавали ранее. Называется c1oud-academy-demo-tg. Прокрутим вниз страницы и нажмем на кнопку Next. На следующей странице необходимо будет ввести настройки группы, а именно здесь мы укажем desired capacity, то есть какое количество инстансов будет изначально в Auto Scaling Group. Также мы укажем граничные значения, то есть минимальное и максимальное количество инстансов, которые могут быть в этой Auto Scaling Group. Чуть ниже мы создадим scaling policy. У нас будет один единственный scaling policy - target tracking scaling policy. Оставим все значения по умолчанию, единственное внизу, там где Instance warmup, укажем 0 секунд. Это нужно для того, чтобы не ждать дополнительное время, пока инстанс после создания можно будет добавлять к Auto Scaling Group. Так как стоит 0, как только инстанс будет создан, он сразу будет привязан к Auto Scaling Group и будет готов к работе. В реальной же жизни, во время запуска EC2 инстанса у нас скорее всего будет заполнены user data, там будет ряд команд, которые проводят дополнительную настройку, устанавливают необходимые программы. В этом случае вы будете указывать Instance warmup какое-то положительное значение. На этой странице мы заполнили все необходимое. Необходимо будет теперь в нижней части экрана нажать на кнопку Next. В рамках текущего демо мы не будем настраивать никакие уведомления, поэтому нажмем на кнопку Next. Также мы не будем вводить никакие теги, вы уже умеете работать с тегами, мы это проделывали в предыдущих демо. В будущем во время работы над реальными проектами рекомендация - всегда вводить теги в зависимости от того для чего создается тот или иной ресурс, чтобы в будущем через какое-то время вы всегда могли открыть эти теги и вспомнить для чего же они создавались. Нажимаем на кнопку Next, нас направит на самую последнюю страницу с Review, здесь мы можем посмотреть все введенные нами настройки ранее. Необходимо будет пройтись перепроверить и в самой нижней части экрана нажать на кнопку Create Auto Scaling Group. Нас направит на страницу с Auto Scaling Group, мы увидим что у нашей Auto Scaling Group статус updating. Она сейчас занимается созданием двух EC2 инстансов, которые мы указали в desired capacity. На текущий момент количество инстансов под этой Auto Scaling Group равняется нулю. Давайте теперь также перейдем к списку инстансов. Для этого необходимо воспользоваться навигационным меню слева и выбрать пункт Instances. Мы увидим, что создаются два EC2 инстанса, они пока еще не прошли системные проверки, поэтому там стоит под Status check - Initializing. Обратите внимание на столбец Availability zone, два инстанса были распределены по двум availability зонам, которые мы указывали во время настройки наших ресурсов. Для проведения эксперимента нам необходимо дождаться, когда наши инстансы будут полностью готовы. Для этого необходимо периодически нажимать на кнопку Refresh и через какое-то время Status check поменяется, станет зеленым и будет текст 2/2 checks passed. Давайте теперь воспользуемся навигационным меню слева и выберем пункт Load balancers. Здесь нам необходимо будет выбрать наш Load balancer и во вкладке Details найти DNS name. Будет соответствующая иконка для того чтобы скопировать URL-адрес. Давайте откроем новую вкладку и откроем нашу ссылку, мы увидим что открылась страница, ошибки не было и в самом верху слева увидим текст Hello World. Это говорит о том, что мы все ресурсы связали между собой корректно и получили ответ от одного из наших EC2 инстансов. Отлично, давайте теперь также перейдем к target группе, для этого воспользуемся навигационным меню слева и выберем пункт Target groups. Далее откроется список target group, необходимо выбрать нашу и необходимо здесь выбрать вкладку Targets. Обратите внимание что эти же инстансы отображаются здесь. Мы видим, что они распределены по двум разным availability зонам и статус у них healthy, то есть они корректно сейчас работают. Теперь мы продолжаем наш эксперимент, мы будем симулировать проблему на одном из инстансов. И после этого когда он отключится мы проверим продолжит ли Load balancer отображать веб-сайт. Для этого необходимо в списке инстансов выбрать один из инстансов под Auto Scaling Group. Далее нажать на кнопку Instance state и в выпадающем списке выбрать Terminate instance. Нам необходимо подтвердить что мы отключаем этот EC2 instance. Теперь если мы вернемся на нашу target группу и посмотрим таргеты, то здесь уже отображается оставшийся EC2 instance. Если мы сейчас откроем обратно URL-адрес нашего Load balancer, то никакой ошибки не выдалось и мы также увидели страницу нашего веб-сайта, то есть надпись Hello World в верхней левой части экрана. Через некоторое время, если мы будем обновлять страницу, то на стороне target группы появится вторая запись. Создается новый EC2 инстанс в availability зоне us-east-1a, это та availability зона, в которой мы удалили ранее EC2 инстанс. В самом начале health status будет initial, то есть он только-только создается и не подключен к Auto Scaling Group. Если подождать некоторое время и обновить страницу, то мы увидим, что инстанс полностью поднялся, добавился к Load balancer и готов принимать трафик. На этом мы завершили основную часть нашего демо. Мы видим как мы построили небольшую IT-инфраструктуру, которая предоставляет высокую доступность нашего веб-сайта. Мы сделали симуляцию проблемы на одном из EC2 инстансов, при этом как пользователи мы продолжили видеть наш веб-сайт. Теперь нам необходимо зачистить наш AWS аккаунт от созданных ресурсов в рамках этого демо. Нам необходимо будет произвести все действия в обратном порядке и мы начинаем с Auto Scaling Group. Необходимо будет выбрать наш Auto Scaling Group, верхней правой части нажать на кнопку Actions и в выпадающем списке нажать на кнопку Delete. В всплывающем окне необходимо будет в текстовом поле ввести слово delete и после чего кнопка Delete станет активной и мы сможем на нее нажать. Далее переходим ко списку Load balancers, здесь также выбираем наш Load balancer, в верхней правой части нажимаем на кнопку Actions, в выпадающем списке нажимаем на пункт Delete load balancer. В всплывающем окне необходимо будет ввести confirm и нажать на кнопку Delete. Далее мы открываем список target group, выбираем нашу target группу. Мы видим, что она не ассоциирована с Load balancer, то есть она не привязана ни к одному из Load balancer и только в этом случае target группу можно удалять. Выбираем нашу target группу, в верхней правой части выбираем Actions и в выпадающем списке выбираем вариант Delete. Здесь нам необходимо будет нажать на кнопку Yes, delete и подтвердить что мы хотим удалить этот ресурс. Отлично, теперь мы переходим к списку security group, находим нашу security группу. Это c1oud-academy-demo-sg, выбираем ее, опять же в верхней правой части экрана нажимаем на Actions. В выпадающем списке выбираем пункт Delete security group. Подтверждаем, что мы удаляем нашу security группу и на этом мы удалили все созданные нами ресурсы в рамках этого демо. Теперь нам необходимо корректно разлогиниться, для этого в верхней правой части экрана нажимаем на имя пользователя и в выпадающем списке нажимаем на кнопку Sign out. На этом мы очистили полностью наш AWS аккаунт от созданных ресурсов, успешно вышли с этого AWS аккаунта. Я надеюсь, вы получили более полное представление как создавать высокодоступные IT-инфраструктуры в облаке AWS. Спасибо за внимание, увидимся с вами на следующих наших активностях.
