Қайырлы күн, құрметті студенттер. Кезекті демо сессияда сіздерді көргеніме қуаныштымын. Бүгінгі демо барысында біз Lambda-функция құрып, оны Amazon S3 сервисімен өзара әрекеттестіреміз. Ендеше, бастайық. Бізде екі S3 bucket болады. Біріншісі — input bucket, екіншісі — output bucket. Біз Lambda көмегімен input bucket-тен output bucket-ке деректерді еш өзгеріссіз көшіреміз. Маңызды жайт — деректер input bucket-ке жүктелген сәтте event жасалады, ол Lambda-функцияны іске қосады. Ал Lambda-функция өз логикасына сәйкес орындалады. Алдымен S3 bucket-терін құруымыз керек. Осыдан бастайық. AWS Management Console-дың басты парақшасынан бастаймыз. Мұнда сервис іздеу жолағын пайдаланып, S3 деп теру керек. Бірінші сілтеме — бізге керегі. Бізде қазірдің өзінде бірнеше S3 bucket бар. Біз бәрібір екі жаңасын құрамыз, сондықтан экранның оң жақ жоғарғы бөлігіндегі Create bucket батырмасын басу керек. Бізді жаңа ресурс құру парақшасына жібереді. Bucket name ретінде c1oud-academy-lambda-demo-input деп көрсетеміз. Region ретінде North Virginia таңдап, парақшаның төменгі оң жағындағы Create bucket батырмасын басамыз. Бізді bucket тізімі бар парақшаға жібереді. Bucket сәтті құрылғаны жайлы жасыл фонда хабарлама көреміз. Сондай-ақ біздің bucket тізімде шығады. Енді екінші S3 bucket құрамыз, тағы да Create bucket батырмасын басамыз. Bucket name ретінде c1oud-academy-lambda-demo-output енгіземіз. Region ретінде North Virginia таңдап, қалған баптауларды әдепкі бойынша қалдырамыз да, төмендегі Create bucket батырмасын басамыз. Осылайша біз демоға қажетті екі S3 bucket құрдық, енді келесі бөлікке көшеміз. Бүгінгі демоның екінші бөлігіне өтеміз, мұнда lambda үшін IAM рөлін құрамыз. Ол үшін сервис іздеу жолағында IAM деп теру керек. Бірінші сілтеме — бізге керегі. Мұнда сол жақтағы навигация мәзірінен рөлдер тізіміне өту керек. Экранның оң жақ жоғарғы бөлігінде Create role батырмасы болады. Оны басамыз, бізді жаңа ресурс құрудың бірінші парақшасына жібереді. Мұнда Trusted Entity ретінде AWS service таңдаймыз. Төменірек Use case ретінде сервис таңдау керек, бізде бұл Lambda. Содан кейін парақшаның төменгі оң жағындағы Next батырмасын басамыз. Екінші парақшада рөлімізге Permissions таңдау ұсынылады. Бұл демода рөлді қарапайым етеміз, бастысы — Lambda жұмысы және оның S3-пен әрекеттесуі. Сондықтан AmazonS3FullAccess деп аталатын AWS managed policy таңдаймыз, ол барлық S3 bucket-терге толық қол жеткізу береді. Айта кететін жайт, болашақта production ортада жұмыс істегенде, least privilege принципін сақтау ұсынылады және рөлдерге тек қажетті құқықтарды ғана беру керек. Мысалы, бұл lambda үшін input bucket-тен файлдарды оқуға арналған бірінші policy және output bucket-ке файл жазуға арналған екінші policy жеткілікті болар еді. Мұнда сізден бір сәт ойланып, lambda функциясының дұрыс жұмыс істеуі үшін тағы қандай policy қосу керек екенін анықтауды сұраймын. Lambda функциясы онсыз да жұмыс істейді, бірақ бір нюанс бар. Ойланып көріңіз, жауабы сәл кейінірек беріледі. Енді парақшаның төменгі оң жағындағы Next батырмасын басамыз. Соңғы парақшада рөлдің атауын енгіземіз, ол c1oud-academy-lambda-demo-role болсын. Сондай-ақ енгізілген параметрлердің Review бөлімін көресіз, бәрі дұрыс болса, парақшаның соңына дейін жылжып, Create role батырмасын басамыз. Бізді рөлдер тізімі бар парақшаға жібереді, lambda деп сүзгілеп, рөліміздің тізімде бар екеніне көз жеткіземіз. Сондай-ақ экранның жоғарғы бөлігінде рөл сәтті құрылғаны туралы хабарлама көресіз. Жақсы, осымен демоның екінші бөлігін аяқтап, келесісіне көшеміз. Біз бүгінгі демоның негізгі бөлігіне жеттік — lambda функциясын құрып, баптаймыз. Lambda құру үшін осы сервиске өту керек, сондықтан сол жақ жоғарғы іздеу жолағында lambda деп тереміз. Бірінші сілтеме — бізге керегі. Бізді функциялар тізімі бар парақшаға жібереді, оң жақ жоғарғы бөлікте Create function батырмасы болады, оны басамыз. Сол сәтте жаңа ресурс құру парақшасына түсеміз. Мұнда Author from scratch опциясын таңдаймыз, яғни lambda функциясын нөлден құрамыз. Function name ретінде c1oud-academy-demo-lambda, ал Runtime ретінде соңғы нұсқадағы Python, яғни 3.10 таңдап, парақшаның соңына дейін жылжимыз. IAM рөлін алдын ала құрдық, сондықтан Use an existing role опциясын таңдап, рөлдер тізімінен c1oud-academy-lambda-demo-role таңдап, парақшаның төменгі оң жағындағы Create function батырмасын басамыз. Бізді lambda функциясының басты парақшасына жібереді, жоғарғы бөлікте жасыл фонда функция сәтті құрылғаны жайлы хабарлама көреміз. Енді troubleshooting мақсатында lambda функциясына бір жол қосамыз — print операторы арқылы input event мазмұнын экранға шығарамыз. Бұл жолды қосып, өзгерістерді сақтаймыз. Өзгерістерді сақтау үшін Ctrl+S пернелерін басуға немесе редактордың сол жақ жоғарғы бөлігіндегі File батырмасын басып, ашылған тізімнен Save таңдау керек. Сақтаған соң, редактордың жоғарғы бөлігінде сұр фонда өзгерістер бар және олар әлі орнатылмағаны туралы хабарлама шығады. Ол үшін Deploy батырмасын басу керек. Оны жасайық. Бірнеше секундтан кейін lambda функциямызды сәтті орнатамыз және жоғарғы бөлікте жасыл фонда өзгерістердің сәтті орнатылғаны жайлы хабарлама аламыз. Сондай-ақ Deploy батырмасы енді белсенді болмайды. Бұл редактордағы барлық өзгерістер сәтті орнатылғанын және дәл осы нұсқа Lambda функциясын шақырғанда кіріс сұраныстарын өңдейтінін білдіреді. Енді біз lambda үшін триггер құруымыз керек. Ол үшін парақшаны жоғарыға жылжытып, Add trigger батырмасын басамыз. Жаңа триггер құру парақшасы ашылады. Мұнда event жасаушы сервис қандай екенін көрсету керек. Біздің жағдайда бұл S3. Сервис таңдағаннан кейін төменде тиісті енгізу өрістерінің тізімі шығады. Біздің жағдайда бұл Bucket. c1oud-academy-lambda-demo-input bucket таңдаймыз. Сәл төменірек Event types жерінде All object create events таңдаймыз, яғни S3 bucket ішінде файлдар әртүрлі жолмен құрылуы мүмкін. Файлдың қалай жасалғаны бізді қызықтырмайды. Кез келген файл жасалғанда, біз event генерациялауымыз керек және бұл event Lambda функциясын іске қосуы тиіс. Қалған өрістерді әдепкі бойынша қалдырамыз және ең төменгі бөлігінде құсбелгі қою керек. Бұл құсбелгі S3 bucket ішіндегі объект жасалғанда триггерленетін Lambda функциясы сол bucket ішінде файл жасамауы керек екенін түсінетінімізді білдіреді. Әйтпесе бұл шексіз цикл болады. Lambda жасаған файл сол S3 bucket ішінде жаңа event туғызады, ол тағы да сол lambda-ны іске қосады. Бұл шексіз, мағынасыз цикл және өте қымбатқа түседі. Сондықтан құсбелгі қойып, бұлай жасауға болмайтынын есте сақтап, экранның төменгі оң жағындағы Add батырмасын басамыз. Бұны жасаған соң бізді Lambda функциясының басты парақшасына қайтарады, жасыл фонда триггер сәтті жасалғаны және белсендірілгені туралы хабарлама көреміз. Сондай-ақ триггерлер тізімінде S3 сервисін көреміз. Енді триггердің жұмысын тестілеуге көше аламыз. Біз демоның келесі бөлігіне көшеміз және S3-тен Lambda функциясының триггерін тексереміз. Ол үшін S3 сервисіне өтіп, Input S3 bucket ашу керек. S3 bucket басты парақшасы ашылған соң Properties қойындысын ашып, парақшаның ортасына Event notifications бөліміне дейін жылжимыз. Мұнда S3 bucket жағынан дәл осындай триггер жасау мүмкіндігі бар екенін көресіз. Біз мұны lambda жағынан жасадық және бұл өзгерістер S3 bucket жағында да көрінді. Бір event notification бар, ол S3 bucket ішінде объектілер жасауға байланысты барлық event-терге байланған. Нәтижесінде event Lambda функциясын триггерлейді және мұнда біздің Lambda функциясының сілтемесін және атауын көреміз. Енді парақшаның басына оралып, Objects қойындысына өту керек. Мұнда біздің S3 bucket-ке әлі ешқандай объект жүктелмегенін көреміз. Мұны жасайық. Upload батырмасын басу керек, содан кейін файлдар мен папкаларды таңдау парақшасына өтеміз, біз файлдарды да, тұтас папкаларды да жүктей аламыз. Біздің жағдайда бұл файл болады, QR.jpg суретін жүктеп, парақшаның төменгі бөлігіндегі Upload батырмасын басамыз. Бізді S3 bucket-ке деректер жүктеу статусы бар парақшаға жібереді. Барлық файлдарды жүктеу аяқталған соң, экранның жоғарғы бөлігінде жасыл фонда жүктеу сәтті аяқталғаны туралы хабарлама көреміз. Сондай-ақ экранның төменгі бөлігінде әр файлдың жүктеу статусы көрсетіледі. Енді S3 bucket-ке қайта оралу керек, біз мұны сілтеме арқылы немесе экранның оң жақ жоғарғы бөлігіндегі Close батырмасын басу арқылы жасай аламыз. Екі жағдайда да бізді S3 bucket басты парақшасына қайтарады және объектілер тізімінде QR.jpg файлын көреміз. Енді Lambda функциясының басты парақшасына қайта оралып, Monitor қойындысын таңдаймыз, содан кейін View CloudWatch logs батырмасын басамыз. Жаңа браузер қойындысы ашылады, мұнда көрсетілген lambda логтары шығуы тиіс. Алғашқы өту кезінде Log group жоқ екені жайлы хабарлама көруіңіз мүмкін. Бұл қойындыны жабу керек, ондай жағдай болады, lambda парақшасына қайта оралып, парақшаны жаңарту керек. 1-2 минут күтіп, осы уақытта метрика деректерін де жаңартамыз. Lambda функциясының бір рет іске қосылғанын және оның сәтті орындалғанын көреміз. Жақсы, енді тағы да View CloudWatch logs батырмасын басып, логтарды ашып көрейік. Көріп тұрғанымыздай, тағы да дәл осындай қате алдық. Енді мен сізге видеоны тоқтатып, бұл қатені неге шыққанын және логтар неге шықпай жатқанын түсінуге тырысуды ұсынамын, не істеу керек екенін ойланыңыз. Егер сіз lambda функциясында log group және log stream жасауға құқық жетіспейді деп ойласаңыз, онда дұрыс ойладыңыз, troubleshooting жасап көрейік. Lambda функциясы парақшасында Configuration қойындысын ашу керек. Содан кейін Permissions ішкі қойындысын ашып, мұнда біздің IAM role сілтемесін көреміз. Сәл төменде Resource summary бөлімі бар, ашылмалы тізімді бассақ, IAM role тек S3 bucket-ке қол жеткізе алатынын көреміз. Енді IAM role басты парақшасына өтіп, қажетті policy қосайық. Ол үшін Permissions қойындысын ашып, Add permissions батырмасын басамыз, содан кейін ашылмалы тізімнен Attach policies пунктін таңдаймыз. Мұнда аздап түсініктеме беру керек: AWS Management Console арқылы Lambda функциясын жасаған кезде, егер біз Lambda үшін IAM role автоматты түрде жасалсын деп көрсетсек, бұл IAM role ішінде бір ғана policy автоматты түрде жасалады. Бұл policy CloudWatch сервисіне қол жеткізу құқығын береді, атап айтқанда слайдта көрсетілгендей policy-ге назар аударыңыз. Біз CloudWatch сервисінде лог топ (log group) жасауға рұқсат берілгенін көреміз. Келесі бөлігі — осы Lambda функциясына байланған лог топта CreateLogStream және PutLogEvents әрекеттеріне рұқсат. Біздің жағдайда лог топ атауы my-hello-world-lambda, бұл алдыңғы демоларымыздан қалған. Осы демо аясында IAM сервисінде көп кідірмейміз, сондықтан AWSLambdaBasicExecutionRole деп аталатын IAM managed policy таңдаймыз. Бұл дәл сол құқықтарды және дәл сол әрекеттерге рұқсат береді, бірақ ресурс ретінде жұлдызшаны (*) көрсетеді, бұл қажетті мөлшерден көп. Мұнда да атап өткім келеді, нақты жобаларда жұмыс істегенде, әрдайым least privilege принципін ұстанып, тек тапсырманы орындау үшін қажет рұқсаттарды ғана беруді және AWS managed policy-ді барынша аз пайдалануды ұсынамын. Біз демо түсінікті болу үшін AWS managed policy қолданамыз. Жарайды, осы policy жанындағы құсбелгіні қойып, парақшаның төменгі бөлігіндегі Add permissions батырмасын басу керек. Бізді IAM role басты парақшасына қайтарады. Сондай-ақ жасыл фонда policy осы рольге сәтті байланғаны туралы хабарламаны көреміз, policy тізімінде екі policy болады. Енді input S3 bucket қойындысына оралып, файлымізді қайта жүктеп көре аламыз. Оны жасағаннан кейін Lambda функциясы қойындысын ашу керек. Содан кейін Monitor қойындысына өтіп, метрикаларды жаңартамыз. Біраз күтеміз, максимум 2 минут, және метрикалар жаңарғанын көреміз. Invocations графигінде тағы бір іске қосу болғанын көреміз, сонымен қатар екінші іске қосу сәл ұзақырақ орындалғанын байқаймыз. Бірақ екеуі де миллисекундтың бөлігі ғана, сондықтан екеуі де тез орындалды. Үшінші графикке қарасаңыз, екінші іске қосу да сәтті орындалған, сондықтан жасыл сызық жоғарғы жағында, ал қызыл төменгі жағында. Жақсы, енді логтарымызға өтейік, ол үшін метрикалар жоғарғы жағындағы View CloudWatch logs батырмасын басу керек. Тамаша, лог топ сәтті жасалғанын көреміз, сондай-ақ экранның төменгі жағында Log stream пайда болғанын көреміз, бұл Log stream біздің lambda-ның екінші іске қосылуына тиесілі. Оған өтіп, логтарда не бар екенін қарайық. Алдымен логтар құрылымын түсініп алайық. Ең бірінші жазба INIT_START, бұл тек lambda жаңа контейнерде іске қосылғанда ғана пайда болады. Егер солай болса, соңында REPORT деп басталатын соңғы жолдан контейнерді инициализациялауға кеткен уақытты көреміз. Контейнер инициализацияланғаннан кейін, осы контейнер ішінде lambda функциясының барлық келесі іске қосылулары Init Duration талап етпейді және әлдеқайда тез басталады. Келесі үш жол — біздің lambda іске қосылу шекаралары, бір іске қосылудың барлық логтары осы жолдардың арасында орналасқан. Басталуы START, мұнда Request ID көрсетіледі, ал соңғы екі жол END және REPORT сол Request ID-мен. REPORT жолында қосымша метрикалар бар: lambda функциясының нақты орындалу уақыты, есепке алынған орындалу уақыты. Сондай-ақ lambda функциясына бөлінген жедел жад көлемі және оның қаншасы нақты қолданылғаны көрсетіледі. Енді lambda логтарына қарайық. Естеріңізде болса, біз input event мазмұнын экранға шығарып, логтарға жазу үшін арнайы жол қосқанбыз, қазір соны көріп отырмыз. Бұл лог жазбасын кеңейтейік, толық хабарламаны көреміз, оны көшіруге болады. Сондай-ақ JSON-ды ыңғайлы форматқа келтіретін кез келген онлайн сервисін қолданып, осы хабарламаны кез келген мәтіндік редакторда көре аласыз. Кіріс event — бұл JSON, барлық қажетті ақпаратты қамтиды. Ол бұл lambda функциясын event триггерлегенін, event c1oud-academy-lambda-demo-input bucket-тен келгенін және оның QR.jpg файлы қосылғандықтан келгенін айтады. Енді бізге осы event-тен қажетті деректерді алып, файлды output bucket-ке көшіру үшін lambda кодын өзгерту қажет. Ол үшін lambda функциясы парақшасына оралып, Code қойындысын ашу керек. Lambda кодын AWS Management Console ішінде өзгертуді ұсынбаймын. Жергілікті Git репозиторийінде жұмыс істеп, кодты қажетті түрде өзгертіп, содан кейін оны CloudFormation немесе CodePipeline арқылы орнатқан дұрыс. Ең соңғы шара ретінде дайын кодты lambda функциясы парақшасында орналасқан код редакторына көшіріп, сол жерден орнатуға болады. Неге? Себебі онлайн редакторда lambda функциясымен жұмыс істегенде, егер командада бірнеше маман жұмыс істесе, нұсқалар қақтығысы болуы мүмкін және келесі нұсқаны сақтау мен орнату кезінде сіз әріптесіңіздің өзгерістерін өшіріп алуыңыз мүмкін. Бұл демо аясында біз бұл lambda функциясымен жұмыс істейтін жалғыз пайдаланушы екенімізді білеміз, сондықтан басты парақшадағы онлайн редакторда өзгерістер енгізе аламыз. Мұны жасайық. Алдымен қажетті модульдерді импорттау керек, бұл үшінші-бесінші жолдар. Содан кейін сегізінші жолда біз Environment Variable-ді импорттаймыз, оны кейінірек баптаймыз. Одан кейін он бірінші және он екінші жолдарда boto3.client баптаймыз, бұл lambda-дан AWS сервистерімен жұмыс істеуге арналған SDK. Он бесінші жолдан бастап бағдарламамыздың негізгі коды басталады, мұнда не істейміз? Біз жаһандық айнымалыларды импорттаймыз, бұл s3_client және environment variable, яғни output bucket атауы. Содан кейін input event-ті экранға шығарамыз және environment variable мәнін де шығарамыз. Бұл өте пайдалы жазба және troubleshooting кезінде қатты көмектеседі. Содан кейін input event-пен жұмыс істеп, одан input S3 bucket атауын аламыз және өзгерген объектінің жолын алуға тырысамыз, содан кейін осы екі мәнді экранға шығарамыз. Мұны жасаған соң, өзгерістерді сақтайық. Бұны екі жолмен жасауға болады: біріншісі — File батырмасы арқылы Save пунктін таңдау, немесе Ctrl+S пернелер комбинациясын басу. Одан кейін бұл өзгерістерді орнату керек, ол үшін онлайн редактордың жоғарғы бөлігіндегі Deploy батырмасын басу қажет. Мұны жасаған соң, бірнеше секундтан кейін жасыл фонда Lambda функциясының өзгерістері сәтті орнатылғаны туралы хабарламаны көреміз. Жақсы, енді input S3 bucket қойындысын ашып, QR.jpg қайтадан жүктейік. Бұл слайдта біз мұны сәтті жасағанымыз көрінеді. Енді Lambda логтары бар парақшаға оралып, Log streams тізімін жаңартып көрейік. Жаңа Log stream пайда болғанына назар аударыңыз. Мұнда қосымша атап өткім келеді: Lambda функциясын орнатқанда автоматты түрде жаңа Log stream жасалады. Әр Log stream жеке контейнерге тиесілі. Сондықтан егер Lambda функциясында өзгеріс болмаса, барлық келесі іске қосулар логтарды сол бір Log stream-ге жазады. Әр контейнердің өмірі 10-15 минут, бұл ресми жарияланбайды, AWS құжаттамасында да таба алмайсыз. Бірақ идеясы мынада: осы 10-15 минут ішінде Lambda іске қосуларында cold start болмайды және олар барынша тез орындалады, содан кейін контейнер жойылады. Тіпті егер сіз Lambda функциясына өзгеріс енгізбесеңіз де, жаңа контейнер жасалса, ол жаңа Log stream жасайды. Ал егер Lambda функциясын жаңартсақ, онда алдыңғы контейнер бізге керек емес, сондықтан ескі Log stream-ге логтар енбей қалады, тіпті 10-15 минут өтпесе де. Ол сол күйінде қалады, ал Lambda функциясы жаңартылғанда жаңа контейнер жасалады. Жаңа контейнер жаңа Log stream жасайды және барлық логтар жаңа Log stream-ге жазылады. Біз екінші Log stream пайда болғанын көріп тұрмыз, ашып логтарды қарайық. Event сақталғанына назар аударыңыз. Содан кейін Environment variable мәнін көреміз, оның мәні None, бұл біз Environment variable баптамағанымызды білдіреді, қазір соны жасаймыз. Содан кейін s3_input_bucket айнымалысының мәніне назар аударыңыз, біз event контекстінен деректерді дұрыс ала алдық, бұл құрылым тұрақты болғандықтан барлық келесі event-терден де s3 bucket атауын сәтті аламыз деген сөз. s3_key айнымалысының мәніне қарасақ, жолды да сәтті алғанымызды көреміз, бұл QR.jpg. Жақсы, енді Lambda функциясының басты парақшасына оралып, Configuration қойындысын және Environment Variables қосымша қойындысын таңдаймыз. Бұл Lambda функциясында Environment variables әлі бапталмаған, сондықтан жаңа орта айнымалыларын жасау үшін Edit батырмасын басу ұсынылады. Орта айнымалыларын өңдеу парақшасы ашылады. Add environment variable батырмасын басайық, екі өріс шығады. Key өрісіне S3_OUTPUT_BUCKET мәнін енгіземіз, ал Value өрісіне output bucket атауын енгіземіз, бұл c1oud-academy-lambda-demo-output. Содан кейін парақшаның төменгі оң жақ бөлігіндегі Save батырмасын басамыз. Одан кейін бізді Lambda функциясының басты парақшасына қайтарады. Жасыл фонда environment variable сәтті қосылғаны туралы хабарламаны көреміз және жаңа key-value жұбы орта айнымалылары тізімінде көрінеді. Келесі өзгерістерді енгізейік, бұл небәрі екі команда: біріншісі boto3.client қолданып, input bucket-тен output bucket-ке файл көшіреді. Параметрлерді бірнеше жолға бөлдік, қабылдауды жеңілдету үшін, бірақ бұл бір команда. Екінші команда — клиент жұмысының нәтижесін экранға шығару, логтарда response айнымалысында жауабын көреміз. Мұны жасаған соң, өзгерістерді сақтап, орнатамыз. Біз демоның соңғы бөлігіне жеттік, барлық қажетті дайындық жасалды, енді бүкіл шешімімізді тестілеуге көшеміз. Алдымен output bucket ашып, объектілер тізімін жаңартып, bucket бос екеніне көз жеткізейік. Содан кейін басқа қойындыда input bucket ашып, QR.jpg қайта жүктейміз. Мұны жасаған соң, Lambda логтары бар қойындыны ашып, Log streams тізімін жаңартамыз, жаңа Log stream пайда болады. Ашып, логтарда не бар екенін қарайық. Environment variable s3_output_bucket дұрыс мән алғанына назар аударыңыз, ол экранға шығарылды, логтарда көрінеді, сондай-ақ response айнымалысының мәніне қараңыз, JSON форматында жауап көрініп тұр. Бұл жолды кеңейтіп, ішінде не бар екенін қарайық. Мұнда жүйелік ақпарат көрсетілген, сонымен қатар output bucket-ке жасалған файлға meta ақпарат ретінде байланған күнді көреміз. Егер файл жасалмаса және қателер болса, онда мұнда қате көрінер еді және Lambda функциясы сәтсіз аяқталар еді. Lambda функциясы сәтті орындалғандықтан, файл output bucket жағында пайда болуы керек деп айта аламыз. Тексерейік. Енді output bucket-ке оралып, объектілер тізімін жаңартсақ, QR.jpg пайда болғанын көреміз. Осылайша біз кемінде 4 сервис пайдаланатын шағын шешім құрдық, олар — Lambda function, S3 bucket, IAM role және CloudWatch Logs. Бұл 3 сервис бірге жұмыс істеп, input bucket-ке объектілер жүктелген сәтте оларды output bucket-ке автоматты түрде көшіру міндетін орындады. Осылайша бүгінгі демо аяқталды. Назарларыңызға рахмет. Келесі белсенділіктерде кездескенше.
