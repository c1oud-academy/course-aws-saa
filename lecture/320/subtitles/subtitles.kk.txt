Қайырлы күн, құрметті студенттер, сіздерді келесі дәрісте көргеніме қуаныштымын. Бұл дәріс — үлкен тақырыптың екінші және соңғы бөлігі, тақырып — AWS бұлтында микросервисті және серверсіз архитектураларды құру. Бізде соңғы екі секция ғана қалды, сондықтан бастайық. Бүгінгі сессияның бірінші бөлімінде біз Amazon API Gateway сервисін толығырақ қарастырамыз, ол біздің серверсіз архитектураларымызды кеңейтуге көмектеседі. Ал екінші бөлімінде біз AWS Step Functions сервисімен танысамыз, ол микросервистерді оркестрациялауға мүмкіндік береді. Amazon API Gateway — бұл AWS ұсынған толық managed шешім, ол бізге кез келген ауқымдағы API-лерімізді құруға, жариялауға, қолдауға, мониторинг және қауіпсіздігін баптауға мүмкіндік береді. API Gateway қолдана отырып, біз API-лерімізді RESTful немесе WebSockets негізінде баптай аламыз. API Gateway-дің өзі баптауға оңай, көптеген AWS сервистерімен интеграцияланады, мысалы Lambda, EC2 және тағы басқа. API Gateway бір секундта жүз мыңдаған параллель API шақыруларын өңдей алады. Бұдан бөлек, API Gateway арқылы біз трафикті басқару, авторизация, қолжетімділікті бақылау, мониторинг және API нұсқаларын (versions) басқару мүмкіндіктерін баптай аламыз. API Gateway сервисін қолданғаны үшін алдын ала ештеңе төлемейміз, бастапқы инвестиция қажет емес, тек пайдаланғанымыз үшін төлейміз. Төлем трафик көлеміне байланысты, яғни API Gateway арқылы өтетін трафик үшін. Егер трафик болмаса, мүлде төлемейміз немесе ең аз мөлшерде төлейміз. Сонымен бірге инфрақұрылымымыз кенеттен келетін үлкен көлемдегі трафикті қабылдауға толық дайын болады. Қауіпсіздік туралы айтатын болсақ, Amazon API Gateway біздің API-лерімізді қорғауға мүмкіндік беретін бірнеше тәсілді қолдайды. Біріншісі — авторизацияны баптау мүмкіндігі, бұл не кастомды lambda, не API Gateway-дің нативті шешімі болуы мүмкін. Келесі біз policy-ді тек инфрақұрылымымыздағы таңдалған ішкі ресурстар ғана API Gateway-мен жұмыс істей алатындай етіп баптай аламыз. API шақыруларына қатысты біз Throttling логикасын баптай аламыз, егер белгілі бір API секундына X реттен артық шақырылмауы керек болса, оған шектеу қойып, артық жүктемені және спам шақыруларды азайтамыз. Соңғы жетілдірілген тәсіл — API Gateway-ге AWS WAF сервисін қосу, осылайша DDoS шабуылдарына дайын боламыз. Бұл слайдта сіз Amazon API Gateway қолданылатын танымал архитектура мысалын көріп тұрсыз. Басында біздің қолданушыларымыз бар, олар интернет арқылы біздің қосымшаға жүгінеді. Олар CloudFront-қа түседі, содан кейін бұл шақырулар API Gateway-ге бағытталады. API Gateway трафик туралы ақпаратты Amazon CloudWatch-қа автоматты түрде логтайды және API Gateway жағында кэштеу логикасын баптауға болады. Одан әрі бұл трафик инфрақұрылымымыздағы әртүрлі ресурстарға бағытталады, олар — Lambda functions, EC2 инстанстар, VPC ішіндегі ресурстар немесе бөлек орналасқан AWS сервистері болуы мүмкін. Осы слайдта біз микросервис архитектурасының мысалын да көреміз. Біздің қолданушыларымыз бар, олар интернет арқылы біздің қосымшаға жүгінеді және бұл шақырулар API Gateway-ге түседі. API Gateway AWS Lambda-мен тығыз интеграциялана алады, яғни микросервис қосымшаларын және серверсіз архитектураларды құру үшін. API Gateway-ден келген сұраныстар AWS Lambda-ға түседі, ал Lambda қажет болса DynamoDB немесе кез келген басқа деректер қорымен жұмыс істеп, жауапты API Gateway арқылы пайдаланушыларға қайтарады. API Gateway қолданылатын архитектураның соңғы мысалы — бұл мобильді қосымшаның backend-і, мұнда бүкіл инфрақұрылым серверсіз болады. Біздің қолданушыларымыз бар, олар қосымша арқылы API Gateway-ге сұраныс жібереді. Содан кейін API Gateway кастомды lambda-функциясы және Amazon Cognito немесе AWS STS көмегімен бұл сұранысты және сәйкесінше қосымша пайдаланушыларын аутентификациялайды. Одан кейін қосымшаның негізгі логикасы жұмысқа кіріседі, барлық аутентификацияланған сұраныстар біздің Lambda-ға түседі. Бұл Lambda ары қарай сұраныс түрі мен қосымша логикасына байланысты DynamoDB, S3, ElastiCache немесе RDS деректер қорымен жұмыс істей алады. Осылайша, біз бүгінгі сессиямыздың бірінші бөлігін аяқтадық. Біз Amazon API Gateway сервисін егжей-тегжейлі қарастырдық, оның анықтамасын, беретін мүмкіндіктері мен артықшылықтарын, сондай-ақ басқа AWS сервистерімен интеграциялау тәсілдерін көрдік. Сондай-ақ микросервис немесе серверсіз архитектураны белгілі бір міндеттерді шешу үшін қалай баптауға болатынын көрсететін бірнеше мысалдарды талқыладық. Енді біз бүгінгі сессиямыздың қорытынды бөлігіне көшеміз және мұнда AWS Step Functions сервисімен танысамыз, ол микросервистерімізді оркестрациялауға арналған. Елестетейік, бізде бір қосымша бар, ал бұл қосымшада серверсіз архитектура деңгейінде бірнеше lambda-функциялар іске қосылады. Lambda-функциялар процесс түріне қарай белгілі бір ретпен жұмыс істейді және әр lambda басқа бір немесе бірнеше lambda-функцияны келесі қадам үшін іске қосады. Сіз диаграммада көріп тұрғандай, lambda-функциялар саны көбейіп, логика күрделенген сайын, бұл әзірлеуді едәуір шатастырып, қиындата алады. AWS тарапында дайын шешім бар — бұл AWS Step Functions сервисі, ол микросервистерімізді бір-бірімен үйлестіруге және бәрін визуалды workflow-ға орауға мүмкіндік береді. Біз workflow-ды AWS командасы жасаған арнайы тіл мен элементтерді пайдаланып құрамыз. Содан кейін ыңғайлы интерфейсте workflow-ымыздың қалай орындалып жатқанын визуалды түрде көруге болады. Қай түйінде қате болғанын, оның себебін, сондай-ақ осы немесе алдыңғы түйіндер бойынша қосымша мәліметтерді көруге мүмкіндік бар. Арнайы workflow сипаттау тілін пайдаланып, біз түрлі әрекеттерді орындай аламыз. Бұл слайдта негізгі мысалдар көрсетілген: біз тапсырмалар ретін (task sequence) баптай аламыз. Task — бұл бір тапсырма, ал әр тапсырма — бұл бір lambda-функция. Сондай-ақ шартқа байланысты белгілі бір lambda-функцияны іске қосу немесе бірнеше lambda-функцияны параллель орындап, оның нәтижесінде келесі lambda-ны кезекпен іске қосу мүмкіндігін баптауға болады. Retry логикасын немесе try-catch логикасын баптап, қате түріне немесе алғашқы тапсырманың сәтті орындалуына қарай белгілі бір lambda-функцияны орындауға болады. Workflow-дағы әрбір түйін state деп аталады, ал бір-бірімен байланысқан бірнеше state жиынтығы state machine деп аталады. Енді ең қарапайым state machine мысалын қарастырайық. Елестетейік, бізде фотосуреттер жүктеуге болатын мобильді қосымша бар. Бұл фотосуреттер қосымшада сақталады, әр сурет үшін кішірейтілген көшірме (thumbnail) жасалады және суретте не бейнеленгенін анықтауға әрекет жасалады. Бұл тегтер суретке мета-деректер ретінде байланыстырылып сақталады. Осы мобильді қосымша үшін state machine мынадай болуы мүмкін. Сурет S3 bucket-ке түскен сәтте автоматты түрде event генерацияланып, ол біздің state machine-ді триггерлейді. State machine бірінші task-ты іске қосады, ол біздің суретіміздің мета-деректерін шығаратын lambda, содан кейін сурет түрі тексеріледі. Егер сурет түрі қолдау таппаса, онда процесс қате арқылы тоқтайды. Содан кейін хабарландыру жіберуді немесе пайдаланушыға басқа сурет жүктеу қажеттігі туралы тікелей хабарлама жіберуді баптауға болады. Егер сурет түрі қолдау тапса, онда параллель тапсырмалар орындалады. Бірінші тапсырма — бұл суреттің миниатюралық көшірмесін (thumbnail) жасау, ал екінші параллель тапсырма — бұл Rekognition. Біз суретімізді арнайы сервиске жібереміз, ол сурет ішіндегі объектілерді тануға тырысады. Егер бірдеңе табылса, келесі lambda бұл тегтерді біздің суретке бекітеді, содан кейін state machine өз жұмысын аяқтайды. Енді state machine-де қандай түйін түрлері болатынын қарастырайық. Біріншісі — Task, біз онымен бұрын таныстық, Task бір lambda-функцияны іске қосады. Келесі — Choice, ол кіріс деректеріне байланысты state machine ішінде бір бағытқа немесе басқа бағытқа өтеді. Бағдарламалаудағы ұқсастығы — EFails block. Үшінші түрі — Fail, ал төртіншісі — Succeed, олар өзара байланысты. Біз state machine-нің әртүрлі тармақтарына соңғы нүкте ретінде логикаға байланысты Fail немесе Succeed қоса аламыз. Келесі түйін түрі — Pass, ол өзі ешқандай жұмыс атқармайды, бірақ кіріс құрылымын түрлендіріп, келесі түйінге өзгертілген күйінде бере алады. Содан кейін Wait түрі келеді, ол да ешқандай жұмыс атқармайды, бірақ state machine-нің орындалуын берілген секундқа кідірте алады. Бұл өте ыңғайлы, өйткені біз state machine-ге басқа тармақ немесе асинхронды тапсырма келесі түйінге өтпес бұрын орындалып біткенше күту кезеңін қоса аламыз. Тағы бір таныс түйін түрі — Parallel, оның идеясы — біз state machine-нің тұтас тармақтарын немесе жеке тапсырмаларды бір-бірінен тәуелсіз іске қоса аламыз, бұл кейде өте ыңғайлы. Негізгі түйін түрлерінің соңғысы — Map. Оның идеясы — бірдей элементтер жиынтығын әрқайсысын жеке-жеке, цикл арқылы өңдеу, яғни бағдарламалаудағы Map түйініне тікелей ұқсастығы — цикл. Бұл слайдта сол жақта state machine-ді сипаттайтын JSON мысалын көресіз, біз оны бүгінгі сессияда егжей-тегжейлі талдамаймыз. Ал оң жақта AWS Step Functions сервисіндегі осы state machine-нің визуализациясы көрсетілген. Енді AWS Step Functions қолданылатын архитектура мысалын қарастырайық. Ең танымал мысал — интернетте бейнені трансляцияға дайындау. Біз бастапқы бейнені S3 bucket-ке жүктейміз, содан кейін ол workflow-дан өтеді. Workflow ішінде Step Functions және бейнені қажетті форматқа келтіретін қосымша сервистер бар. Workflow аяқталғаннан кейін нәтижелер тиісті сервистерге беріледі — бұл S3 болуы мүмкін немесе Elemental MediaPackage, ал CloudFront көмегімен бейнеңізді пайдаланушыларыңызға таратуға болады. Осылайша, біз бүгінгі сессиямыздың соңғы бөлігін аяқтаймыз. Біз AWS Step Functions сервисін егжей-тегжейлі қарастырдық, ол қандай мүмкіндіктер береді, state machine деген не, оның құрамына не кіреді, қандай түйін түрлері бар және олардың айырмашылықтары қандай екенін талқыладық. Біз екі дәрістен тұратын үлкен тақырыпты аяқтадық. Біз микросервистер деген не, серверсіз архитектура деген не, олардың айырмашылықтары, артықшылықтары мен кемшіліктері қандай, сондай-ақ осындай архитектураларды құру үшін қандай AWS сервистерін қолдануға болатынын егжей-тегжейлі талдадық. Содан кейін Amazon API Gateway және AWS Step Functions атты екі пайдалы сервисті қарастырдық, олар микросервис немесе серверсіз шешімдерге негізделген архитектураларды одан әрі кеңейтуге көмектеседі. Бұл слайдта интернеттен қосымша ақпарат іздеуге арналған негізгі кілт сөздерді көресіз. Олар негізінен AWS құжаттамасына немесе YouTube-тағы AWS конференциясының веб-сессияларына сілтейді. Осылайша, біз бүгінгі дәрісімізді аяқтаймыз. Назарларыңызға рахмет, келесі белсенділіктерде кездескенше.
