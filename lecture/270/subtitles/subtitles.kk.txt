Қайырлы күн, құрметті студенттер! Келесі дәрісте барлығыңызды көргеніме қуаныштымын. Бүгінгі дәрістің тақырыбы — AWS бұлтында архитектураны автоматтандырылған түрде құру. Бұл осы үлкен тақырыптың екінші және соңғы бөлімі. Ендеше бастайық. Бүгінгі дәріс екі бөлімнен тұрады. Біріншісі — орнатуды автоматтандыру, екіншісі — AWS Elastic Beanstalk сервисі. Біз төртінші бөлімді бастаймыз және мұнда орнатуды автоматтандыру туралы сөйлесеміз. Бір кейсті елестетейік. Сізде үш EC2 сервері бар, оларда мезгіл-мезгіл жаңартулар жасау қажет. Жаңартулар дайын скрипттерді орындау түрінде болуы мүмкін. Бұл скрипттер қолданбаларды жаңарта алады, қауіпсіздік патчтарын орната алады немесе операциялық жүйені жаңартуға қатысты болуы мүмкін. Бұл әрқашан бірнеше командалардың жиынтығы болады. Егер сізде дайын командалар жиынтығы бар скрипт болса, сіз серверге қосылып, осы скриптті орындайсыз. Сол кезде барлық командалар ретімен орындалып, серверіңізде жаңарту аяқталады. Солай әр серверге қосылу қажет. Ал енді елестетіңіз, сізде үш емес, 300 сервер бар. Мұны қолмен істеу мүмкін емес дерлік, сондықтан бізге бұл процесті автоматтандыратын шешім қажет. Мұндай жағдайда бізге AWS көмекке келеді. SSM деп аталатын дайын сервис бар — AWS Systems Manager. Оның мақсаты — серверлеріміздің операциялық жүйесінде орындалатын әрекеттерді автоматтандыру. AWS Systems Manager үшін 3 сервер немесе 300 сервер болсын — бәрібір, ол барлығымен жұмыс істей алады. Одан да маңыздысы — бұл сервис тек AWS ішіндегі EC2 инстанстарды ғана емес, сонымен қатар локалды серверлерді де қолдайды. Яғни, біз гибридті инфрақұрылымның екі бөлігінде де операциялық жүйемен байланысты процестерді автоматтандыра аламыз. AWS Systems Manager-ды қалай баптаймыз? Бірінші қадам — серверлерге SSM Agent орнату. SSM Agent орнатылғаннан кейін, AWS Systems Manager осы агентпен бірге барлық қажетті әрекеттерді орындай алады. Слайдтың төменгі бөлігінде AWS Systems Manager сервисінде бар барлық ішкі сервистер көрсетілген. Әрқайсысын жеке қарастырайық. Бірінші — Run Command. Бұл SSH немесе Windows үшін RDP қосылымына балама ретінде жұмыс істейді. Біз SSH және RDP протоколдары бойынша порттарын толықтай жаба аламыз. Дегенмен, SSM Agent дұрыс орнатылса, Run Command арқылы кез келген команданы орындауға болады. Бұл команда SSM Agent-ке тікелей ішкі протоколдар арқылы қосылады. Бұл жағдайда бізге Bastion Host баптаудың да қажеті жоқ. Келесі — Maintenance Windows. Бұл функция арқылы біз әр серверге жаңартулар үшін қауіпсіз уақыт аралықтарын орната аламыз. Сіз бұл терезелерді бір рет орнатасыз және кейінгі автоматтандыруларда осы уақыт аралықтары есепке алынады. Келесі — Parameter Store. Бұл сервис құпия ақпаратты сақтау үшін қолданылады. Мысалы, құпиясөздер, API кілттері, лицензиялар және т.б. Бұл деректер қауіпсіз түрде сақталады, ал қолданбалар ол жерден қажетті деректерді алады. Осылайша, кодта немесе басқа жерлерде бұл деректерді сақтау қажет емес. Олар сенімді және қауіпсіз түрде осы сервисте сақталады. Келесі — Patch Manager. Бұл сервис патчтарды автоматты түрде орнатуға көмектеседі. Бұл қауіпсіздік патчтары немесе басқа жаңартулар болуы мүмкін. Келесі — State Manager. Бұл біздің серверлерімізді алдын ала белгіленген күйде ұстап тұруды автоматтандыруға көмектеседі. Келесі — Automation. Бұл арқылы біз workflow құра аламыз — яғни бір-бірімен байланысты әрекеттер тізбегі, жетілдірілген автоматтандыруды орнатуға көмектеседі. Келесі — Session Manager. Бұл SSH немесе RDP арқылы Shell-ге қосылуға толық балама. Бірақ бұл жағдайда бәрі AWS Management Console ішінде орындалады. Shell сол жерде ашылады және командаларды енгізе аласыз. Келесі — Inventory. Бұл сервис автоматты түрде инстанстар метадеректерін жинап, серверлерді түгендеуге мүмкіндік береді. Соңғысы — Documents. Documents — бұл Systems Manager мен оның ішкі сервистері орындай алатын әрекеттердің жиынтығы. Олар осы әрекеттерді workflow ретінде біріктіреді. Automation-нан айырмашылығы — мұнда дайын құжаттар өте көп және оларды бірден қолдануға болады. Олардың кейбіреулері тіпті өз параметрлеріңізді енгізуге мүмкіндік береді, яғни бірден қолдануға дайын. Бұл құжаттар JSON немесе YAML форматында жазылады. Енді сізде сұрақ туындауы мүмкін: AWS CloudFormation мен AWS Systems Manager арасында қандай айырмашылық бар? Біз оларды бірге қолдануымыз керек пе, әлде біреуін ғана таңдауымыз керек пе? AWS CloudFormation — бұл инфрақұрылымды templates жазу арқылы автоматты түрде орнатуға мүмкіндік беретін сервис екенін біз білеміз. Яғни, біз мәтін жазамыз, оны сервиске ұсынамыз, ал сервис осы құжатқа сүйеніп, қажетті ресурстарды жасайды. Мысалы, бір ғана template арқылы барлық желілік ресурстарды құруға болады. Сосын сол template-те немесе басқасында EC2 инстанстар, лямбда функциялар, дерекқорлар секілді қолданба ресурстарын құруға болады. Ал AWS Systems Manager серверіміздің ішіндегі операциялық жүйе деңгейіндегі автоматизацияны қамтамасыз етеді. Сондықтан бұл екі сервис бір-бірін толықтырып, бірге қолданылады. Тағы бір автоматтандыруға көмектесетін сервис — AWS OpsWorks. AWS OpsWorks — бұл Configuration Management Service, ол Chef пен Puppet-ті қолдайды. Chef және Puppet — кеңінен қолданылатын автоматтандыру платформалары, олар әдетте қолданба деңгейін (Application Layer) басқаруға пайдаланылады. AWS OpsWorks осы құралдармен интеграцияланып, сіз Chef немесе Puppet рецептеріңізді AWS ішінде де қолдана аласыз. AWS OpsWorks үш түрінде ұсынылады: егер сіз Chef қолдансаңыз, онда AWS OpsWorks for Chef Automate немесе AWS OpsWorks Stacks. Ал егер Puppet қолдансаңыз, онда AWS OpsWorks for Puppet Enterprise. Енді логикалық сұрақ туындайды: AWS OpsWorks-ті ме, әлде AWS Systems Manager-ді ме қолданған дұрыс? Екі негізгі себеп бар, соған байланысты OpsWorks таңдалады, ал қалған жағдайларда AWS Systems Manager ұсынылады. Ендеше сол себептерді қарастырайық. Бірінші — егер сізде Chef немесе Puppet үшін дайын рецептер болса, онда AWS OpsWorks қолданған тиімді. Екінші — болашақта сіздің инфрақұрылымыңыз гибридті болады деп білсеңіз (бір бөлігі бұлтта, бір бөлігі жергілікті желіде). Немесе multicloud — яғни бірнеше бұлт провайдерін қолдансаңыз. Ондай жағдайда барлық платформалармен жұмыс істей алатын әмбебап құралдар қажет болады. Chef және Puppet осы мақсатқа өте қолайлы, сондықтан мұндай жағдайда да AWS OpsWorks ұсынылады. Бірақ қалған барлық жағдайларда AWS Systems Manager-ді қолданған дұрыс, өйткені ол — AWS-тің нативті шешімі. Нативті шешім болғандықтан, ол жақсы интеграцияланған және AWS ішінде көбірек мүмкіндіктер береді. Енді AWS OpsWorks Stacks қалай жұмыс істейтінін толығырақ қарастырайық. Бұл модельде қосымша бір-бірімен байланысты бірнеше деңгейден (layer) тұратын stack ретінде қарастырылады. Бұл мысалда бізде жүктемені теңестіру деңгейі, қолданба серверлері деңгейі және дерекқорлар деңгейі бар. Барлығы бірігіп stack құрайды және осы stack AWS OpsWorks Stacks арқылы басқарылады. Енді AWS Systems Manager мен AWS CloudFormation-ға ұқсас, бұл сервиспен де біз біреуін ғана қолданамыз ба, әлде бірге ме — соны талдайық. Негізінде, AWS OpsWorks Stacks — бұл AWS CloudFormation-ды толықтырады. CloudFormation инфрақұрылымды құруға арналған, ал OpsWorks — application layer орнатуға арналған. Тіпті AWS OpsWorks-тің өзін CloudFormation template арқылы орнатуға болады. Осылайша бізде екі template болады: біріншісі – инфрақұрылымды орнатуға арналған AWS CloudFormation template, екіншісі – AWS OpsWorks Stacks орнатуға арналған AWS CloudFormation template. Содан кейін AWS OpsWorks Stacks арқылы біз өзіміздің application деңгейімізді басқаратын боламыз. Осылайша біз төртінші секцияны аяқтадық және мұнда AWS Systems Manager және AWS OpsWorks сервистерін толығырақ қарастырдық. Біз бесінші, соңғы секцияға жеттік және енді AWS Elastic Beanstalk сервисін егжей-тегжейлі қарастырамыз. Біз көптеген сервистерді қарастырдық, олардың бірқатары автоматизацияға көмектеседі. Сонда сізде сұрақ туындайды: «Жақсы, мұның бәрі қызық, мен инфрақұрылымды да, қолданба деңгейін де автоматтандыруға болатынын түсіндім. Бірақ мен шағын кәсіпкермін, менде шағын ІТ-команда бар және AWS-ті жақсы білетін мамандар жоқ. Сондықтан бұлтта ІТ-инфрақұрылым құру мен үшін және менің командам үшін қиын. Сонымен қатар, осы инфрақұрылыммен жұмыс істеу уақытты алады, ал бұл уақытты шын мәнінде ІТ-өнім жазуға жұмсауға болар еді». Бұдан бөлек, тәжірибе жетіспеуіне байланысты, AWS бұлтындағы инфрақұрылымыңыз тиімді емес түрде бапталған болуы мүмкін. Сонда сұрақ туындайды: «Бұл мәселелерді шешуге көмектесетін сервис бар ма?» AWS-тің жауабы: иә, біз мұны да автоматтандыра аламыз. AWS Elastic Beanstalk — бұл сіздің веб-қосымшаңызды хостингке орналастыруға арналған сапалы ІТ-инфрақұрылымды тез әрі оңай жасауға көмектесетін сервис. Осылайша сіз өзіңіздің веб-сайтыңыздың, веб-қосымшаңыздың кодын жазуға шоғырланасыз. Ал AWS Elastic Beanstalk барлық қалғанын өз мойнына алады: инфрақұрылымды орнату мен конфигурациялау, қолданбаларды орнату, трафикті теңестіру, автоматты масштабтау, серверлер мен қолданбаның күйін бақылау, лог жүргізу және troubleshooting. Яғни бұл веб-қосымшаларды хостингке орналастыруды жеңілдететін арнайы сервис және AWS Elastic Beanstalk үшін қосымша төлем алынбайды. Сіз тек пайдаланылған ресурстар үшін және нақты қандай ресурстар құрылған болса, тек солар үшін ғана төлейсіз. Осы слайдта қандай бағдарламалау тілдері қолдау табатынын көріп тұрсыз: Java, .NET, PHP, Node.js, Python, Ruby, Go және Docker. Бұл тізім үнемі жаңартылып отырады. Сондай-ақ, веб-серверлерге келетін болсақ, бұл — Apache, NGINX, Passenger, Puma және Microsoft Internet Information Services (IIS). Бұл автоматтандыруға болатын құралдардың кең жиынтығы және сіз шынымен де өзіңіздің веб-қосымшаңызға көңіл бөле аласыз. Elastic Beanstalk ортасын баптау кезінде сізге бірнеше сұрақ қойылады. Осы сұрақтарға берген жауаптарыңызға байланысты, Elastic Beanstalk қандай инстанстарды құру қажет, Load Balancing пен Auto Scaling қажет пе, лог жүргізу деңгейі қандай, дерекқор деңгейі қажет пе, қанша Availability Zone қолданылады — соның бәрін өзі шешеді. Яғни сіздің жауаптарыңызға сүйене отырып, Elastic Beanstalk қажетті ресурстарды өзі орнатып, баптайды. Осылайша AWS бізге бірнеше сервис ұсынады, олар өзара алмастырылатын және сізге қаншалықты бақылау немесе ыңғайлылық қажет екеніне байланысты таңдалады. Мысалы, егер сізге толық бақылау қажет болса және бәрін өзіңіз баптағыңыз келсе — AWS CloudFormation мен Amazon EC2 қарастырған жөн. Егер сіз AWS-тің көп бөлігін автоматтандыруын қаласаңыз, онда AWS Elastic Beanstalk, AWS OpsWorks сияқты сервистерге назар аударған жөн. Осылайша біз бесінші және соңғы секцияны аяқтадық, мұнда AWS Elastic Beanstalk сервисін егжей-тегжейлі қарастырдық. Осылайша біз екінші бөлімді де, жалпы AWS бұлтындағы инфрақұрылымды автоматтандыру тақырыбын толығымен аяқтадық. Біз AWS CloudFormation, кейін AWS Systems Manager, AWS OpsWorks және AWS Elastic Beanstalk сервистерін қарастырдық. Осының бәрі — AWS бұлтындағы инфрақұрылымды тиімді басқаруға көмектесетін сервистер. Бұл слайдта сіз қосымша ресурстардың атауларын көресіз, оларды Google-ға енгізсеңіз жеткілікті, бірінші жарнамасыз сілтеме — керектісі. Бүгінгі дәрісті аяқтаймыз. Назар аударғандарыңызға рахмет, кездескенше.
