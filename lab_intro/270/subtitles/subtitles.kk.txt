Қайырлы күн, құрметті студенттер. Зертханалық жұмыстың кезекті шолуына қош келдіңіздер. Бүгінгі зертханалық жұмыстың тақырыбы — AWS бұлтында инфрақұрылым орнатуды автоматтандыру. Ендеше, бастайық. Біз AWS Academy Cloud Architecting курсының басты парақшасынан бастаймыз. Мұнда сол жақтағы навигациялық мәзір арқылы Modules бөлімін таңдау қажет. Содан кейін 10-модульге өтіп, ондағы тапсырмалар тізімінен Challenge Lab тармағын таңдаймыз. Оны басайық — зертханалық жұмыстың басты парақшасына өтеміз. Бұл — зертханалық жұмыстың шолуы болғандықтан, терминал терезесін уақытша жасырып, тапсырманы толық экранда көруімізге болады. Бизнес-кейс бойынша, аспаздық ТВ-шоуға сәтті қатысқаннан кейін, кафе иелері көптеген оң пікірлер мен әртүрлі аймақтардан әріптестік ұсыныстарын алды. Бастапқы кезеңде біз София ретінде әр сервисті қолмен баптағанымызды есімізге түсірейік. Қазіргі уақытта бізде AWS-тің бір аймағында жұмыс істеп тұрған IT-инфрақұрылым бар. Енді келесі міндет тұр. Біріншіден — IT-инфрақұрылымды автоматтандырып, оны басқа AWS аймақтарына оңай көшіру мүмкіндігін жасау қажет. Бұл зертханалық жұмыста біз AWS CloudFormation сервисімен тығыз жұмыс жасаймыз. Дайын templates қолданамыз, зертханалық тапсырмаға сәйкес оларды толықтырып, stacks құрамыз. Біз желілік ресурстар үшін stack құрамыз, сондай-ақ application layer үшін де. Кейін AWS CodeCommit сервисін қолданамыз — templates нұсқаларын бақылау және осы сервис көмегімен pipeline іске қосу үшін. Pipeline дегенде — бұл AWS CodePipeline сервисі. Оның көмегімен біз templates жаңартылған кезде stacks-ті автоматты түрде жаңартуды баптаймыз — бұл өте ыңғайлы. Соңғы қадам — біз жасаған templates пайдаланып, басқа AWS аймағында жаңа IT-инфрақұрылымды көшіру және құру. Осы слайдта бізде зертханалық жұмысты жеңілдету үшін AWS аккаунтында қандай ресурстар бар екенін көре аласыз. Бірінші кезекте бұл — Environment Cloud9 орнатылған EC2 инстансы. Сондай-ақ CloudFormation templates бар репозиторий бар. Бізде екі pipeline бар: біреуі network layer үшін, екіншісі application layer үшін. Сонымен қатар зертханалық жұмыста қолданатын екі IAM рөлі бар. Естеріңізге саламыз, бұл — Challenge Lab, яғни кейбір қарапайым қадамдар көрсетілмейді және оларды өзіңіз орындауыңыз қажет. Тапсырма сипаттамасында не істеу керектігі тек жалпы түрде ғана беріледі. Бұл зертханалық жұмысқа 90 минут уақыт бөлген жөн. Егер бұл уақыт жеткіліксіз болса, таймерді қайта іске қосуға болады — бұл үшін ұпайдан айрылмайсыз. Қосымша айыппұл салынбайды. Естеріңізде болсын, біз уақытша AWS аккаунтында жұмыс істеп жатырмыз, яғни бұл — құмсалғыш орта, онда тек зертханалық жұмыс үшін рұқсат етілген сервистер ғана қолжетімді. Зертханалық жұмысты бастау үшін экранның жоғарғы оң жақ бөлігіндегі Start Lab батырмасын басыңыз. Қалқымалы терезе ашылады, онда уақытша AWS аккаунтының құрылу барысы көрсетіледі. Аккаунт дайын болғанда тиісті хабарлама шығады, сонда бұл терезені жабуға болады. Содан кейін экранның жоғарғы оң жағындағы AWS батырмасын басу арқылы AWS Management Console-дың басты парақшасына өтеміз. Сол жерден зертханалық жұмысты орындауды бастаймыз. Біз тапсырмалардың бірінші блогына өтеміз. Мұнда AWS CloudFormation сервисін сынап көреміз, себебі София бұл бізге қажет сервис екенін тексергісі келеді. Мысал ретінде біз S3 bucket құрамыз, оған статикалық веб-сайтқа қатысты барлық файлдарды жүктейміз. Содан кейін, AWS CloudFormation көмегімен, Amazon S3-те веб-сайт хостинг функциясын қосамыз. Сонымен, бірінші тапсырманы бастаймыз: мұнда AWS CloudFormation арқылы S3 bucket құрамыз. Ол үшін алдымен Cloud9 ортасына өтуіміз керек. Бірінші кезекте жаңа файл жасауымыз керек. Ол үшін экранның жоғарғы сол жақ бұрышындағы File бөлімін ашып, файлды сақтау қажет. Файлды S3.yaml атауымен сақтаймыз. Файлды сақтаған соң, жетінші қадамнан екі жолды қосу қажет болады. Мұнда біз AWS Template Format Version бөлімін нақты мәнімен қосамыз. Содан кейін, мазмұнсыз Description бөлімін қосамыз және сегізінші қадамға өтеміз. Сегізінші қадамда бізден Resources бөлімін және бір ресурс – S3 bucket құру үшін үш жол қосу сұралады. Ерекше назар аударыңыз — шегіністердің әр деңгейі екі бос орыннан тұрады. Сәйкесінше, егер сізде екі деңгейлі шегініс болса, төрт бос орын жасау керек. Тоғызыншы қадамда Description бөліміне еркін түрде мәтін жазу ұсынылады — бұл біздің template-тің сипаттамасы және ол келесідей естіледі: cafe S3 template. Өзгерістерді енгізгеннен кейін файлды сақтау қажет және енді біз template орнатуға дайынбыз. Ол үшін экранның төменгі бөлігіндегі Bash терминалды қолданамыз. Бірінші команда — aws configure get region, бұл команда бізге AWS CLI client құрылған әдепкі аймақты көрсетеді. Бұрын, еске салсақ, біз AWS Management Console арқылы CloudFormation stack жасаған болатынбыз. CloudFormation stack жасауын AWS CLI арқылы да орындауға болады — соны істейік. Stack жасау үшін оныншы қадамдағы екінші команданы енгіземіз — ол CreateBucket атауымен stack жасайды және ол үшін S3.yaml файлын қолданады. Команданы іске қосқанда, жауап ретінде JSON қайтарылуы керек, онда StackId болады. Егер JSON қайтпаса, онда қате болуы мүмкін. Алдыңғы қадамдарды қайта қарап, қатені табуға тырысыңыз. Енді диаграмма түрінде не істегенімізге көз жүгіртейік. Біз EC2 инстансында, нақты айтқанда Cloud9 ортасында жұмыс істеп отырмыз және онда CloudFormation template жасадық. Одан кейін AWS CLI командасын қолданып, бұл template-ті AWS CloudFormation сервисіне жібердік. AWS CloudFormation бұл template-ті қабылдап, жаңа stack атауын алып, оны жасады. Бұл жаңа stack аясында біздің template-ке сәйкес, S3 bucket ресурсы құрылды. Команданы іске қосқаннан кейін, AWS Management Console-ды ашу ұсынылады. Содан кейін AWS CloudFormation сервисіне өтіп, CreateBucket stack құрылғанына көз жеткіземіз. Сондай-ақ Events, Resources, Outputs және Template қойындыларын қарау қажет. Егер stack сәтті құрылғанына көз жеткізсек, S3 сервисіне өтіп, біздің bucket шынымен құрылғанын тексереміз. Жақсы, егер bucket көрінсе — бәрін дұрыс жасадық деген сөз. Енді зертханалық жұмыстың басты парақшасына оралып, Details батырмасын басу қажет. Ашылатын тізімнен Show батырмасын басып, ашылған терезеде Access to Multiple Choice Questions сілтемесін таңдаймыз. Сұрақтар тізімі ашылады және бізге алғашқы үш сұраққа жауап беру қажет. Бірінші сұрақ келесідей: CloudFormation Template көмегімен құрылған S3 bucket қандай атауға ие болды? Екінші сұрақ — S3 bucket қай аймақта құрылды және неге? Үшінші сұрақ — біздің CloudFormation Template-тің Resources бөлімінде S3 bucket құру үшін қанша жол код қажет болды? Біз екінші тапсырмаға жеттік. Бұл жерде біз веб-сайт файлдарын S3 bucket-ке көшірумен айналысамыз. Содан кейін CloudFormation Template көмегімен S3 bucket-те веб-сайт хостинг функциясын қосамыз. Ендеше, бастайық. 15-қадамда бізге S3 bucket-ке ашық қолжетімділік орнататын және оған веб-сайт файлдарын жүктейтін командалар жиынтығын іске қосу ұсынылады. Бұл командаларда bucket name деген кілт сөзді AWS Management Console-дегі нақты bucket атауына ауыстыру қажет болады. Бұл слайдта сіз командалар тізімін көріп тұрсыз, олар топтарға бөлінген. Мұндағы мақсат — алдымен веб-сайт файлдарын жүктеу, бұл зертханалық жұмыс аясындағы демо веб-сайт. Келесі қадам — веб-сайтқа жалпыға ортақ қолжетімділікті орнату, соңғы қадам — барлық файлдарды S3 bucket-ке жүктеу. Енді біз CloudFormation Template-пен жұмыс істеуге көшеміз. Ол үшін бізге берілген сілтеме арқылы AWS құжаттамасын ашу керек, сол жақ мәзірден S3 сервисін табамыз. S3 сервисінің астында бірнеше парақша болады, бізді қызықтыратыны — S3 bucket ресурсы. Енді S3.yaml template-ке кейбір өзгертулер енгізуіміз қажет болады. Біріншіден, біз Deletion Policy қосуымыз керек, яғни stack жойылған кезде S3 bucket жойылмауы үшін. Екіншіден, Static website hosting функциясын қосып, негізгі құжат ретінде index.html деп көрсетуіміз қажет. Бұдан кейін CloudFormation template-не Outputs бөлімі қосылып, веб-сайттың URL-і сол жерде Output ретінде көрсетілуі тиіс. Бұл өзгертулерді енгізген соң, S3.yaml файлында барлық өзгертулерді сақтау қажет. Енді template-тің дұрыстығын тексеруіміз керек. 20-қадамда берілген команданы қолданыңыз, егер қате шықпаса — өзгертулер дұрыс енгізілген. Одан кейін stack-ты жаңарту үшін команданы іске қосамыз. Бұл команда 21-қадамда көрсетілген. Мұнда update stack командасы қолданылады. Stack name ретінде бұрынғы create bucket атауы пайдаланылады, ал template body ретінде өзгертілген S3.yaml қолданылады. Енді AWS Management Console-ге өтіп, AWS CloudFormation сервисінен stack күйін тексереміз. Егер статус Update complete болса — бәрі дұрыс жасалған. Егер ондай болмаса, алдыңғы қадамдарға оралып, барлық әрекеттерді дұрыс орындағаныңызды тексеріңіз. Сондай-ақ Events қойындысын қарап шығу ұсынылады. Онда неге қате болғаны туралы нақты түсініктеме көрсетіледі. Бұл ақпаратты template-тегі қателерді түзету үшін қолдана аламыз. Енді барлығы жұмыс істегенін тексерейік. Outputs қойындысын ашып, веб-сайттың URL мекенжайын көшіріп, оны браузердің жаңа қойындысында ашыңыз. Егер сіз өз қосымшаңызды көрсеңіз — құттықтаймын, бәрі дұрыс орындалды. Егер жоқ болса — уайымдамаңыз, біз troubleshooting процесін бастаймыз, яғни ақауларды іздеу. Бірінші кезекте S3 bucket-тің ішінде барлық веб-сайт файлдарының бар-жоғын тексеріңіз. index.html файлына, сондай-ақ css және images папкаларына назар аударыңыз. Егер бәрі орнында болса, index.html файлына қолжетімділікті тексеріңіз. Қолжетімділік барлық пайдаланушылар үшін жалпыға ортақ болуы керек, яғни оқу операциясы үшін public access. Егер бұл да дұрыс болса, енді bucket баптауларын тексеру қажет. Properties қойындысын ашып, ең соңына дейін айналдырып, Static website hosting функциясы қосылғанына көз жеткізіңіз. Егер мұнда да бәрі дұрыс болса, соңғы қадам — дұрыс команданы іске қосқаныңызды тексеру, яғни update stack орнына create stack енгізіп қойған жоқсыз ба — соны қарау керек. Сондықтан командаға назар аударыңыз және оны тағы бір рет орындап көріңіз. Мұнда шағын ескерту бар: сіз байқаған боларсыз, біз веб-сайт файлдарын AWS CLI арқылы қолмен көшірдік. Болашақта бұл да автоматтандырылуы мүмкін. Бұл зертханалық жұмыс аясында біз осы қадамды оңайлаттық, яғни веб-сайт файлдарын S3 bucket-ке көшіруді, себебі басты назарымыз CloudFormation сервисінде. Біз бизнес-кейстің екінші сынағына келдік. Софияның командасы бір ғана template-пен бүкіл AWS инфрақұрылымын басқаруға болатынына таңғалды. Бұл сиқыр емес, бұл арнайы құрал, ол инфрақұрылыммен жұмысты жеңілдетуге көмектеседі. Енді олар осы идеяға қызығып, барлық қалған ресурстарды да соған көшіруді қалайды. Бірақ бұған дейін олар Матеодан кеңес алып, нұсқаларды бақылау жүйесін пайдалану керектігін түсінеді. AWS жағдайында бұл — AWS CodeCommit сервисі. Алдағы тапсырмаларда біз бар репозиторийді Cloud9 ортаға көшіру процесімен айналысамыз. Үшінші тапсырманы бастаймыз: енді біз AWS CodeCommit сервисіндегі бар репозиторийлерді IDE Cloud9-ға көшіреміз. Бірінші кезекте AWS Management Console-да AWS CodeCommit сервисін ашу керек. Онда CFTemplatesRepo атты жалғыз репозиторий болады — соны ашыңыз. Оны ашқан соң, Templates деген папка бар екенін көреміз — соны ашып, ішін қарастырайық. Бұл папкада бірнеше CloudFormation template файлдары орналасқан. Бізге керегі — start-lab.yaml файлы, оны ашып, мазмұнымен танысайық. Бұл template арқылы бірнеше ресурс жасалады, оның ішінде Cloud9 instance және біз отырған CodeCommit репозиторийі де бар. Әрине, бұл уақытша AWS аккаунтын инициализациялауға арналған нақты template емес. Ол көлемдірек, бірақ идеясы ұқсас: template жазылады, және зертханалық жұмыс басталғанда сол CloudFormation template іске қосылады. Ол кейін барлық қолжетімділікті реттейді, қажетті ресурстарды жасайды және зертханалық жұмысты бастауға мүмкіндік береді. Енді сол репозиторийді көшіру сілтемесін көшіру қажет. Бұл сілтеме репозиторийлер тізімі парақшасында орналасқан, бізге қажеті — HTTPS сілтеме. Оны көшірген соң, Cloud9 ортаға қайта оралып, Bash терминалын ашып, git clone командасын жазып, URL-ді жапсырамыз. Көшіру аяқталған соң, жасалған папкаға өтіп, git commit командасын іске қосыңыз. Біз main тармағында екеніміз туралы хабарлама аламыз, бұл git репозиторий сәтті көшірілгенін білдіреді. Біз тапсырманың үшінші блогына келдік — мұнда AWS CloudFormation көмегімен екі инфрақұрылым бөлігін орналастырамыз: желілік ресурстар және қолданба қабаты. Бизнес-кейске сай, София templates-ді жиі жаңартатынын түсінеді, ал бұл CloudFormation stack-терін де жиі жаңартуды қажет етеді. Ол Матеодан процесті қалай жылдамдатуға болатынын сұрайды. Матео оған CI/CD құралы бар екенін айтады — бұл AWS CodePipeline, ол бастапқы дереккөз бойынша іске қосылады. Біздің жағдайда дереккөз — CodeCommit репозиторийі, және онда өзгеріс орын алғанда автоматты түрде stack жаңарту процесі басталады. София бұған қуанып, енді осы pipeline-дарды пайдаланып, өз инфрақұрылымындағы желілік және қолданба деңгейлерін жаңартатын болады. Біз төртінші тапсырманы бастаймыз, мұнда желілік ресурстарды жасаймыз. Бастапқыда Cloud9 IDE ортаға кіріп, репозиторийдегі Templates папкасын ашамыз, сол жерден template1.yaml файлын ашамыз. Бұл файлды көшіруіміз керек және оның негізінде жаңа құжат жасаймыз. Жаңа құжаттың атауы — cafe-network.yaml болуы тиіс. Бұл әрекетті орындаған соң, жаңадан жасалған файлды ашып, Description бөліміне "Network layer for the cafe" деген сипаттаманы қосайық. Сондай-ақ ресурстар бөліміне назар аударыңыз, онда біздің network layer-ге қатысты 7 ресурс жасалады. Енді AWS Management Console ішіндегі AWS CodePipeline сервисіне өтуіміз қажет. Бұл сервисті ашқан соң, pipeline тізімі бар парақшаға өтеміз. Біздің зертханалық жұмысымыз аясында екі pipeline алдын ала жасалған — біреуі application layer үшін, екіншісі network layer үшін. Сіз сондай-ақ олардың күйі Failed екенін байқайсыз, бұл күтілетін жағдай, себебі екеуі де өз атауына сәйкес template-терге сілтеме жасайды. Файлдар көзі әлі жасалмағандықтан, олар қате беріп жұмысын тоқтатты. Енді біз дұрыс аталған template-терді жасап, pipeline-дарды іске қосамыз. 31-қадамда бізге Network pipeline-ды ашу ұсынылады. Ашқан соң, біз екі деңгейлі екі қадамды көреміз. Бірінші қадам — Source, егер нақтырақ қарайтын болсақ, бұл жерде Source action ретінде AWS CodeCommit пайдаланылады. Ақпарат белгішесіне басайық. Мұнда осы қадамның параметрлерін көреміз — CFTemplatesRepo атты репозиторийге қосылғанымызды және қай тармаққа (branch) байланысты екенімізді көре аламыз. Сондай-ақ, қай файл stack-ті орналастыру үшін пайдаланылатыны да көрсетілген. Керемет, енді қалқымалы терезені жабу үшін Done батырмасын басып, pipeline-ның келесі деңгейіне өтеміз. Келесі деңгей — Deploy, мұнда сервис ретінде AWS CloudFormation көрсетілген. Ақпарат белгішесін бассақ, біз update-cafe-network атты stack-ті жаңарту әрекеті орындалатынын және бұл үшін cafe-network.yaml атты template пайдаланылатынын көреміз. Яғни, Source деңгейінен сәйкес YAML файлы алынуы тиіс, және Deploy деңгейі осы template-ті stack жаңартуға пайдаланады. Енді бұл процестің диаграмма түріндегі көрінісіне көз жүгіртейік. Cloud9 IDE ортасында біз репозиторийді көшірдік және онда өзгерістер енгіздік. Бұл өзгерістерді біз репозиторийге push етеміз. Олар AWS CodeCommit сервисіне түседі. CodeCommit — бұл CodePipeline ішіндегі Source, және онда өзгеріс болған жағдайда pipeline автоматты түрде іске қосылады. Source деңгейі барлық файлдарды келесі деңгейге жібереді. Келесі деңгейде қажетті атауы бар YAML файл ізделінеді және сол template stack-ке орналастырылады, бұл үшін тиісті рөл қолданылады. CloudFormation өз жұмысында CustomCFnRole рөлін қолданады, ал CodePipeline — CustomPipelineRole атты IAM рөлін пайдаланады. Deploy деңгейінде CloudFormation жұмыс істеп, stack-ті жасайды немесе жаңартады. Stack жасау немесе жаңарту барысында желілік ресурстар: VPC, subnet, route table, Internet Gateway және басқа да желілік элементтер жасалады. Енді репозиторийімізге өзгеріс енгізу арқылы pipeline-ды триггерлейік — біз жаңа YAML файл, яғни cafe-network.yaml жасадық. Енді Bash терминалда git status командасын орындап, осы өзгерістердің бар екеніне көз жеткізейік. Одан кейін git add командасын және біздің yaml файлының жолын енгіземіз, оны ағымдағы commit-ке қосу үшін. Содан соң біз осы commit-ті бекітеміз, git commit -m командасын және commit хабарламасының мәтінін орындаймыз. Одан кейін git status командасы арқылы commit-тің әлі қашықтағы репозиторийге жіберілмегенін тексере аламыз және git push командасымен оны жібере аламыз. Енді, егер біз AWS Management Console ішіндегі pipelines тізімін ашсақ, CafeNetworkPipeline іске қосылғанын және қазіргі кезде In progress күйінде екенін көреміз. Бірнеше минуттан кейін ол толығымен орындалып, Source және Deploy деңгейлері Succeeded күйінде көрсетіледі. Бұл біз stack-ті сәтті жасағанымызды білдіреді. Егер олай болмаса, төменде қайта тексеруге болатын ұсыныстар тізімі берілген. Немесе алдыңғы қадамдарға оралып, оларды қайта орындап көруіңізге болады. Егер бәрін дұрыс орындасақ, AWS CloudFormation сервисіне өтіп, update-cafe-network stack-тің бар екенін көре аламыз. Сондай-ақ оның күйі Create complete немесе Update complete екенін көреміз. Жақсы, құттықтаймын! Барлығын дұрыс жасадыңыз. Қазір Outputs қойындысын ашып, ол жерде ешқандай output жоқ екенін көресіз, бірақ келесі тапсырмаларда оны қосамыз. Сондай-ақ VPC сервисіне өз қалауынша өтіп, ресурстардың сәтті жасалғанын тексере аласыз: VPC, subnet, Internet gateway және т.б. Біз бесінші тапсырманы бастаймыз және мұнда біз network stack-ті жаңартамыз. Ол үшін Cloud9 IDE-ге қайта оралу қажет. Сонда cafe-network.yaml файлын ашып, yaml файлымызға келесі мәтінді енгіземіз, яғни біз екі output параметрін қосамыз — бұл public subnet ID және VPC ID. Назар аударыңыз, әрбір output параметрі үшін Description және Value қасиеттерінен бөлек, Export мәнін де көрсетеміз. Бұл дегеніміз — Export name арқылы басқа stacks біздің output параметрлеріміздің мәнін өзіне тарта алады, яғни public subnet ID мен VPC ID. Осы әрекеттерді орындағаннан кейін, өзгерістерді сақтау және оларды CodeCommit репозиторийіне push ету қажет. Одан соң pipeline автоматты түрде триггерленетінін көресіз. Кейін stack жаңарту процесі іске қосылады және ол аяқталғаннан кейін парақшаны жаңартып, Outputs қойындысын ашамыз және онда екі output параметрі қосылғанын көреміз — бұл public subnet және VPC id. Міне осындай біз күткен өзгерістер болады. Егер бәрі осылай болса, онда бәрін дұрыс жасадыңыз, келесі тапсырмаға көше аламыз. Біз алтыншы тапсырмаға жеттік, оның аясында EC2 instance ресурстарын біздің template-ке қосамыз, содан кейін сол template-тен application stack құрамыз. Бірінші кезекте Cloud9 IDE-ге қайта оралып, template2.yaml файлының көшірмесін жасап, оны cafe-app.yaml деп атаймыз. Оны жасағаннан кейін, жаңа файлды ашып, оның мазмұнын қарап шығайық. Бізде бірнеше параметр бар, бірінші — бұл LatestAmiId, ол EC2 instance жасаған кезде соңғы AMI ID таңдауға мүмкіндік береді. Одан кейін CafeNetworkParameter параметрі бар. Бұл жерде біз network stack-тің атын сақтаймыз, оның әдепкі мәні көрсетілген. Кейін Mappings бөлімі бар, ол RegionMap деп аталады, мұнда біз EC2 instance баптауларына аймаққа байланысты key pair атын қоямыз. Одан кейін бізде бір ресурс бар — бұл EC2 instance үшін қауіпсіздік тобы, ол 80 және 22 порттары бойынша кіріс трафикке рұқсат береді. Сондай-ақ security тобы тиісті VPC ішінде жасалып жатқанына назар аударыңыз. Біз дәл осы VPC-ті қайдан алдық? Дұрыс, біз network stack-тегі output параметрін, яғни оның Export name-ын пайдаландық. Одан кейін бізде Outputs параметрі бар — бұл WebServerPublicIP. Яғни бұл — біздің EC2 instance-тің жалпыға ортақ IP-мекенжайы, оны біз өз қосымшамызға өту үшін қолданамыз. Алдымен үшінші параметрді жасауымыз керек, бұл параметрде біз EC2 instance түрін сақтаймыз. Сілтеме арқылы template-ті көшіріп, кейбір өзгерістер енгізе аламыз. Рұқсат етілген инстанс түрлеріне t2.micro, t2.small, t3.micro және t3.small көрсетеміз, ал әдепкі мән ретінде t2.small таңдаймыз. Жақсы, параметрді жасадық, енді EC2 instance ресурсымызды жасауға көше аламыз. Сілтемені қолданып, оны браузердің жаңа қойындысында ашайық. Бұл EC2 instance ресурсын жасау сипаттамасы бар парақша, оған біз өз ресурсымызды жасау барысында қайта-қайта оралып отырамыз. Сонымен, ресурстың Logical ID атауы ретінде CafeInstance деп көрсетеміз. Одан кейін Properties бөлігін толтырамыз. ImageId ретінде LatestAmiId параметрінің мәнін көрсетеміз, instance түрі ретінде біз жаңа жасаған параметр мәнін көрсетеміз, Key name ретінде келесі жолды жазамыз. Мұндағы идея — біз RegionMap кестесін қолданамыз, оған ағымдағы аймақты береміз, осылайша әр аймақ үшін сәйкес key pair атауын аламыз. Келесіде Instance Profile ретінде CafeRole көрсетеміз, бұл рөл бұрыннан бар, сондықтан оны жеке жасаудың қажеті жоқ. Одан кейін Properties бөліміне келесі код жолдарын көшіріп енгізуіміз қажет, олар EC2 instance-ті қажетті subnet ішінде жасауға мүмкіндік береді. Содан соң тегтер жасауымыз керек, Key ретінде name, ал Value ретінде Cafe Web Server көрсетеміз. Тегтер жасау үлгісін template ішіндегі security group ресурсынан көре аласыз. Соңғысы — User data өрісін толтыруымыз керек, дайын командалар жиыны бар, оны көшіріп қою қажет. Бұл командалар веб-сервер мен PHP сияқты қажетті бағдарламаларды орнатады, демо-қосымшаны жүктейді, оны орнатып, веб-серверді іске қосады. Жақсы, біз CloudFormation template-іне барлық қажетті өзгерістерді енгіздік. Енді осы template-ті валидациядан өткізу қажет. Дайын команда 45-қадамда көрсетілген, егер қате шықпаса, келесі қадамға өте аламыз. Енді өзгерістерді git репозиторийіне сақтап, оларды push етуіміз керек. Біз мұны орындаған соң, AWS Management Console ішінде сәйкес pipeline іске қосылады. Ол іске қосылады, Deploy қадамы орындалады, ол өз кезегінде жаңа stack-ті жасауды бастайды, оның атауы update-cafe-app болады, бұны AWS CloudFormation сервисінде тексеруге болады. Біраз күтейік, CloudFormation stack Create Complete күйіне өтеді. Содан кейін pipeline парақшасында да екі қадам Succeeded күйіне өтеді. Бұл біз stack-ті сәтті жасадық дегенді білдіреді, және ресурстарымыз да сәтті құрылды. Мұны тексеру үшін EC2 сервисіне өтіп, сервердің жасалғанын тексереміз. Егер EC2 instance тізімінде біздің серверді көретін болсақ, құттықтаймын, бәрін дұрыс жасадыңыз. Қалған тек бір қадам қалды — веб-қосымшамыздың сәтті іске қосылатынын тексеру. Ол үшін EC2 instance барлық жүйелік тексерістерден өткенше күтуіміз қажет — яғни 2-ден 2 тексеріс, парақшаны мезгіл-мезгіл жаңартып отыру керек, шамамен екі минуттан кейін бәрі дайын болады. Сосын EC2 instance-тің жалпыға ортақ IP-мекенжайын көшіріп, соңына /cafe деп қосамыз. Айта кетейін, біз stack ішінде осы IP-мекенжайды көрсететін output параметрін жасадық. Бұл URL-ді алуға болатын екінші орын. Сонымен, қосымшаны ашып көрейік. Егер қосымшаны көретін болсақ — жақсы, құттықтаймын! Бұл тапсырманы сәтті орындадыңыз және бүкіл инфрақұрылымды, яғни network layer мен application layer-ді толықтай AWS CloudFormation көмегімен орнаттыңыз. Енді қалған үш сұраққа жауап беруіміз қажет. Төртінші сұрақ: update-cafe-app stack-тің Parameters қойындысын ашып, LatestAmiId параметрінің мәнін айтып беріңіз. Бесінші сұрақ: update-cafe-app stack-тің Stack info қойындысын ашып, IAM рөлінің ARN-ін табыңыз. Естеріңізге сала кетейін, бұл — CloudFormation stack-терін жасау және жаңарту құқықтарын беретін IAM рөлі. Ал алтыншы, соңғы сұрақ — AWS Management Console ішінен AWS CodeCommit сервисін ашыңыз, репозиторийімізді ашып, сол жақтағы навигациямен commits тізімін ашыңыз, ұнаған commit-ті таңдаңыз. Сұрақ: белгілі бір commit-ті ашқан кезде сіз не көресіз? Біз тапсырмалардың соңғы блогына жеттік, мұнда біз бұрын жасаған CloudFormation templates-ті пайдаланып, өзіміздің IT-инфрақұрылымымыздың толық көшірмесін басқа AWS аймағында жасаймыз. Бизнес-кейс бойынша, София мен оның командасы өте қуанышты, олар қажетті templates дайындап қойды. Енді олар өздерінің IT-инфрақұрылымының көшірмесін басқа AWS аймағында жасап көргісі келеді. Олар бұл процестің өте жылдам болатынын түсінеді, ешқандай адам араласусыз, тек AWS Management Console-де бірнеше батырма басу арқылы. Сонымен, біз жетінші тапсырманы бастаймыз, Oregon аймағында Network және Application Layer инфрақұрылымын жасаймыз. Бұрын біз AWS CLI арқылы stack-терді жасап және жаңартып отырған едік. Жаңа аймақта pipeline-дар жасалмаған, сондықтан бір stack-ті CLI командасымен, ал екінші stack-ті AWS Management Console арқылы жасаймыз. Бірінші кезекте Cloud9 IDE-ге оралып, келесі команданы іске қосу қажет. Бұл команда update-cafe-network деген жаңа stack жасайды, cafe-network.yaml файлын пайдалана отырып, бірақ аймақ ретінде us-west-2 көрсетіледі. Нәтижесінде біз JSON жауабын аламыз, онда Stack ID көрсетіледі. Егер осылай болса, команда сәтті орындалды деген сөз. Енді AWS Management Console-ге оралып, аймақты Oregon (немесе us-west-2) деп ауыстырамыз. Сосын CloudFormation stack тізімінен update-cafe-network stack бар екеніне көз жеткіземіз. Одан кейін біраз уақыт күтіп, stack күйінің Create Complete болғанын күтеміз. Жақсы, енді қажетті желілік ресурстардың сәтті жасалғанын тексереміз. Ол үшін VPC сервисіне өтіп, аймақты Oregon деп ауыстыруды ұмытпаңыз. Енді Application Layer жасауды бастауға болады. Ол үшін алдымен жаңа key pair жасау қажет. Key pair жасау үшін EC2 сервисіне өтіңіз. Аймақтың дұрыс екенін тексеріңіз — Oregon аймағы болу керек. Сол жақтағы навигацияны пайдаланып, Key Pairs тармағын таңдаңыз, ашылған парақшада Create Key Pair батырмасын басыңыз, атауы ретінде cafe-oregon енгізіңіз де, жасаңыз. Содан соң Cloud9 IDE-ге қайта оралып, cafe-app.yaml файлын ашыңыз және онда RegionMap mapping бөлігін тексеріңіз. Oregon аймағы үшін көрсетілген Key Pair аты — жаңа ғана жасаған кілтке сәйкес келуі тиіс. Егер солай болса — бәрі дұрыс. Енді Application Stack жасауды бастауға болады. Бұрын айтқанымыздай, бұл stack-ті AWS Management Console арқылы жасаймыз, ол үшін template-імізге қолжетімділік беруіміз керек. Бір нұсқа — template-ті S3 bucket-тердің біріне жүктеу. Ол үшін арнайы жасалған бакетті қолданамыз. Атауы ішінде repobucket-bucketname деген мәтін бар S3 бакетті табыңыз. Атауын көшіріп, 57-қадамдағы командаға қойыңыз. Бұл команда cafe-app.yaml файлын бакетке көшіреді. Содан соң бакетті ашып, жаңа объект парақшасына өтеміз, яғни біздің template, URL мекенжайын көшіріп аламыз. Оны CloudFormation Stack жасау кезінде пайдаланамыз. Енді AWS CloudFormation сервисіне өтуге болады. Барғаннан кейін аймақтың Oregon екенін қайта тексеріңіз. Сосын Create Stack батырмасын басыңыз. Ашылған парақшада Amazon S3 URL опциясын таңдаңыз. Тиісті өріске көшірілген объект URL мекенжайын қойып, келесі парақшаға өтіңіз. Келесі парақшада Stack Name ретінде қалаған атауыңызды енгізіңіз, ал Instance Type Parameter үшін t3.micro деп көрсетіңіз. Мұнда біз parameters және mappings көмегімен инстанс түрлері мен ресурстарды өзгертеміз, ал template-тің өзін өзгертпейміз — бұл өте ыңғайлы. Барлық параметрлерді толтырғаннан кейін stack жасауға болады. Stack сәтті жасалғанын күту қажет. Одан кейін EC2 инстанс барлық жүйелік тексерістерден өткенін күтіңіз. Дайын болған соң оның жалпыға ортақ IP-мекенжайын көшіріп, соңына /cafe деп қосыңыз және қосымшаны ашыңыз. Қосымша ашылған кезде EC2 инстанс туралы ақпарат көрсетіледі. Инстанстың ID-і, IP-мекенжайы және аймағы көрсетіледі. Егер бәрі дұрыс болса, аймақ ретінде us-west-2 көресіз. Егер солай болса, құттықтаймын — біз жаңа AWS аймағында өзіміздің IT-инфрақұрылымымыздың көшірмесін сәтті орнаттық, бар болғаны бірнеше әрекетпен, ешқандай ресурсты қолмен құрмай-ақ. Және бәрі дұрыс жұмыс істеп тұр. Бизнес-кейс бойынша, біз кафеден жаңалық аламыз. София өте қуанышты, ол AWS CloudFormation сервисімен танысқанына риза. Сонымен қатар ол AWS CodeCommit және AWS CodePipeline сервистерімен де танысты. Олардың бәрі бірігіп CI/CD pipeline жасайды және stack-терді басқаруға көмектеседі. Бұл өте ыңғайлы — DevOps автоматтандыруының арқасында инфрақұрылымды жасау және жаңарту қолмен араласусыз өтеді. Енді Софияда көптеген идея бар — ол қосымша тесттік environment жасағысы келеді. Сонымен қатар, ол disaster recovery шешімдерін жасауды жоспарлап отыр, бұны біз келесі зертханалық жұмыстарда орындаймыз. Енді автобағалау скриптін іске қосу қажет. Ол үшін зертханалық жұмыстың басты парақшасына оралып, жоғарғы бөлікте Submit батырмасын басыңыз. Бұл әрекетті растаңыз да, біраз күтіңіз. Көп ұзамай жинаған ұпайларыңыз көрсетіледі, егер көрсетілмесе, жоғарғы оң жақтағы Grades батырмасын басып, бағаларыңызды көре аласыз. Егер жеткілікті ұпай жинасаңыз — құттықтаймын! Егер жоқ болса, қай тапсырмада балл жетіспегенін қарап, сол жерге оралып, түзетулер енгізіп, скриптті қайтадан іске қосуға болады. Енді барлық жүйелерден дұрыс шығу қажет. Ең алдымен бұл AWS Management Console-ге қатысты. Бір қойындыны ғана қалдырып, жоғарғы оң жақта өз атыңызды басып, ашылған мәзірде Sign out батырмасын таңдаңыз. Содан кейін зертханалық жұмыстан шығу қажет. Басты парақшаға оралып, жоғарғы оң жақтағы End lab батырмасын басып, әрекетті растаңыз. Содан кейін зертхана парақшасын жабуға болатыны туралы хабарлама шығады. Себебі уақытша AWS аккаунтын жою процесі басталды. Осылайша зертханалық жұмыстың шолуы аяқталды. Назарларыңызға рахмет, келесі белсенділіктерде кездескенше!
