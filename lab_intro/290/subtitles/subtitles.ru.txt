Добрый день, уважаемые студенты. Я рад вас всех видеть на очередной сессии обзора лабораторной работы. Тема сегодняшней лабораторной работы — это стриминг динамического контента с использованием сервиса Amazon CloudFront. Итак, давайте начнем. Начинаем мы с главной страницы курса Cloud Architecting в AWS Academy. Здесь нам необходимо воспользоваться навигационным меню слева и выбрать пункт Modules. В списке модулей нас интересует 11-й модуль Caching content и здесь есть активность Guided Lab. Давайте на нее нажмем и перейдем на главную страницу лабораторной работы. Здесь, как мы видим, есть два окна — окно с заданием лабораторной работы и терминал. Терминал в рамках обзора лабораторной работы нам не нужен, поэтому мы его можем скрыть. В этой лабораторной работе мы с вами закэшируем динамический контент, используя сервис Amazon CloudFront. Контентом в нашем случае будет выступать мультибитрейтный стрим в формате HLS. Этот стрим можно будет открыть в любом браузере из смартфона. Также мы познакомимся с сервисом Amazon Elastic Transcoder для того, чтобы наше готовое видео перевести в формат HLS с несколькими битрейтами. В конце этой лабораторной работы мы получим следующую архитектуру в облаке AWS. В самом начале мы загружаем наш готовый MP4-файл с видео в S3 бакет. Далее используем этот S3 бакет как источник в сервисе Amazon Elastic Transcoder. После конвертации нашего MP4-файла в формат HLS, готовые файлы мы загрузим во второй S3 бакет. Далее CloudFront будет использовать второй S3 бакет как источник для стриминга динамического контента на смартфоны пользователей. Всего на выполнение этой лабораторной работы рекомендуется выделить 30 минут. Напоминаю, что мы работаем во временно созданном AWS аккаунте в рамках этой лабораторной работы, поэтому не все сервисы будут доступны. Мы будем ограничены только теми сервисами, которые используются в этой лабораторной работе. Для того, чтобы начать выполнение лабораторной работы, нам необходимо инициализировать создание временного AWS аккаунта. Для этого в верхней правой части экрана необходимо нажать на кнопку Start Lab. После того, как мы увидим сообщение о готовности AWS аккаунта, мы можем закрыть всплывающее окно и нажать на кнопку AWS, также в верхней правой части экрана возле кнопки Start Lab. Нас направит на главную страницу AWS Management Console. Мы с вами начинаем первое задание лабораторной работы. Здесь необходимо убедиться в наличии AWS ресурсов и файлов для второго задания. Первым делом нам необходимо перейти в сервис S3. Для этого воспользуемся строкой поиска сервисов и начнем вводить S3. В списке выдачи сервис S3 будет первым. Давайте на него перейдем. Далее нам необходимо будет из списка S3 бакетов найти тот, в названии которого содержится awstrainingreinvent. Как только мы ее найдем, необходимо будет ее открыть, чтобы проверить содержимое. Вы увидите, что в бакете есть папка Input. Давайте ее откроем и посмотрим, что есть внутри. Внутри должен быть видеофайл с названием AmazonS3Sample.mp4. Если этого файла там нет, то необходимо будет подождать 10 минут, после чего обновить страницу. Если вы увидели видеофайл, то можете переходить к выполнению следующего задания. Во втором задании нам необходимо будет создать CloudFront Distribution. Мы будем использовать CloudFront Distribution для кэширования и доставки динамического контента, а именно мультибитрейтного видеофайла в формате HLS. Для того, чтобы создать Distribution, нам необходимо в первую очередь перейти в сервис CloudFront. Давайте воспользуемся строкой поиска сервисов и начнем вводить CloudFront. Как только мы перейдем в этот сервис, мы увидим главную страницу этого сервиса. И здесь необходимо будет найти и нажать кнопку Create CloudFront Distribution. Нас направят на страницу создания нового Distribution. Здесь нам необходимо будет в секции Origin Settings внести некоторые изменения. Там, где Origin Domain, необходимо будет открыть список бакетов и выбрать S3 бакет, в названии которого содержится awstrainingreinvent. Далее для поля Origin Access необходимо будет выбрать Public и для поля Web Application Firewall необходимо будет выбрать опцию Do Not Enable Security Protections. Обратите внимание, мы увидим сообщение красным цветом о том, что необходимо заполнить поле Custom SSL Certificate. На самом деле это рекомендация с точки зрения безопасности и заполнение этого поля является опциональным. Поэтому мы в рамках лабораторной работы можем его игнорировать и прокрутить до конца страницы. В самом конце нижней правой части экрана будет кнопка Create Distribution. Давайте на нее нажмем и создадим CloudFront Distribution. Мы с вами переходим к третьему заданию и в этом задании будем настраивать pipeline в сервисе Amazon Elastic Transcoder. Это задание делится на несколько частей. В первой части мы создадим сам pipeline. Для того чтобы это сделать, нам необходимо воспользоваться строкой поиска сервисов и перейти в сервис Elastic Transcoder. Далее необходимо будет перепроверить, что мы находимся в том же регионе, где хранятся данные нашего S3 бакета. Скорее всего это будет North Virginia. Как только мы переключились на нужный регион, нам необходимо будет на странице с pipeline нажать на кнопку Create a new pipeline. Нас направят на страницу создания нового pipeline. Для поля pipeline name укажем InputPipeline. Далее для поля Input bucket выберем S3 bucket, в названии которого есть awstrainingreinvent. Как IAM Role укажем AmazonElasticTranscoderRole. Это специально созданная роль в рамках лабораторной работы, которая предоставляет доступ сервису Elastic Transcoder к нашему S3 bucket. Далее нам необходимо будет прокрутить до следующей секции с длинным названием Configuration for Amazon S3 bucket for transcoded files and playlists. Здесь необходимо будет для поля Bucket выбрать наш S3 bucket и как Storage Class указать Standard. Чуть ниже будет другая секция, называется Configuration for Amazon S3 bucket for thumbnails. Здесь необходимо будет также для поля Bucket выбрать наш S3 bucket и как Storage Class необходимо будет выбрать ReducedRedundancy и прокрутить до конца страницы. В нижней правой части экрана будет кнопка Create pipeline. Давайте нажмем и создадим наш pipeline. Мы с вами переходим ко второй части третьего задания. Здесь будем создавать job. Это как раз таки тот элемент pipeline, который конвертирует наше видео из одного формата в другой. Нам необходимо будет на странице со списком pipelines нажать на кнопку Create new job. Откроется страница создания нового job. Здесь как Pipeline необходимо будет указать InputPipeline. Далее для поля Output key prefix необходимо будет указать output/. Этот префикс будет использоваться для сохранения созданных медиа файлов в S3 бакете. Далее для поля Input key необходимо будет выбрать наш видео файл. Мы с вами продолжаем создание job. Нам необходимо прокрутить до секции ниже и здесь мы будем указывать детали наших битрейтов. Мы в рамках этой лабораторной работы будем создавать три битрейта это 2, 1,5 и 1 мегабайт в секунду. Нам необходимо будет для каждого битрейта открыть новую секцию и в этой секции ввести детали по каждому битрейту. Давайте посмотрим что необходимо будет сделать на примере битрейта с двумя мегабайтами в секунду. Здесь необходимо будет для поля Preset выбрать System preset: HLS 2M, далее как Segment duration указать 10 секунд, как Output key укажем HLS20M. Этот префикс будет использоваться для созданных сегментов. После чего необходимо будет нажать на кнопку Add another output, добавится новая секция и необходимо будет проделать те же действия для пресетов HLS 1,5M и HLS 1M. Мы с вами добрались до последней части третьего задания и здесь укажем настройки плейлиста. Необходимо будет прокрутить до секции Playlists (Adaptive Streaming), далее выбрать Add playlist и внести следующие значения. Для поля Master playlist name укажем primary, далее для Playlist format необходимо будет выбрать HLSv3, чуть ниже необходимо будет также выбрать три наших битрейта настроенные выше. После чего мы можем прокрутить до конца страницы и нажать на кнопку Create new job. Сама job отработает в течение двух минут. Мы с вами добрались до последнего четвертого задания и здесь будем тестировать стрим с динамическим контентом. Для того чтобы его протестировать нам необходим будет любой смартфон. Первым делом нам необходимо будет построить URL. URL состоит из двух частей. Первая часть - это URL нашего CloudFront Distribution, далее нам необходимо будет найти наш S3 bucket и открыть папку, где находятся сгенерированные медиа файлы сервисом Elastic Transcoder. Итак, давайте начнем первую часть. Нам необходимо будет воспользоваться строкой поиска сервисов и перейти в сервис CloudFront. Далее из списка distributions необходимо будет открыть наш distribution, перепроверьте что статус поменялся с In progress на Enabled. После чего нам необходимо будет скопировать distribution URL в текстовый редактор. Теперь нам необходимо получить вторую часть конечного URL. Для этого необходимо воспользоваться строкой поиска сервисов и перейти в сервис S3. Здесь нас интересует S3 bucket, в названии которого есть awstrainingreinvent. Как только мы откроем этот bucket, необходимо будет открыть папку Output и найти файл primary.m3u8. Для конечного URL будет использоваться путь до этого файла, а именно /output/primary.m3u8. Давайте путь до этого файла добавим к URL-адресу CloudFront Distribution. На шаге 38 вы можете найти пример конечного URL. Теперь необходимо будет этот URL открыть на вашем смартфоне. Как только вы откроете ссылку на вашем смартфоне, вы увидите видеоплеер и на нем запустится видеоряд. В зависимости от интернет соединения, видеоплеер автоматически поменяет на подходящий битрейт. Если у вас хорошая скорость интернета, то покажется видео в высоком качестве. Если же у вас слабое интернет подключение, то видеоплеер автоматически переключит вас на видео с низким разрешением. На этом я вас поздравляю, мы выполнили все задания лабораторной работы. Мы получили опыт работы с сервисами Elastic Transcoder и Amazon CloudFront. Таким образом, мы с вами настроили кэширование и распространение динамического контента через сервис Amazon CloudFront. Теперь нам необходимо будет запустить скрипт автооценивания. Необходимая кнопка находится на верхней правой части экрана на главной странице лабораторной работы. Если вы получили необходимое количество баллов, то можете завершать работу лабораторной работы. Если же нет, вы всегда можете вернуться к определенному заданию, внести правки и запустить скрипт автооценивания еще раз. Для того, чтобы завершить лабораторную работу, необходимо будет нажать на кнопку End Lab в верхней правой части экрана и подтвердить это действие. После чего вы можете закрывать страницу с лабораторной работы. На этом мы завершаем обзор лабораторной работы. Спасибо за внимание. Увидимся с вами на следующих наших активностях.
