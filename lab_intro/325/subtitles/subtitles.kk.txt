Қайырлы күн құрметті студенттер, зертханалық жұмыстың кезекті шолу сессиясында сіздерді көргеніме қуаныштымын. Бүгінгі зертханалық жұмыстың тақырыбы – біздің Cafe бизнес кейсіне арналған серверсіз архитектура құру. Ендеше, бастайық. Ең алдымен Cloud Architecting курсының басты парақшасын ашуымыз керек. Содан кейін сол жақтағы навигациялық мәзірді қолданып, Modules бөлімін таңдаймыз. Әрі қарай бізді 13 модуль қызықтырады, егер біз осы модульдің белсенділіктер тізімін ашсақ, сәл төменде Challenge Lab зертханалық жұмысын табуға болады. Оған басып, зертханалық жұмыстың басты парақшасына өтейік. Мұнда терминал терезесін жасыруымыз керек, зертханалық жұмыстың тапсырмасын толық экранда көрсету үшін. Бизнес кейске сәйкес Cafe өсіп, дамып келеді. Веб-сайт құру бизнеске өте үлкен өсім берді. Фрэнк пен Марта қуанышты және енді олар веб-сайтта жасалған тапсырыстар бойынша күнделікті есеп алғысы келеді. Фрэнк үшін бұл ингредиенттер сатып алуды жоспарлау үшін қажет, ал Марта әртүрлі акциялардың нәтижесін талдауды қалайды. София мен Нихил мұның қалай жұмыс істейтінін алдын ала жоспарлады. Олар веб-серверлердің бірін пайдаланып, онда cron job орнатқысы келеді. Cron job күн сайын белгілі бір уақытта есеп генерациялау скриптін іске қосады. Есеп генерациялау ресурсты көп қажет ететін операция болғандықтан, веб-сервер қосымша жүктеме алады, бұл веб-сайт пайдаланушыларына сезіледі. Бұл жақсы емес, сондықтан Нихил Оливиямен сөйлесіп, кеңес алуға шешім қабылдады. Оливия критикалық емес жүктемелерді production жүктемелерінен бөлуге кеңес берді. Бұл өте маңызды және жеке EC2 инстанс нұсқасы бірден алынып тасталды, себебі ол күніне бір рет бір сағат көлемінде ғана жұмыс істейді, қалған уақытта бос тұрады. Бұл нұсқа алынып тасталды, және Оливия одан да жақсы нұсқа ұсынды. AWS Lambda сервисін пайдаланып, есеп генерациялауды осы Lambda функциясына көшіру. Бұл AWS бұлтындағы ресурстарды ұстау шығындарын айтарлықтай азайтады және есеп генерациялау жүктемелерін production жүктемелерінен бөледі. Lambda-мен бірге хабарламаларды жіберу үшін SNS сервисін пайдалануға болады. Нәтижесінде, барлық артықшылықтар мен кемшіліктерді өлшеп, София мен Нихил Оливияның кеңесін ұстануға шешім қабылдады. Осы зертханалық жұмыс аясында біз AWS Lambda сервисін пайдаланып архитектураның бір бөлігін баптаймыз. Ендеше, бастайық. Енді техникалық сәттерге толығырақ тоқталайық. Зертханалық жұмыс барысында біз екі Lambda функциясын құрамыз. Бірінші Lambda функциясы VPC ішінде жасалып, қажетті деректерді алу үшін Amazon RDS сервисіндегі дерекқорға қосылады. Екінші Lambda VPC сыртында орналасады және дайын деректерді пайдаланып, есепті SNS сервисі арқылы жібереді. Ал екінші Lambda-ны күн сайын жеке жасалған Event іске қосады. Зертханалық жұмыстың басында AWS бұлтындағы инфрақұрылым келесідей көрінеді. Зертханалық жұмыс аяқталғаннан кейін келесі ресурстар қосылады. Бұл – екі Lambda, event, SNS topic және SNS topic үшін Subscription. Біз Challenge Lab-пен жұмыс істегендіктен, яғни бұл зертханалық жұмыстың күрделенген нұсқасы, кейбір ұсақ сәттер өткізіледі. Әр қадамда көрсетілген нәтижеге қалай жету керегін өзіңіз шешуіңіз қажет. Бұл зертханалық жұмысты орындау үшін 90 минут уақыт ұсынылады. Егер көбірек уақыт қажет болса, таймерді әрқашан қайта нөлдеп, жұмысты жалғастыра аласыз. Сондай-ақ, біз арнайы AWS аккаунтында жұмыс істеп жатқанымызды еске саламын. Ол уақытша жасалған және құмжәшік болып табылады, сондықтан тек зертханалық жұмыста қолданылатын сервистер ғана сізге қолжетімді болады. Зертханалық жұмысты бастау үшін экранның жоғарғы оң жақ бұрышындағы Start Lab батырмасын басу керек. Сіз уақытша AWS аккаунтын құру күйін көрсететін қалқымалы терезені көресіз. Ол дайын болған кезде сәйкес хабарламаны көресіз. Одан кейін бұл қалқымалы хабарламаны жабуға және сол жерде Start Lab батырмасының жанындағы AWS батырмасын басуға болады. Бұл батырманы басқанда сізді жаңа браузер қойындысында AWS Management Console басты парақшасына бағыттайды және сол жерден зертханалық жұмысты бастай аласыз. Біз бірінші тапсырманы бастаймыз. Бірінші тапсырмада 5-қадамда көрсетілген екі сілтеме арқылы лямбда-функциясының кодын жүктеу қажет болады. Жүктеп алған соң файлдарды мұрағаттан шығарып, ішінде не бар екенін көру керек. Содан кейін зертханалық жұмыстың парақшасына оралу керек. Мұнда Details батырмасын, содан кейін Show батырмасын басып, тест тапсырмасына сілтемені көресіз. Бұл сілтемені жаңа браузер қойындысында ашайық, онда бірнеше сұрақ шығады, және бірінші тапсырмада бізге бірінші сұраққа жауап беру керек. Жауап бергеннен кейін бұл парақшаны жаппаңыз, өйткені келесі тапсырмаларда келесі сұрақтарға жауап береміз. Біз екінші тапсырманы бастаймыз. Екінші тапсырмада лямбда-функция құрамыз. Бұл лямбда-функция VPC ішінде орналасып, дерекқордан деректер алады. Дерекқорға қосылу үшін лямбда-функция VPC ішінде болумен қатар, RDS инстансының Security тобына өзгерістер енгізу қажет. RDS инстансының Security тобына өзгеріс енгізу үшін лямбдаға бөлек Security тобы қажет. Сондықтан біз лямбдаға арналған Security топ құрамыз, жаңа Security топтың ID-н пайдаланып, дерекқордың бар Security тобының Inbound rules бөлігіне өзгеріс енгіземіз. Қадамдарды ретімен өтейік. Алдымен лямбда-функцияға арналған Security топты құрамыз. Security топты LambdaSG деп атаймыз, SG – Security Group қысқартылған түрі. Әрі қарай VPC ретінде Lab VPC таңдаймыз және Outbound rules арқылы лямбда-функция кез келген мекенжайға қосыла алатындай етеміз. Содан кейін Database SG деп аталатын дерекқордың Security тобын ашып, Inbound rules ашамыз. Қосымша Inbound rule құрамыз, Type ретінде MYSQL/Aurora таңдаймыз. Келесі өрісте Custom таңдап, ресурс ретінде sg- енгізуді бастаймыз. Тізімде Security топтар шығады, сол жерден біз бұрын жасаған лямбда-функцияның Security тобын таңдаймыз, содан кейін өзгерістерді сақтаймыз. Енді лямбда-функцияның өзін құрамыз. Lambda функциясының Name өрісіне 11-қадамдағы мәнді енгіземіз, Runtime ретінде Python 3.8 таңдаймыз, Role ретінде дайын рөл – salesAnalysisReportDERole таңдаймыз. VPC ретінде Lab VPC таңдаймыз, ішінде екі Private subnets – бірінші және екінші көрсетеміз. Security топ ретінде біз жасаған лямбда-функцияның Security тобын таңдаймыз. VPC ішінде жасалатындықтан, лямбда-функцияны құру біраз уақыт алады. Бұл аяқталған соң келесі қадамға көшуге болады. Енді бізге лямбда-функцияның кодын жүктеу қажет болады. Бұл біз бұрын жүктеген архив, ол үшін zip файлды көрсету керек. Әрі қарай 12-қадамда Description өрісіне қажетті мән көрсетілген, Handler ретінде – lambda_handler, Memory size – 128 мегабайт, ал Timeout – 30 секунд деп көрсетеміз. Жақсы, енді сұрақтары бар қойындыны ашып, екінші сұраққа жауап беру керек, содан кейін келесі тапсырманы орындауға көше аламыз. Біз үшінші тапсырманы бастаймыз, онда екінші лямбданы құрамыз. Бұл лямбда алынған деректерді есеп генерациялау және оны кейін жіберу үшін қолданады. Мұны жасау үшін AWS Lambda сервисіне өтіп, Function name ретінде salesAnalysisReport деп көрсетеміз. Runtime ретінде Python 3.8 нұсқасын және осы лямбда үшін бұрын жасалған IAM рөлін көрсетеміз. Содан кейін лямбда-функция жасалған соң, кодты жүктеу қажет болады, бұл – екінші zip файл. Сондай-ақ Description, Handler, Memory size және Timeout өрістерін толтыру керек. Осыдан кейін төртінші тапсырмаға көшеміз. Төртінші тапсырмада біз SNS topic құрамыз. Бұл SNS topic есептерді тарату үшін пайдаланылады. Алдымен SNS topic құрамыз, атауы SalesReportTopic, Display name ретінде Sales Report Topic деп, арасына бос орын қоямыз. Содан кейін біздің лямбда-функцияның орта айнымалыларына өзгерістер енгізу керек, атап айтқанда topicARN орта айнымалысына SNS topic-тің ARN мәнін енгізу қажет. Бұны жасаған соң, сұрақтары бар парақшаны ашып, үшінші сұраққа жауап береміз. Бесінші тапсырмада біз SNS topic ішінде жазылым құрамыз. Бұл тапсырманы орындау үшін кез келген email-ды, тіпті жеке email-ды қолдана аласыз. Ең бастысы – пошта жәшігіне қолжетімділік болуы керек. Қолжетімділік жазылымды растау үшін қажет. SNS topic жағында жазылым құрған соң, сізге растау хаты келеді. Содан кейін хаттағы сілтемеге өтіп, сіз парақшаға түсесіз. Парақшада сіздің SNS topic-ке сәтті жазылғаныңыз туралы ақпарат болады. Сондай-ақ SNS topic ішіндегі жазылымдар тізімін ашып, сол жерде сіздің email-ға Confirmed, яғни расталған статусы көрсетілуі керек. Егер солай болса, сіз бесінші тапсырманы дұрыс орындадыңыз, енді сұрақтар тізімін ашып, төртінші сұраққа жауап беру керек. Алтыншы тапсырмада біз есеп генерациялауды тестілеу жасаймыз. Мұны жасау үшін лямбда-функцияны ашып, Test қойындысында жаңа event құру қажет. Кез келген event шаблонын пайдалануға болады, тіпті Hello World шаблоны да жарайды. Осыдан кейін лямбданы іске қосу керек. Біраз уақыттан кейін егер поштаңызға есеп келсе, бәрін дұрыс жасадыңыз деген сөз. Егер жоқ болса, troubleshooting жасап, мәселенің неде екенін анықтау қажет. Мәселені анықтау үшін CloudWatch сервисіндегі лямбда-функция логтарын ашу керек. Оны қалай жасау керегін сіз білесіз. Логтарға қарап, дерекқорға қосылуда мәселе бар-жоғын, Security топтарын дұрыс баптаған-баптамағаныңызды тексеріңіз. Егер лямбда-функция Timeout қателігімен тоқтаса, Timeout мәнін шынымен 30 секунд деп қойған-қоймағаныңызды тексеріңіз. Егер лямбда-функция табылмады деген қате шықса, Handler-ді дұрыс көрсеткен-көрсетпегеніңізді тексеріңіз. Барлық осы сәттерді тексергеннен кейін, мәселені тауып, есепті сәтті іске қосып, генерациялай аласыз. Соңғы жетінші тапсырмада біз белгілі бір уақытта лямбда-функцияны іске қосып, есеп генерациялайтын event құрамыз. Мұны жасау үшін Amazon EventBridge сервисіне өтіп, жаңа rule құрамыз. Уақыт ретінде ең жақын уақытты көрсетуге болады, мысалы, ағымдағы уақыттан 5 немесе 10 минуттан кейін. Уақытты UTC-де көрсету керек екенін еске саламын, сондықтан жергілікті уақытты UTC-ке ауыстыру қажет. Біраз күтіңіз, сізге event rule лямбда-функцияны триггерлеп, лямбда-функция сәтті орындалатындай ету қажет. Лямбда-функцияның сәтті орындалуы – сіздің поштаңызға есептің келуі деген сөз. Егер солай болса, сізді құттықтаймын, қосымшамыздың бір бөлігінің логикасын сәтті баптадыңыз. Енді сұрақтар тізімі бар қойындыны ашып, соңғы алтыншы сұраққа жауап беру қажет. Бизнес кейске сәйкес біз кафе тарапынан жаңарту алдық. София Фрэнк пен Марта үшін есепті сәтті баптады, олар келесі есепті біздің лямбда-функциядан генерацияланған түрде алды. Бұл серверсіз шешім өте сәтті болды. София өте қуанышты, себебі бұл шешім өте жеңіл, оңай бапталады және көп шығынды қажет етпейді. Яғни әр лямбда-функция іске қосылғанда біз тек сол жұмыс істеген уақыт үшін төлейміз. Қалған уақытта біз AWS-ке ештеңе төлемейміз. Енді София қосымшаның басқа бөліктерін, соның ішінде басқа есепті де серверсіз шешімдер негізінде жасауды жоспарлап отыр. Осылайша біз зертханалық жұмыстың соңына жеттік. Соңында автобағалау скриптін іске қосу қажет. Егер қажетті ұпайды алсаңыз, зертханалық жұмысты аяқтай аласыз. Егер жоқ болса, қай тапсырмада ұпай жетіспейтінін көріп, түзетулер енгізіп, автобағалау скриптін қайта іске қосуға болады. Зертханалық жұмысты аяқтаған соң, экранның жоғарғы оң жағындағы End Lab батырмасын басып, бұл әрекетті растау керек. Сондай-ақ AWS Management Console-дан дұрыс түрде шығу қажет. Осылайша біз зертханалық жұмыстың шолуын аяқтаймыз. Назарларыңызға рахмет. Келесі белсенділіктерде кездескенше.
