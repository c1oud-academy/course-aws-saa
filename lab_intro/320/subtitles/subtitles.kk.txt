Қайырлы күн, құрметті студенттер. Зертханалық жұмысты шолу сессиясында баршаңызды көргеніме қуаныштымын. Бүгінгі зертханалық жұмыстың тақырыбы — AWS Lambda сервисін пайдаланып, серверсіз архитектура құру. Ендеше, бастайық. Cloud Architecting курсының басты парақшасынан бастаймыз. Бізді сол жақтағы навигациялық мәзірден Modules бөлімі қызықтырады. Оған батырманы басайық. Одан әрі модульдер тізімінен бізді он үшінші модуль қызықтырады. Осы модульдің белсенділіктер тізімін кеңейтіп, Guided Lab-ты табуымыз қажет. Оны жасаған соң зертханалық жұмыстың басты парақшасына өтеміз. Келесі қадам — терминал парақшасын жабу, осылайша зертханалық жұмыс тапсырмасы бар парақша толық экранға шығады. Зертханалық жұмыс сценарийіне сәйкес, біз кафеміз үшін қорларды бақылау жүйесін құрамыз. Жеткізушілеріміз жіберілген тауарлар мен ингредиенттердің мәліметтері бар файлды біздің S3 bucket-ке жүктейді. S3 bucket-ке файл жүктелген сәтте, ол event жасап, лямбда-функцияны триггерлейді. Содан кейін лямбда-функция жаңа файлдан мәліметтерді оқып, жаңа тауарлар мен ингредиенттер туралы ақпаратты DynamoDB кестесіне енгізеді. Веб-қосымша бапталады, ол бізді Amazon Cognito сервисі арқылы авторизациялап, қорлар туралы мәліметті тікелей DynamoDB-ден веб-интерфейсте көрсетеді. Басқа бір лямбда-функция DynamoDB кестесінен жаңартуларды алып, егер ингредиент таусылса, SNS topic-ке хабарлама жібереді. SNS topic жағында SMS немесе email-ескерту жіберу үшін кез келген саны бар жазылушыларды баптауға болады. Серверсіз архитектура құратынымыздың арқасында бізге серверлерді сатып алудың, жалға алудың және оларды бөлек баптауға уақыт жұмсаудың қажеті жоқ. Біздің шешім, соның ішінде веб-интерфейс те AWS Lambda жағында болады, ал егер жүктеме болмаса, біз ештеңеге төлемейміз. Егер үлкен трафик келсе, кез келген сұраныс өңделеді, себебі AWS Lambda және басқа serverless шешімдер өте оңай масштабталады, әрі біз тек пайдаланылғанымыз үшін ғана төлейміз. Бұл слайдта AWS бұлтында бірнеше сервисті пайдаланып жасалған соңғы архитектура мысалын көріп тұрсыздар. Олар бір-бірімен нативті түрде интеграцияланып, бізге міндетімізді шешуге көмектеседі. Зертханалық жұмысты орындауға шамамен 40 минут бөлу ұсынылады. Сондай-ақ, біз уақытша жасалған AWS аккаунтында жұмыс істейтінімізді еске салғым келеді. Ол құмжәшік түрінде беріледі, сондықтан тек зертханалық жұмыс шеңберінде қарастырылған сервистер мен олардың функцияларына ғана қолжетімділік ашық. Зертханалық жұмысты бастау үшін, зертханалық жұмыстың басты парақшасында, экранның жоғарғы оң жағында Start Lab батырмасын басу қажет. Сіз қалқып шығатын терезені көресіз, онда біздің құмжәшіктің жасалу статусы көрсетіледі. Ол дайын болған кезде қалқып шығатын терезені жаба аласыз және Start Lab батырмасының жанындағы AWS батырмасын басу арқылы уақытша AWS аккаунтындағы AWS Management Console басты парақшасына өтесіз. Енді бірінші тапсырманы бастаймыз. Бірінші тапсырма аясында S3 bucket-тен триггер арқылы файлды оқып, қорлар туралы мәліметті DynamoDB кестесіне енгізетін лямбда-функцияны құрып, баптаймыз. Мұны жасау үшін AWS Lambda сервисіне өту қажет. Лямбда-функцияны жасағанда бірнеше нұсқа ұсынылады: нөлден бастау, blueprint пайдалану және т.б. Код біз үшін алдын ала дайындалған және ол демо түріндегі дайын blueprint-шешім емес болғандықтан, Author from scratch опциясын таңдап, келесі өрістерді толтырамыз. Яғни, функция атауы Load-Inventory болуы тиіс, содан кейін Runtime ретінде Python 3.7 таңдаймыз. Төменірек лямбда-функция үшін role көрсету қажет, біз оны нөлден құрмай, дайын рөлді таңдаймыз. Рөл де біз үшін алдын ала жасалған, оны ұсынылған рөлдер тізімінен таба аласыз. Рөлдің атауы — Lambda-Load-Inventory-Role. Одан кейін Create function батырмасын басу қажет. Функция жасалған соң бізді лямбда-функцияның басты парақшасына бағыттайды. Мұнда біз парақша ортасына дейін төмен сырғытып, онлайн редакторға жетуіміз керек. Одан кейін бастапқы кодтың барлық мазмұнын өшіріп, 11-қадамдағы дайын кодты қоямыз. Бұл зертханалық жұмыс аясында лямбда-функцияның ұсынылған кодын толық талдап шығудың қажеті жоқ, негізгі сәттерін түсінсеңіз жеткілікті. Бұл лямбда-функция кіріс event-ті пайдаланып, одан қажетті ақпаратты парсинг жасайды, атап айтқанда S3 бакетінің атауын және жүктелген файлдың жолын. Осы деректерді пайдаланып, жаңа файл лямбда-функциямен оқылады. Одан кейін цикл арқылы файлдағы әрбір жолдан өтіп, оны DynamoDB кестесіне жүктейміз. Кодты көшіріп қойып болған соң, өзгертулерді сақтап, редактордың жоғарғы бөлігіндегі Deploy батырмасын пайдаланып, лямбда-функцияның жаңа кодын орнату қажет. Енді екінші тапсырмаға көшеміз. Бұл тапсырмада біз S3 бакетін және сол S3 бакет үшін біздің лямбданы триггерлейтін event құрамыз. Жеткізушілеріміздің S3 бакетке файл жүктеуі үшін тікелей қолжетімділікті баптауға болады. Бұл веб-интерфейс арқылы да жүзеге асырылуы мүмкін, ол сіздің нақты міндетіңізге байланысты. Зертханалық жұмыс аясында бұл жеңілдетілген және бизнес-кейс бойынша жеткізушілер деректерді тікелей S3 бакетке жүктейді. Мұны бірге жасап көрейік. Алдымен сервис іздеу жолағын пайдаланып, S3 сервисіне кіруіміз керек. Содан кейін Create Bucket батырмасын басып, S3 бакетіне бірегей атау енгізу қажет. Бұл атауда Inventory- префиксі және дефис болуы тиіс. Содан соң бұрын қолданылмаған бірегей сан таңдау керек. Егер бірден шықпаса, бірнеше рет қайталап, S3 бакетіміз үшін бірегей цифрлар комбинациясын таңдауға тырысыңыз. Бұл орындалған соң, Event Notification жасауымыз қажет. Мұны S3 бакетінің басты парақшасынан жасауға болады, онда Properties қойындысы бар, парақша ортасына дейін төмен сырғытсақ, Event Notifications секциясын көреміз. Мұнда Create Event Notification батырмасын басып, event жасау парақшасында келесі деректерді енгіземіз. Name ретінде Load-Inventory көрсетеміз, Event Type ретінде All Object Create Events таңдаймыз. Айта кетейін, S3 бакетінде объектіні жасау үшін бірнеше нұсқа бар, бізге оның қалай жүктелгені маңызды емес, біз үшін маңыздысы — S3 бакетінде объектінің пайда болуы. Destination ретінде Lambda Function таңдап, келесі өрісте біздің Load-Inventory функциямыздың атын көрсетеміз. Одан кейін экранның төменгі бөлігіндегі Save Changes батырмасын басамыз. Керемет, біз S3 бакетін жасадық, Event Notification құрдық және енді S3 бакетке жаңа файл жүктелсе, Event жасалып, ол біздің Lambda функцияны триггерлейді. Енді келесі тапсырмаға көше аламыз. Біз үшінші тапсырманы бастаймыз. Бұл тапсырмада жүйеге деректерді жүктеу процесін тестілеу болады. Алдымен жергілікті компьютерге .csv файлдарын жүктейміз. Бұл — біздің жүйеге сәйкес келетін, алдын ала дайындалған құрылымы бар тест файлдары. Аталған файлдарды жергілікті компьютерге жүктеген соң, AWS Management Console-да S3 сервисіне, нақтырақ айтқанда біздің S3 бакетке өтіп, осы файлдардың барлығын S3 бакетке жүктеуіміз қажет. Файлдар жүктелген бойда автоматты түрде Lambda функциясы іске қосылады және ол барлық деректерді DynamoDB-ге жазады. Осы уақытта біз зертханалық жұмыстың басты парақшасын ашып, оң жақ жоғарғы бұрышындағы Details батырмасынан Dashboard URL деп жазылған сілтемені таба аламыз. Бұл сілтемені көшіріп, браузердің жаңа қойындысында ашу қажет. Егер бәрі дұрыс орындалса, сіз осындай көріністі көресіз. Мұнда біздің қорлар бойынша ақпарат көрсетіледі, деректерді кесте түрінде ғана емес, графиктер түрінде де көреміз. Бұл деректерді DynamoDB кестемізден де көре аламыз. Ол үшін тиісті сервиске кіріп, сол жақтағы навигация мәзірінен Tables тармағын таңдаймыз. Бізді қызықтыратын кесте — Inventory, соған басып, Items қойындысын ашайық. Онда Lambda функциясы жүктеген барлық деректерді кесте түрінде көреміз. Біз төртінші тапсырманы бастаймыз. Бизнес-кейс бойынша, кафе иелері белгілі бір ингредиент таусылғанда, электрондық пошта арқылы хабарлама алғысы келеді. Біз мұны SNS topic арқылы баптаймыз. Ол үшін SNS сервисіне кіріп, SNS topic тізімі парақшасынан Create Topic батырмасын басу керек. Topic name ретінде NoStock деп енгіземіз, SNS topic түрі ретінде Standard таңдап, экранның төменгі жағындағы Create Topic батырмасын басамыз. Мұны орындаған соң, біз SNS topic басты парақшасына өтеміз, енді жазылушыларды қоса аламыз. Ол үшін осы парақшада Create Subscription батырмасын басу қажет. Жаңа жазылу жасау парақшасында Protocol ретінде Email таңдап, Endpoint өрісіне жеке электрондық поштаңызды енгіземіз және төменгі жағындағы Create Subscription батырмасын басамыз. Енді электрондық поштаңызды ашып, SNS topic-ке жазылғаныңыз туралы хат аласыз, егер бұл хатты сіз бастаған болсаңыз және жазылуды растағыңыз келсе, сілтеме бойынша өтіңіз. SNS topic-ке жазылу үшін сілтеме арқылы бір рет қана өту жеткілікті. Сілтемеге өткен соң, жазылудың сәтті өткенін көрсететін қарапайым парақша ашылады. Осыдан кейін SNS topic-ке келіп түсетін барлық хабарламалар сіздің электрондық поштаңызға да жіберіледі. Біз бесінші тапсырманы бастаймыз. Бұл тапсырма бойынша SNS хабарламаларын жіберу үшін лямбда-функция жасаймыз. Басқа нұсқа ретінде бар лямбда-функцияны пайдалануға болады, бірақ оның бірқатар кемшіліктері бар. Атап айтқанда, бұл лямбда-функция қатты жүктеледі және бір логикаға қоса тағы бір бизнес-логика қосылады. Бұл жақсы емес, өйткені біз инфрақұрылымда тығыз байланыс жасаймыз. Сондықтан инфрақұрылымды әлсіз байланысқан етіп, оны оңай басқару үшін жеке функция жасаған дұрыс. Сол арқылы қажет болғанда оны өзгертуге және бастапқы басқа лямбдадан тәуелсіз бизнес-логика қосуға болады. Міне, осы лямбда-функцияның орналасқан жері көрсетілген, ол DynamoDB кестесіне жазылған және кестедегі барлық өзгерістер осы лямбдаға жіберіледі. Одан кейін лямбда-функция берілген деректер ішінде саны 0 ингредиенттер бар-жоғын тексеріп, бар болса SNS topic-ке хабарлама жібереді. Ал, бастайық. AWS Lambda сервисіне кіріп, Create Function батырмасын басып, келесі мәндерді енгізу қажет. Function Name өрісіне Check-Stock деп жазамыз, Runtime ретінде Python 3.7 таңдаймыз. Біз үшін алдын ала IAM role жасалған, сондықтан Use an existing role опциясын таңдап, тізімнен Lambda-Check-Stock-Role рөлін таңдаймыз, содан кейін Create Function батырмасын басамыз. Алдыңғы функциядағыдай, бізде дайын код бар, оны 43-қадамнан көшіріп алып, онлайн редакторға қою керек. Содан кейін өзгертулерді сақтап, онлайн редактордың жоғарғы жағындағы Deploy батырмасын басамыз, осылайша өзгерістер қолданылады және келесі іске қосу жаңа кодпен орындалады. Енді бұл лямбда-функцияны DynamoDB-ге байлауымыз керек, ол үшін парақшаның басына оралып, Add Trigger батырмасын басамыз. Осыдан кейін жаңа триггер жасау парақшасы ашылады. Триггер ретінде DynamoDB таңдап, төменде ашылған өрісте DynamoDB Table ретінде Inventory кестесін көрсетеміз және парақшаның төменгі жағындағы Add батырмасын басамыз. Жақсы, бәрін дайындадық, енді бүкіл жүйені тестілеуге болады. Жүйені тестілеуді алтыншы тапсырма аясында орындаймыз. Кез келген мәтіндік редакторда бір .csv файлын ашып, кез келген жолдағы санды 0 деп өзгертіп, өзгертулерді сақтап, оны S3 Bucket-ке жүктеу керек. Бұдан кейін келесілер орындалады: файл S3 Bucket-ке түседі, S3 Bucket Event генерациялайды, ол бірінші лямбда-функцияны іске қосады. Бірінші лямбда-функция Event-ті парсинг жасап, қажетті файлды жүктейді және оны оқиды. Оқылған деректер DynamoDB кестесіне жүктеледі. Содан кейін екінші лямбда-функция DynamoDB кестесіндегі өзгерістерге байланысты іске қосылады. Бұл өзгерістер екінші лямбда-функцияға хабар ретінде жіберіледі. Екінші лямбда-функция барлық өзгерген жолдарды тексеріп, егер саны 0 жолды тапса, SNS topic-ке хабар жібереді. SNS topic хабарды алған соң, оны барлық жазылушыларына жібереді. Біз email-ді жаздырып, оны растағандықтан, біздің поштамызға хабар келуі тиіс. Кейде email бірден келмеуі мүмкін, бірнеше минут күтіңіз, көмектеспесе, басқа .csv файлды өзгертіп жүктеп көріңіз, сонда сізге email келуі керек. Осылайша барлық тапсырмаларды орындадық, енді автобақылау скриптін іске қосып, барлық тапсырмаларды дұрыс орындағанымызды тексеруіміз керек. Ол үшін зертханалық жұмыстың басты парақшасына барып, оң жақ жоғарғы бұрыштағы Submit батырмасын басып, бұл әрекетті растау қажет. Біраз уақыттан кейін экранның оң жағында бағаларыңыз шығады, егер шықпаса, жоғарғы оң жақтағы Grades батырмасын басып, бағаларды көре аласыз. Егер ең жоғары баға алмасаңыз және оны жақсартқыңыз келсе, тиісті тапсырмаға қайта оралып, түзетулер жасап, автобақылау скриптін қайта іске қоса аласыз. Зертханалық жұмысты аяқтауға дайын болсаңыз, AWS Management Console қойындысының біреуін ғана қалдырыңыз. Содан кейін жоғарғы оң жақтағы пайдаланушы атын басып, ашылған тізімнен Sign out батырмасын таңдаңыз. Енді зертханалық жұмыстың өзін дұрыс аяқтауымыз керек. Ол үшін зертханалық жұмыстың басты парақшасына оралып, жоғарғы оң жақтағы End lab батырмасын басып, бұл әрекетті растау керек. Жақсы, енді бұл браузер қойындысын жабуға болатыны туралы хабарлама шығады. Осылайша зертханалық жұмысқа шолу сессиясын аяқтаймыз. Назарларыңызға рахмет, келесі белсенділіктерде кездескенше.
