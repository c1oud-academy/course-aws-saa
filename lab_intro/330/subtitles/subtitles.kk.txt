Қайырлы күн, құрметті студенттер. Зертханалық жұмыстың шолу сессиясында сіздерді көргеніме қуаныштымын. Бүгінгі зертханалық жұмыста біз AWS Storage Gateway сервисімен жақынырақ танысамыз. Ендеше, бастайық. Cloud Architecting курсының басты парақшасынан бастаймыз. Мұнда бізді сол жақтағы навигация мәзіріндегі Modules бөлімі қызықтырады. Содан кейін модульдер тізімінен 14-модульге дейін жылжытамыз. Белсенділіктер тізімінде Guided Lab көресіз. Зертханалық жұмыстың басты парақшасына өту үшін сілтемені басу қажет. Зертханалық жұмыс парақшасында тапсырманы толық экранға ашу үшін terminal белгісіндегі құсбелгіні алып тастау керек. Бұл зертханалық жұмыста AWS Storage Gateway сервисін қолданып, біз File Gateway баптаймыз, ол Linux инстансын S3 bucket-пен байланыстырады. Linux инстансы жергілікті дата-центрдегі серверді эмуляциялайды. Одан әрі біз S3 bucket жағында кеңейтілген баптаулар жасаймыз, атап айтқанда Lifecycle Policy және Cross-Region Replication. Бұл зертханалық жұмысқа 90 минут бөлу ұсынылады. Егер бұл уақыт аз болса, таймерді қосымша 90 минутқа қосуға болады. AWS құмсалғышында жұмыс істегендіктен, бізге тек зертханалық жұмыста қарастырылатын сервистер ғана қолжетімді болады. Жұмысты бастау үшін зертханалық жұмыстың басты парақшасында оң жақ жоғарғы бұрыштағы Start батырмасын басу керек. Уақытша AWS аккаунтын құру статусы көрсетілетін қалқымалы терезе пайда болады. Дайын болған соң сәйкес мәтін шығады, содан кейін терезені жабуға болады. Одан кейін Start Lab батырмасының жанындағы AWS батырмасын басып, бізді AWS Management Console басты парақшасына жібереді, сол жерден жұмысты бастаймыз. Бірінші тапсырмада зертханалық жұмыс барысында не орындайтынымызды түсіну ұсынылады. Диаграммаға қарасақ, үш AWS аймағын көреміз. Бірінші аймақта біздің Linux инстансымыз орналасқан — бұл on-premise сервердің эмуляциясы. AWS Storage Gateway сервисін қолданып, біз оны екінші AWS аймағындағы S3 bucket-пен байланыстырамыз. Бұл S3 bucket — біздің source bucket болады, оған Linux серверіндегі NFS mount-қа түскен барлық файлдар жіберіледі. Содан кейін файлдар source S3 bucket-ке түскенде, біз онда cross-region replication баптаймыз, және барлық файлдар автоматты түрде басқа AWS аймағындағы destination S3 bucket-ке репликацияланады. Екінші тапсырмада біз алдын ала екі S3 bucket-ті де жасауымыз керек. Ол үшін S3 сервисіне өтеміз. Содан кейін Create bucket батырмасын басып, жаңа bucket құрамыз. Bucket атауын қалауыңыз бойынша беруге болады, ең бастысы аймақ us-east-2 болуы тиіс. Және бұл bucket-те Bucket versioning қосу керек. Неге? Себебі cross-region replication тек bucket versioning қосылған кезде ғана жұмыс істейді. Қалған баптауларды әдепкі күйінде қалдырып, төменгі оң жақтағы Create bucket батырмасын басу керек. Дәл осы әрекеттерді екінші bucket үшін де орындау қажет. Атауын қалауыңыз бойынша таңдаңыз. Region ретінде Oregon, яғни us-west-2 таңдау керек және мұнда да versioning қосу қажет. Үшінші тапсырмада біз cross-region replication баптаймыз. Ол үшін Ohio аймағындағы source bucket-ті ашамыз. Bucket парақшасында Management қойындысын ашып, replication rules жасау бөлігінен Create replication rule батырмасын табамыз. Бізді бөлек парақшаға жібереді. Replication rule атауына crr-full-bucket деп енгізу керек. Status ретінде Enabled таңдаймыз, Source bucket ретінде өзіміздің source bucket-ті таңдаймыз. Destination bucket ретінде Oregon аймағындағы екінші bucket-ті таңдаймыз. Содан кейін алдын ала осы зертханалық жұмыс аясында жасалған IAM role — S3-CRR-Role таңдаймыз. Соңында төменгі бөліктегі Save батырмасын басу керек. Сізден source bucket-тегі бар файлдарды destination bucket-ке көшіруді қалайсыз ба деп сұрауы мүмкін. Бізде source bucket-те файл жоқ болғандықтан, кез келген жауап ешқандай әрекет жасамайды. Сондықтан қалауыңыз бойынша таңдап, Submit батырмасын басыңыз. Енді Cross-Region replication қалай жұмыс істейтінін тексеру керек. Source S3 bucket-ті ашып, кез келген файл жүктеу қажет. Жүктеу аяқталғанын күтеміз. Файл сәтті жүктелсе, destination bucket мазмұнын ашамыз. Егер ештеңе көрінбесе, парақшаны жаңартыңыз немесе S3 bucket парақшасындағы Refresh батырмасын басыңыз. Содан кейін source bucket-тен destination bucket-ке көшірілген файлды көруіңіз керек. Біз төртінші тапсырманы бастаймыз. Бұл тапсырмада біз File Gateway баптаймыз және NFS file share құрамыз. Ол үшін Storage Gateway сервисіне кіреміз. Ресурс парақшасына кірген соң, аймақ North Virginia таңдалғанына көз жеткізіңіз. Содан кейін Create gateway батырмасын басып, жаңа ресурс жасау парақшасына өтеміз. Gateway name өрісіне File gateway, Time zone ретінде GMT-5 енгіземіз. Type gateway — Amazon S3 file gateway және Host platform — Amazon EC2 таңдаймыз. Төменде Customize your settings опциясын таңдаймыз. Осы опцияны таңдаған соң, жаңа бөлім пайда болады, онда Launch instance батырмасын басу керек. Оны басқан кезде браузерде жаңа қойынды ашылып, EC2 инстансымызға арналған AMI баптаймыз. AMI жасау парақшасында Name өрісіне File Gateway Appliance деп енгіземіз. AMI мәнін өзгеріссіз қалдырамыз, Instance type — t2.xlarge, ал Key pair name — vockey таңдаймыз. Бұл кілтті зертханалық жұмыстың басты парақшасына жүктеп алуға болады. Details батырмасын басып, ашылмалы тізімнен Show батырмасын басамыз. Содан кейін бұл кілтті жүктеу үшін қажетті сілтемелер шығады. AMI жасау парақшасына ораламыз, бізді Network бөлімі қызықтырады, Edit батырмасын басып, кейбір өзгерістер енгізу керек. VPC ретінде On-Prem-VPC таңдау қажет. Subnet ретінде On-Prem-Subnet таңдап, Auto assign public IP өрісінде Enable опциясын таңдап, төменге жылжимыз. Төменде security group таңдау бөлімі болады. Select an existing security group опциясын таңдаймыз, яғни зертханалық жұмыс аясында бізге алдын ала жасалған security group-тар бар. Біз екі security group таңдаймыз, біріншісінің атауында FileGatewayAccess бар. Онда 80, 443, 53, 123 және 2049 порттарына рұқсат беретін ережелер бар. Бұл порттар File gateway-ді белсендіруге мүмкіндік береді. Содан кейін атауында OnPremSshAccess бар екінші security group таңдаймыз. Атаудан көрініп тұрғандай, бұл EC2 инстансына SSH арқылы қосылуға, яғни 22-портқа рұқсат береді. Соңғы өзгеріс енгізетін бөлім — Storage бөлімі. Бар дискке қосымша екінші диск қосу керек, сондықтан Add new volume батырмасын басып, көлемін 150 гигабайт деп енгіземіз. Содан кейін экранның оң жағындағы инстанс санын бір деп таңдап, Launch instance батырмасын басамыз. Бізді инстанс жасау парақшасына жібереді. View all instances батырмасын басып, барлық инстанстар тізіміне өтуге болады. Жұмысты жалғастыру үшін біздің инстансымыздың Status checks бағаны «2/2 checks passed» мәніне өзгеруін күту қажет. Парақшаны уақыт сайын жаңартып тұруға немесе консоль интерфейсіндегі жаңарту батырмасын басуға болады. Содан кейін EC2 инстансының басты парақшасын ашып, оның public IP мекенжайын көшіру керек. Бұл мекенжайды кейін File gateway баптау үшін қолданамыз. Мұны жасаған соң, браузердегі алдыңғы қойындыға, яғни AWS Storage Gateway сервисіндегі File gateway баптау парақшасына ораламыз. Мұнда EC2 инстансын дайындап, жасағанымызды растау үшін құсбелгі қоямыз. Содан кейін Next батырмасын басамыз, бізді екінші парақшаға жібереді. Екінші парақшада IP address өрісіне көшірген мекенжайды енгізіп, Service endpoint үшін Publicly accessible опциясын таңдаймыз. Содан кейін экранның төменгі жағындағы Next батырмасын басамыз. Үшінші парақшада енгізілген барлық баптауларды көресіз. Мұнда ештеңе өзгертпей, төмендегі Activate gateway батырмасын басамыз. Төртінші парақшада File gateway жасау процесі басталады. Экранның жоғарғы жағында сәйкес хабарлама шығады. Қосымша ретінде CloudWatch log group және CloudWatch alarms баптауларын ұсынады. Бұл зертханалық жұмыста олар қажет емес, сондықтан log group үшін Deactivate logging, alarms үшін No alarm таңдаймыз. Gateway жасалған соң, жасыл фонда сәтті жасалғаны туралы хабарлама көресіз. Содан кейін төменгі жағындағы Configure батырмасын басамыз. Бізді ресурс басты парақшасына жібереді. Мұнда File gateway статусы Running болғанын күтеміз, бұл шамамен бір минуттай уақыт алады. Барлығы дайын болғанда, сол жақтағы навигация мәзірінен File Shares бөлімін таңдап, оны жасаймыз. Ашылған парақшада Create file share батырмасын басамыз. Ашылған парақшада File gateway атауын таңдаймыз. File share protocol ретінде NFS, ал Amazon S3 bucket name ретінде Ohio аймағындағы source bucket таңдаймыз. Содан кейін Customize configuration опциясын таңдаймыз. File share name өрісіне share деп енгізіп, Next батырмасын басамыз. Содан кейін S3 сақтау баптауларын енгіземіз. Жаңа объектілер үшін сақтау класы ретінде S3 Standard таңдаймыз. Object metadata үшін алғашқы екі мәнге құсбелгі қоямыз, үшіншісін алып тастаймыз. Осындай ұсақ нәрселерге көп мән бермеңіз. Маңыздысы — белгілі бір сервисті қолдана отырып, нақты міндетті шеше алатыныңызды түсіну. Ұсақ-түйек баптауларды бұлттық инженер ретінде жұмыс істегенде оқып, бизнес міндетке сәйкес таңдайсыз. Тапсырмаға қайта ораламыз: Access your S3 bucket үшін бар IAM role опциясын таңдаймыз. IAM role өрісіне FgwIamPolicyARN рөлінің ARN мәнін енгізу қажет. IAM сервисінен бұл мәнді алуға тырысуға болады, бірақ біз арнайы құмсалғышта жұмыс істегендіктен, ол мүмкін болмауы ықтимал. Бұл мәнді алу үшін зертханалық жұмыстың басты парақшасына оралуға болады. Онда Details батырмасын басып, ашылмалы тізімнен Show батырмасын басыңыз. Қалқымалы терезеде қажетті мәнді көресіз. Бұл мәнді IAM role өрісіне енгізіп, Next батырмасын басамыз. Келесі парақшада қол жеткізу баптауларын енгізу ұсынылады. Барлық мәндерді әдепкіде қалдырамыз. Қызыл фонда ескерту бар қосымша өрісті елемеуге болады. Парақшаның соңына дейін жылжып, Next батырмасын басу керек. Келесі парақша — Review, оны да соңына дейін жылжытып, Create батырмасын басамыз. Ресурсты орналастыру басталады, дайын болғанда статус Available болып өзгереді. Бұл болғанда File share сілтемесін басып, ресурс басты парақшасына өтеміз. Ресурс парақшасында File share-ді біздің Linux инстансына тіркеу командасы бар. Осы команданы көшіру қажет, ол бізге кейін керек болады. Бесінші тапсырмада біз File share-ді біздің Linux инстансына тіркейміз. Егер сіз Windows операциялық жүйесінде жұмыс істесеңіз, келесі әрекеттерді орындау қажет. Яғни зертханалық жұмыстың басты парақшасында Details батырмасын басу. Содан кейін Show батырмасын басып, .ppk файлын жүктеу, бұл біздің SSH кілтіміз. Одан кейін OnPremLinuxInstance деп аталатын инстансымыздың public IP мекенжайын көшіру және PuTTY бағдарламасын іске қосу қажет. PuTTY бағдарламасында .ppk кілтінің орналасқан жерін көрсету міндетті. Host Name or IP address өрісіне біздің Linux инстансымыздың IP мекенжайын енгізіп, қосылу. Қосылу кезінде сізден қосылатын пайдаланушы атын енгізу сұралады. EC2 инстанстары үшін бұл әдепкі мән — ec2-user пайдаланушысы. Егер сіздің операциялық жүйеңіз macOS немесе Linux болса, келесі әрекеттерді орындау керек. Зертханалық жұмыстың басты парақшасында да Details батырмасын басамыз. Содан кейін ашылмалы тізімнен Show батырмасын басамыз. Қалқымалы терезеде labuser.pem файлын жүктеу сілтемесі болады, бұл сол SSH кілтінің басқа форматы. Содан кейін EC2 инстансымыздың IP мекенжайын көшіріп, жергілікті компьютердің операциялық жүйесінде терминал терезесін ашу керек. Одан кейін .pem кілтінің орналасқан жеріне өту, әдетте ол Downloads папкасында болады. Бұл файлға қол жеткізу рұқсаттарын өзгерту қажет. Содан кейін 56-қадамдағы команданы енгізіп, EC2 инстансына қосыламыз. Біз EC2 инстансына сәтті қосылдық. Енді ls/media/data командасын енгізіп, S3 bucket-ке жүктеуге арналған тест суреттер тізімін қарайық. Содан кейін File gateway-ді тіркейтін папка жасау ұсынылады. Бұл команда 59-қадамда көрсетілген, оны жасағаннан кейін 60-қадамда осы папкаға File Gateway байланыстыру мысалы көрсетілген. Команданың мысалын біз бұрын AWS Management Console-ден көшіргенбіз. Онда IP мекенжайды дұрыс мәнге ауыстырып, команданы іске қосу керек. df -h командасын пайдаланып, EC2 инстансындағы барлық бар mount нүктелерін тексеруге болады, соңғы жол — бізге керегі. Енді Data папкасындағы барлық суреттерді File Gateway-ге көшейік, ол үшін 62-қадамдағы команданы қолданамыз. Біз алтыншы тапсырмаға жеттік. Бұл тапсырмада біздің шағын инфрақұрылымның жұмысын тестілеу болады. Ол үшін AWS Management Console қойындысына оралып, S3 сервисіне өтеміз. Мұнда бізді Ohio аймағындағы source bucket қызықтырады, оны ашып, файлдар тізімін жаңартамыз. Егер 20 суретті көрсек, демек бәрі дұрыс, EC2 инстансынан source bucket-ке файлдар жүктелді. Енді source bucket-тен destination bucket-ке cross-region replication қалай жұмыс істегенін қарайық. Ол үшін bucket тізімін ашып, Oregon аймағындағы destination bucket-ті табамыз. Егер файлдар тізімінде жаңа файлдар — 20 сурет шықса, бәрі дұрыс жасалды, баптаулар дұрыс және cross-region replication сәтті өтті. Біз зертханалық жұмыстың барлық тапсырмаларын орындадық. Енді автобағалау скриптін іске қосып, барлық тапсырмалар дұрыс орындалғанын тексереміз. Ол үшін зертханалық жұмыстың басты парақшасына оралып, Submit батырмасын басамыз, содан кейін бұл әрекетті растау керек. Біршама уақыттан кейін экранның оң жағында бағаларыңыз шығады. Егер ол шықпаса, экранның жоғарғы оң жағындағы Grades батырмасын басу керек. Егер жеткілікті ұпай жинамасаңыз, әрқашан жетіспейтін тапсырмаға оралып, оны түзетіп, автобағалау скриптін қайта іске қосуға болады. Жеткілікті ұпай жинаған соң, зертханалық жұмысты дұрыс аяқтау керек. Бірінші кезекте бұл AWS Management Console-ге қатысты. Бір ғана қойындыны қалдыру қажет. Экранның жоғарғы оң жағында пайдаланушы атыңызды басыңыз. Ашылмалы тізімнен Sign out батырмасын басыңыз. Содан кейін зертханалық жұмыстың басты парақшасына оралып, экранның жоғарғы оң жағында End lab батырмасын басу керек. Бұл әрекетті растау керек, қалқымалы терезеде уақытша AWS аккаунтын жою процесі басталғаны көрсетіледі және зертханалық жұмыстың қойындысын жабуға болады. Осылайша біз зертханалық жұмысты шолу сессиясын аяқтаймыз. Назар аударғандарыңызға рахмет, келесі белсенділіктерде кездескенше.
