Добрый день, уважаемые студенты. Я рад вас всех видеть на очередной сессии обзора лабораторной работы. В сегодняшней лабораторной работе мы с вами поближе познакомимся с сервисом AWS Storage Gateway. Итак, давайте начнем. Начинаем мы с главной страницы курса Cloud Architecting. Здесь нас интересует пункт Modules в навигационном меню слева. Далее из списка модулей нам необходимо прокрутить до 14 модуля. В списке активностей вы увидите Guided Lab. Необходимо будет нажать на ссылку для того, чтобы перейти на главную страницу лабораторной работы. На странице лабораторной работы нам необходимо будет убрать галочку с пункта терминал для того, чтобы открыть задание страницы на всю страницу. В этой лабораторной работе, используя сервис AWS Storage Gateway, мы с вами настроим File Gateway, который привяжет Linux instance с S3 bucket. Linux instance будет эмулировать сервер в локальном дата-центре. Далее мы произведем продвинутые настройки на стороне S3 bucket, а именно Lifecycle Policy и Cross-Region Replication. На выполнение этой лабораторной работы рекомендуется потратить 90 минут. Если этого времени мало, то вы всегда можете обнулить счетчик и добавить еще 90 минут. Так как мы работаем в песочнице AWS, то только те сервисы, которые рассматриваются в лабораторной работе, будут для нас доступны. Для того, чтобы начать лабораторную работу, нам необходимо на главной странице лабораторной работы в верхней правой части экрана нажать на кнопку Start. Вы увидите всплывающее окно с статусом создания временного AWS аккаунта. Как только он будет готов, вы увидите соответствующий текст, после чего можно будет закрыть всплывающее окно. Далее нам необходимо будет нажать на кнопку AWS возле кнопки Start Lab и нас направят на главную страницу AWS Management Console, где и мы сможем начать выполнение лабораторной работы. На первом задании нам предлагается понять, что мы будем выполнять во время лабораторной работы. Если вы посмотрите на диаграмму, мы видим три региона AWS. В первом регионе находится наш Linux instance, это эмуляция on-premise сервера. Мы используя сервис AWS Storage Gateway привяжем его к S3 бакету во втором AWS регионе. Этот S3 бакет у нас будет являться source бакетом и в нее будут отправляться все файлы, которые попадают в NFS mount на Linux сервере. Далее как только файлы попадают в наш source S3 бакет, на ее стороне мы настроим cross-region replication и все файлы, которые в нее попадут будут автоматически реплицированы в destination S3 бакет в другом AWS регионе. Во втором задании нам необходимо предварительно создать оба наших S3 бакета. Для того, чтобы это сделать, мы переходим в сервис S3. Далее создаем новый бакет путем нажатия на кнопку Create bucket. Название бакета вы можете выбрать абсолютно любой, единственное важное условие регион должен быть us-east-2. И в этом бакете нам необходимо активировать Bucket versioning. Почему? Потому что cross-region replication работает только в том случае, когда bucket versioning активирован. Все остальные настройки можем оставить по умолчанию и необходимо будет нажать на кнопку Create bucket в нижней правой части экрана. Абсолютно те же действия нам необходимо будет сделать для второго бакета. Также название выбирайте любое доступное. Как Region необходимо будет указать регион Oregon, это us-west-2 и здесь также необходимо будет активировать versioning. На третьем задании мы будем настраивать cross-region replication. Для этого нам необходимо открыть source bucket, находящийся в регионе Ohio. Далее на странице S3 бакета нас интересует вкладка Management и здесь интересует секция создания replication rules, будет кнопка Create replication rule. Нас направят на отдельную страницу. Здесь как Replication rule необходимо будет указать crr-full-bucket. Как Status необходимо будет указать Enabled, как Source bucket выбираем наш source bucket. Как Destination bucket необходимо будет указать второй созданный бакет, находящийся в регионе Oregon. После чего необходимо будет выбрать IAM role, S3-CRR-Role, он предварительно был создан для нас в рамках этой лабораторной работы. После чего необходимо будет нажать на кнопку Save в нижней части экрана. Вас могут попросить, желаем ли мы существующие объекты в source bucket перенести в destination bucket. Так как у нас нет файлов в source bucket, то любой ответ он не произведет никаких действий. Поэтому выбирайте на свое усмотрение и далее необходимо будет нажать на кнопку Submit. Теперь нам необходимо протестировать, как работает Cross-Region replication. Нам необходимо будет открыть source S3 bucket, загрузить туда абсолютно любой файл. Как только мы это сделаем, нам необходимо дождаться завершения загрузки. Если файл успешно загружен, то далее открываем содержание destination bucket. Если вы ничего не видите, попробуйте обновить страницу либо нажать на кнопку Refresh на странице S3 bucket. После чего вы должны увидеть склонированный файл из source bucket в destination bucket. Мы с вами начинаем выполнение четвертого задания. В рамках этого задания будем настраивать File Gateway и создадим NFS file share. Для того чтобы это сделать, нам необходимо перейти в сервис Storage Gateway. Как только попадем на страницу ресурса, обязательно проверьте, что выбран регион North Virginia. Далее нам необходимо будет нажать на кнопку Create gateway и нас направит на страницу создания нового ресурса. Как Gateway name укажем File gateway, Time zone укажем GMT-5. Type gateway Amazon S3 file gateway и как Host platform - Amazon EC2. Чуть ниже необходимо будет выбрать тип, нас интересует опция Customize your settings. Как только мы выберем эту опцию, чуть ниже отобразится новая секция и там необходимо будет нажать на кнопку Launch instance. Как только вы это сделаете, откроется новая вкладка браузера, где мы будем настраивать AMI для нашего EC2 инстанса. На странице создания AMI нам необходимо будет в поле Name ввести File Gateway Appliance. Далее AMI оставляем то значение, которое выбрано, Instance type выбираем t2.xlarge и для Key pair name выбираем опцию vockey. Этот ключ можно будет скачать на главной странице лабораторной работы. Нажимаем на кнопку Details и в выпадающем списке нажимаем на кнопку Show. После чего будут необходимые ссылки для загрузки этого ключа. Возвращаемся на страницу создания AMI, нас интересует секция Network, необходимо будет нажать на кнопку Edit и ввести некоторые изменения. Как VPC необходимо будет выбрать On-Prem-VPC. Как Subnet выбираем On-Prem-Subnet, для поля Auto assign public IP необходимо будет выбрать опцию Enable и прокрутить чуть ниже. Чуть ниже у нас будет секция выбора security группы. Выбираем опцию Select an existing security group, то есть в рамках лабораторной работы для нас уже предварительно были созданы security группы. Мы выбираем две security группы, первая, которая содержит в названии FileGatewayAccess. В нее включены те rules, которые дают доступ на порты 80, 443, 53, 123 и 2049. Это все те порты, которые дадут возможность активировать File gateway. Далее нас интересует следующая security группа, в названии которой содержится OnPremSshAccess. По названию вы уже догадались, это та security группа, которая дает доступ для подключения к EC2 инстансу по SSH, то есть 22 порт. Последняя секция, в которую необходимо ввести изменения, это секция Storage. Помимо существующего жесткого диска необходимо добавить второй, поэтому нажимаем на кнопку Add new volume и вводим размер 150 гигабайтов. После чего в правой части экрана в поле количества инстансов выбираем один и нажимаем на кнопку Launch instance. Нас направят на страницу создания этого инстанса. Мы можем нажать на кнопку View all instances и перейти на страницу со списком всех инстансов. Для того, чтобы продолжить работу над заданием, нам необходимо дождаться изменения статуса, столбца Status checks для нашего инстанса на значение 2 из 2, все проверки пройдены. Вы можете периодически обновлять страницу, либо нажимать на кнопку обновления на самой странице в интерфейсе консоли. Далее нам необходимо будет открыть главную страницу нашего EC2 инстанса и скопировать значение публичного IP адреса. Его мы будем использовать далее для настройки File gateway. Как только мы это сделаем, мы можем вернуться на предыдущую вкладку браузера, где мы настраивали наш File gateway в сервисе AWS Storage Gateway. Здесь нам необходимо будет поставить галочку, что мы приготовили и создали EC2 инстанс. После чего можем нажать на кнопку Next, нас направят на вторую страницу. На второй странице нам необходимо будет в поле IP address ввести скопированные значения и для поля Service endpoint выбрать опцию Publicly accessible. После чего можем нажать на кнопку Next в нижней части экрана. На третьей странице вы увидите все введенные настройки. Здесь никаких изменений вводить не нужно, поэтому в нижней части экрана нажимаем на кнопку Activate gateway. На четвертой странице File gateway уже начнет создаваться. Вы увидите соответствующее сообщение в верхней части экрана. Дополнительно нам предлагается сделать опциональные настройки, это CloudWatch log group и CloudWatch alarms. Оба они нам в рамках лабораторной работы не нужны, поэтому для log group выбираем Deactivate logging, а для alarms выбираем опцию No alarm. Как только gateway будет создан, вы увидите сообщение с зеленым фоном о том, что оно было успешно создано. После чего мы можем нажать на кнопку Configure в нижней части экрана. Нас направят на главную страницу ресурса. Здесь необходимо будет также дождаться, что статус File gateway станет Running, занимает это порядка минуты. Как только все будет готово, мы можем воспользоваться навигационным меню слева и выбрать пункт File Shares, для того чтобы его создать. На открывшейся странице необходимо будет нажать на кнопку Create file share. На открывшейся странице нам необходимо будет для поля выбрать название нашего File gateway. Далее как File share protocol укажем NFS, как Amazon S3 bucket name выбираем наш source bucket, который находится в регионе Ohio. После чего необходимо будет выбрать опцию Customize configuration. Далее для поля File share name введем share и нажмем на кнопку Next. Далее нам необходимо будет ввести настройки S3 хранилища. Здесь как класс хранения для новых объектов выбираем опцию S3 Standard. Как Object metadata поставим галочки для первых двух значений, для третьего уберем. Особо не заморачивайтесь на вот таких мелких моментах. Возвращаемся к нашему заданию, для поля Access your S3 bucket необходимо будет выбрать опцию, что у нас есть существующая IAM role. В всплывающем окне мы увидим необходимое нам значение. Необходимо будет ввести это значение в поле IAM role и нажать на кнопку Next. На следующей странице предлагается ввести настройки доступа. Мы оставляем все значения по умолчанию. Также вы увидите опциональное поле с предупреждением с красным фоном, его можно игнорировать. На странице ресурса нас интересует команда, которая монтирует File share к нашему Linux инстансу. Необходимо будет скопировать эту команду, она нам понадобится чуть позже. На пятом задании мы будем монтировать File share к нашему Linux инстансу. Если вы работаете под операционной системой Windows, то вам необходимо будет произвести следующее действие.
