Қайырлы күн, құрметті студенттер! Сіздерді зертханалық жұмыстың кезекті сессиясында көргеніме қуаныштымын. Бүгінгі зертханалық жұмыстың тақырыбы — бұл біздің бизнес-кейс аясында ауқымды және жоғары қолжетімді IT-инфрақұрылымды құру. Ендеше, бастайық. Ең алдымен, зертханалық жұмыстың басты парақшасына жетуіміз қажет. Ол үшін тиісті курста модульдер тізіміне өтуіміз керек. Бізді қызықтыратыны — тоғызыншы модуль, және сол модульдегі әрекеттерден Challenge Lab қызықтырады. Оны басып, зертханалық жұмыстың басты парақшасына өтейік. Қазір зертханалық тапсырмаларды талдайтын болғандықтан, Terminal терезесі қажет емес, сондықтан оны жаба аламыз. Бизнес-кейс бойынша, біздің кафе өте танымал бола бастайды, және танымал ТВ-шоу оларды қатысуға шақырады. Сол себепті София мен Нихил көптеген жаңа келушілердің болатынын түсінеді, және IT-инфрақұрылымының масштабталуын және жоғары қолжетімділігін баптау қажет. Егер зертханалық жұмыс аясындағы тапсырмалар туралы айтатын болсақ, уақытша AWS аккаунтында қандай желілік ресурстар құрылғанын көруіміз керек. Содан кейін, бірнеше availability зоналарында жұмыс істеу үшін желілік ресурстарда қажетті өзгерістер енгіземіз. Одан кейін біз Load balancer, Launch template, Auto Scaling group құрамыз және олардың қалай бірге жұмыс істейтінін тексереміз. Бұл диаграммада сіз AWS аккаунтының ағымдағы күйін және қандай ресурстардың бұрыннан құрылғанын көре аласыз. Ал келесі диаграммада біз осы зертханалық жұмыс аясында қандай қосымша ресурстар жасайтынымыз көрсетілген. Зертханалық жұмысты орындауға ұсынылған уақыт — 90 минут, қажет болған жағдайда оны ұзартуға болады. Сонымен қатар, назар аударыңыз, біз арнайы жасалған AWS аккаунтында жұмыс істеп жатырмыз, сондықтан осы зертханалық жұмыспен қамтылмаған кейбір сервис пен олардың функционалдары қолжетімсіз болады. Өз AWS аккаунтыңызда жұмыс істеген кезде, сізде толық құқықтар болады және қажет болған кез келген сервис түрін пайдалана аласыз. Зертханалық жұмысты бастау үшін, ең алдымен экранның оң жақ жоғарғы бұрышындағы Start Lab батырмасын басу қажет. Сіз қалқымалы терезе мен уақытша AWS аккаунтының құрылып жатқаны туралы хабарламаны көресіз. Ол дайын болғанда, сәйкес хабарлама көрінеді және бұл терезені жауып, Start Lab батырмасының жанындағы AWS батырмасын басуға болады. Бұл сізді AWS Management Console басты парақшасына бағыттайды және сол жерде зертханалық жұмысты бастауға болады. Бизнес-кейс бойынша, София жағдайдың маңыздылығын түсінеді және ағымдағы IT-инфрақұрылымға өзгерістер енгізу қажеттілігін сезінеді. Сондықтан бірінші тапсырма аясында бізде не бар, қандай ресурстар құрылғанын қараймыз. Amazon VPC сервисінен бастау ұсынылады және сол сервис аясында қандай компоненттер мен ресурстар құрылғанын көру керек. Барлығын қарап шыққаннан кейін, 6 сұраққа жауап беру қажет болады. Сұрақтарға жету үшін зертханалық жұмыстың басты парақшасындағы Details батырмасын басу қажет. Қалқымалы тізімде Access the Multiple Choice Questions сілтемесі болады. Оны басқаннан кейін, жаңа браузер қойындысы ашылады және сізге 6 сұрақ көрсетіледі, оларға жауап беру қажет. Қазір әр сұраққа жеке тоқталайық. Бірінші сұрақ: CafeSG security group аясында қандай порттар ашық? Екінші сұрақ: Public Subnet 1 ішіндегі инстанстарға интернеттен қосыла аламыз ба? Үшінші сұрақ: Private Subnet 1 ішіндегі инстанстар интернетке шыға алуы керек пе? Төртінші сұрақ — дәл сол сұрақ, бірақ бұл жолы Private Subnet 2 туралы. Бесінші сұрақ: CafeWebAppServer деп аталатын инстансқа интернеттен қосыла аламыз ба? Алтыншы сұрақ: Осы AWS аккаунтында құрылған AMI-дің атауын көрсетіңіз. Қазір екінші тапсырманы қарастырайық, бұл жерде бізге екінші availability зонада NAT Gateway құру қажет болады. Біз NAT Gateway-ді Public Subnet ішінде құрамыз. Оны жасағаннан кейін, Private Subnet 2 ішіндегі инстанс интернетке жаңа NAT Gateway арқылы, яғни екінші availability зонасы арқылы шығуы үшін қажетті өзгерістер енгізуіміз керек. Енді үшінші тапсырмаға өтейік, мұнда Public Subnet-тің біреуінде Bastion Host құру қажет болады. Bastion Host немесе Jump Server — бұл EC2 инстанс, ол VPC ішінде орналасқан және интернеттен SSH арқылы қосылуға болады. Содан кейін осы инстанс арқылы Application Server-ге қосылуға болады. Bastion Host — бұл бірінші деңгейлі қорғаныс, және ол арқылы сіз де, алаяқтар да Application Server-ге интернеттен тікелей қосыла алмайсыз. Тапсырмаға сәйкес, кез келген Public Subnet таңдалады. Содан кейін Bastion Host атауымен EC2 инстанс құрамыз, AMI ретінде Amazon Linux 2023 AMI көрсетеміз, Instance type ретінде t2.micro, Key pair ретінде vockey көрсетеміз, оны зертханалық жұмыстың басты парақшасынан жүктеуге болады. Содан кейін Auto-Assign Public IP жолында құсбелгі қою қажет және сондай-ақ SSH қосылымына рұқсат беретін Security group жасау қажет, ол нақты сіздің IP-адресіңіз үшін жұмыс істейтін болады. Енді төртінші тапсырмаға назар аударайық, мұнда біз Launch Template құрамыз. Уақытша AWS аккаунты инициализацияланған кезде, біз үшін CafeWebAppServer серверінен кастомды AMI жасалған болатын. Біз оны Launch Template ішінде қолданамыз. Сондықтан Launch Template құру кезінде AMI ретінде Cafe WebServer Image көрсету қажет. Instance type ретінде t2.micro, Key pair ретінде жаңа кілт жасау қажет, себебі қосымша қауіпсіздік үшін Application серверлердің SSH кілттері Bastion Host SSH кілтінен өзгеше болуы маңызды. Әрі қарай Security group ретінде CafeSG таңдаймыз, тегтер баптауларында Key ретінде - Name, ал Value ретінде - webserver көрсетеміз және осы тегтер жаңа EC2 инстанстар үшін де жасалуы үшін құсбелгі қоямыз. Ең соңында IAM Instance Profile үшін CafeRole таңдау қажет. Енді бесінші тапсырманы толығырақ қарастырайық. Мұнда біз Auto Scaling group құрамыз, тапсырма бойынша алдыңғы қадамда құрылған Launch Template таңдалуы тиіс. VPC ретінде LabVPC көрсетеміз, Subnets — бұл Private Subnet 1 және 2, содан кейін ASG Desired және Minimum capacity - 2, ал Maximum capacity - 6 ретінде көрсету қажет. Кейін Target tracking scaling policy баптау қажет, ол Average CPU Utilization метрикасын бақылайды, Target value - 25, Instances need - 60 деп көрсету қажет. Оны құрғаннан кейін, инстанстар тізіміне өтіп, сәйкес атаулармен 2 инстанстың құрылғанын тексеру қажет. Енді алтыншы тапсырмаға толығырақ тоқталайық. Мұнда біз Load Balancer құрамыз, бізге Application Load Balancer қажет. Құру кезінде VPC ретінде LabVPC, ал Subnets ретінде екі public subnet көрсету қажет. Желі баптауларында жаңа security group құру қажет және бұл security group интернеттен келетін HTTP трафикке рұқсат беруі тиіс. Кейін жаңа target group құрамыз және бастапқыда бұл Load Balancer үшін таргеттер тіркелмейді. Load Balancer құрылғаннан кейін оның статусы Active болғанша күтеміз. Load Balancer дайын болған кезде, Auto Scaling group баптауларын өзгертіп, оны Load Balancer-мен байланыстырамыз. Ескерте кетейін, біз ASG-ді Load Balancer-мен тікелей байланыстырмаймыз, бұл байланыс target group арқылы жасалады. Жақсы, бизнес-кейс бойынша София бәрін масштабталатындай және жоғары қолжетімді етіп баптай алды. Енді олардың кафесі TВ-шоуда көрсетілгенге дейін бәрін тестілеу қажет. Біз жетінші тапсырмаға келдік және бұл тапсырмада веб-қосымшаны тестілеу қажет. Ол үшін Load Balancer-дің DNS name көшіріп, URL соңына /cafe қосып, осы сілтемені ашу қажет. Егер қосымша сәтті жүктелсе — бәрін дұрыс жасадыңыз деген сөз. Егер ашылмаса, алдыңғы тапсырмаларды қайта қарап шығыңыз, мүмкін қандай да бір қадамдарды өткізіп алған боларсыз. Егер бәрі дұрыс болса, келесі тапсырмаға көшеміз. Біз ең соңғы тапсырмаға жеттік, бұл сегізінші тапсырма. Бұл тапсырмада біз IT-инфрақұрылымның автомасштабталуын тексереміз. Алдымен кез келген Application серверге Bastion host арқылы қосылу қажет. Содан кейін Stress бағдарламасын орнату үшін ұсынылған командаларды қолданамыз, бұл серверге жасанды жүктеме түсіретін бағдарлама. Біз процессорларға 100% жүктеме түсіретін команданы 10 минутқа іске қосуымыз керек. Команданы іске қосқаннан кейін, AWS Management Console ішінде инстанстар тізімін ашу қажет. Сондай-ақ Auto Scaling group ішіндегі Instance Management парақшасын ашып, жаңа инстанстардың құрылып жатқанын көру қажет. Егер солай болса, құттықтаймын — бәрін дұрыс жасадыңыз. Барлық тапсырмалар сәтті орындалды және енді сіз AWS бұлтында автомасштабталатын және жоғары қолжетімді IT-инфрақұрылым құруды білесіз. Бизнес-кейс бойынша, Софияның ата-анасы TВ-шоуға сәтті қатысты, көптеп келушілер кафенің веб-сайтын ашты және олардың тұрақты келушіге айналуға мүмкіндігі бар. София да бақытты, себебі IT-инфрақұрылым барлық жүктемеге төтеп берді, автомасштабталды және жүктеме азайғаннан кейін бұрынғы күйіне қайта оралды. Енді орындалған жұмысты автобағалауды іске қосу қажет, ол үшін Submit батырмасын басып, бұл әрекетті растау қажет. Біраз уақыттан кейін скрипт жұмыс істейді, бұл жолы ол әдеттегіден ұзақ жұмыс істейді, себебі тапсырмалар саны көп және скриптке көбірек уақыт қажет. Біраздан соң өз бағаларыңызды көресіз. Егер қандай да бір қате бар болып, балдарыңызды жақсартқыңыз келсе — тиісті тапсырмаға оралып, түзетулер енгізіп, автобағалауды қайтадан іске қосуға болады. Барлық тапсырмаларды орындап, қалаған бағаларыңызды алғаннан кейін, барлық жүйеден дұрыс шығу қажет. Бұл зертханалық жұмысқа қатысты — End Lab батырмасын басып, әрекетті растаңыз. Сондай-ақ AWS Management Console жүйесінен дұрыс шығыңыз. Осылайша біз зертханалық жұмыстың шолуын аяқтадық. Назарларыңызға рахмет, келесі белсенділіктерде кездескенше!
